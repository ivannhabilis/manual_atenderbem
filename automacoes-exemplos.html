Duas formas de usar um exemplo.
  1. Importar pela tela (mais rápido): baixe o arquivo .ivr ao lado do título e, em Fluxo de Automação e URA, clique em Importar e escolha esse arquivo. O fluxo entra pronto, com os elementos ligados.
  2. Montar no editor (para aprender): siga os passos do exemplo e escolha cada elemento na paleta pelo nome em português indicado na ficha do elemento (a ficha traz "No editor, escolha:").
Sobre o formato dos arquivos. Cada exemplo tem os dois arquivos: o .ivr é o registro do fluxo codificado — o mesmo formato que o botão Exportar gera, e o único que o Importar aceita; o .txt traz o mesmo fluxo em linguagem de fluxo, que serve para ler, comparar e criar ou atualizar o fluxo por API. Para importar na tela, use o .ivr.
Antes de publicar: troque os identificadores didáticos pelos da sua instância — pipelineId, stageId, queueId, userId, assistantId, templateId, tagId, fileId. Os exemplos usam valores genéricos justamente para poderem ser importados em qualquer ambiente.

1. Boas-vindas, menu principal e consulta com validação de CPF compilado

Receber o cliente no primeiro contato, oferecer as opções da central em um menu tocável e só pedir o CPF quando ele escolhe consultar um pedido.

Elementos usados: message · info · question · options · url · terminate

  1. message — cumprimenta o cliente pelo nome e avisa que ele falou com a central de atendimento.
  2. info — grava uma nota interna (só o atendente vê) dizendo que o cliente está sendo triado pelo menu.
  3. options — apresenta o menu com três caminhos (consultar pedido, segunda via e falar com atendente) e um else para a escolha que não existe.
  4. question — no caminho do pedido, pede o CPF do titular e valida o formato antes de seguir; se vier inválido, usa o texto de validateError.
  5. message — confirma o CPF recebido e mostra o protocolo do atendimento.
  6. url — no caminho da segunda via, envia um botão de ação com o link do boleto montado com o telefone do cliente.
  7. terminate — fecha cada caminho com o motivo correspondente.
boas_vindas: message text="Olá, {{chat_client_name}}! Você está falando com a Central de Atendimento."
nota_triagem: info text="Triagem automática pelo menu principal. O cliente ainda não escolheu uma opção."
menu_principal: options text="Escolha uma opção para eu te ajudar mais rápido:" type=0 {
  case pedido text="Consultar um pedido" {
    pede_cpf: question varName="cpf_cliente" text="Informe o CPF do titular do pedido, apenas os números." validate=1 validateError="CPF inválido. Envie os 11 números, sem pontos nem traços."
    cpf_recebido: message text="Obrigado! Com o CPF {{cpf_cliente}} eu localizo o pedido e sigo com a consulta."
    aviso_protocolo: message text="Guardei este atendimento no protocolo {{chat_protocol}}."
    fim_pedido: terminate reason="Consulta de pedido iniciada"
  }
  case boleto text="Segunda via de boleto" {
    link_boleto: url text="Toque no botão abaixo para abrir a segunda via:" btnText="Abrir segunda via" data="https://financeiro.exemplo.com.br/boleto/{{chat_client_number}}"
    aviso_boleto: message text="Se o botão não abrir, responda esta conversa que um atendente gera o boleto para você."
    fim_boleto: terminate reason="Segunda via enviada ao cliente"
  }
  case humano text="Falar com um atendente" {
    aviso_fila: message text="Combinado! Estou te colocando na fila de atendimento humano agora."
    fim_humano: terminate reason="Cliente pediu atendimento humano"
  }
  else {
    nao_entendi: message text="Não entendi a opção. Sem problema: vou te encaminhar para um atendente para não te deixar esperando."
    fim_invalido: terminate reason="Opção inválida no menu principal"
  }
}
Resultado: O cliente vê a saudação, toca em uma opção e recebe a confirmação (com o link do boleto ou o pedido de CPF validado); cada caminho encerra o atendimento com um motivo registrado.

2. Pesquisa de satisfação com a nota protegida compilado

Colher a nota do cliente no fim do atendimento e esconder a resposta dele dos atendentes comuns, deixando-a visível só para supervisores.

Elementos usados: message · question · changeMessageVisualGroup · info · terminate

  1. message — avisa que o atendimento está terminando e que vem uma pergunta rápida.
  2. question — pergunta a nota de 0 a 10 e guarda a resposta na variável nota_atendimento, esperando a resposta do cliente.
  3. changeMessageVisualGroup — move a mensagem mais recente ({{message_id}}) para o grupo de visualização 1, restringindo quem pode vê-la.
  4. info — deixa a nota registrada como informação interna para quem pode ver a mensagem.
  5. terminate — encerra o atendimento com o motivo pesquisa respondida.
abre_pesquisa: message text="Antes de encerrar, quero saber como foi este atendimento."
pede_nota: question varName="nota_atendimento" text="De 0 a 10, que nota você dá para o atendimento de hoje? Responda apenas com o número."
protege_nota: changeMessageVisualGroup messageId="{{message_id}}" visualGroupId="1"
nota_interna: info text="Nota informada pelo cliente: {{nota_atendimento}}. A mensagem com a resposta foi movida para o grupo de visualização 1: supervisores e administradores continuam vendo, atendentes comuns não."
agradece_nota: message text="Obrigado pela avaliação, {{chat_client_name}}! Sua nota {{nota_atendimento}} foi registrada e vai nos ajudar a melhorar."
fim_pesquisa: terminate reason="Pesquisa de satisfação respondida"
Resultado: O cliente responde uma única pergunta e recebe o agradecimento; o atendente comum não vê a nota na conversa, mas o supervisor e o administrador continuam vendo.

3. Coleta de endereço com Whatsapp Flow e limpeza do dado sensível compilado

Pedir o endereço de entrega em um formulário nativo do WhatsApp, usar a localização compartilhada como conferência e apagar o conteúdo do Flow logo depois.

Elementos usados: sendTemplate · waitMessage · requestLocation · sendFlow · clearFlowDataFromMessage · message · sendMail · terminate

  1. sendTemplate — abre a conversa com um template pré-aprovado (exemplo para fila WA Cloud API).
  2. waitMessage — espera o cliente mandar a primeira mensagem antes de pedir dados.
  3. requestLocation — envia o pedido de localização para conferir a região da entrega.
  4. sendFlow — manda o Whatsapp Flow de endereço, com cabeçalho, corpo, rodapé e o texto do botão.
  5. clearFlowDataFromMessage — limpa a resposta do Flow da última mensagem recebida, inclusive no banco de dados.
  6. message — confirma o recebimento dos dados e avisa que o frete será calculado.
  7. sendMail — envia o e-mail de confirmação de endereço usando o modelo cadastrado.
  8. terminate — encerra o atendimento com o motivo endereço coletado.
abre_confirmacao: sendTemplate templateId=0
aguarda_cliente: waitMessage
pede_localizacao: requestLocation text="Para calcular o frete, toque em Anexar e compartilhe sua localização."
form_endereco: sendFlow flowId="flow-endereco-entrega" initialScreenId="ENDERECO_ENTREGA" headerText="Dados de entrega" bodyText="Confirme o endereço de entrega do pedido {{chat_protocol}}." footerText="Leva menos de um minuto." btnText="Preencher endereço"
limpa_dados_flow: clearFlowDataFromMessage
confirma_recebimento: message text="Prontinho, {{chat_client_name}}! Recebemos seus dados com segurança e o frete já vai ser calculado."

Elementos usados: request · varCondition · publishToExtension · message · terminate

  1. request — faz um GET no endpoint externo e guarda a resposta em variaveis com o prefixo pedido (pedido_status, pedido.*).
  2. varCondition — ramifica por expressao: se pedido_status == 200 segue o caminho de sucesso, senao o de falha.
  3. message — confirma ao cliente que o pedido foi consultado.
  4. publishToExtension — publica no canal da extensao painel-pedidos, no topico pedido_atualizado, avisando os agentes para recarregar os dados.
  5. terminate — encerra o atendimento pelos dois caminhos.

  case ok conditionOperator="expression" conditionValue="pedido_status == 200" {
    bom: message text="Seu pedido foi consultado com sucesso."
    avisa: publishToExtension installId="painel-pedidos" topic="pedido_atualizado" target="type:agent" payload="{\"chatId\": \"{{chat_id}}\"}"
    f1: terminate reason="Pedido consultado"
  }
  else {
    ruim: message text="Nao consegui consultar seu pedido agora. Vou encaminhar para um atendente."
    f2: terminate reason="Falha na consulta"
  }
}
Resultado: Se a API responde 200, o cliente ve a confirmacao e a extensao painel-pedidos recebe o aviso; senao o cliente e orientado.
