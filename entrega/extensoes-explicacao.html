1. Antes de começar (e a ideia em 1 minuto)

Pense numa loja de aplicativos: o aplicativo existe uma vez só na loja (global); cada aparelho que instala tem a sua cópia (local). Na plataforma, a extensão é o aplicativo e cada empresa é um aparelho.

PapelQuem faz
Criar e publicar a extensão (Editor de Extensões)Administrador
Instalar, configurar, ligar/desligarSomente o superusuário
Distribuir em várias empresasParceiro (painel do parceiro)
Guarde bem Você vai criar a extensão. Quem instala é o superusuário — o Administrador comum não vê a tela de instalação (e o servidor bloqueia, mesmo digitando o endereço).

O item Extensões fica no fim do menu Configurações:

Você só precisa de duas coisas: acesso ao editor e um lugar público para hospedar os arquivos (ou usar o próprio editor, que já grava os arquivos por você).

A distinção que resolve tudo Publicar não coloca no ar: apenas congela a versão. Quem coloca em uso é apontar o canal (dev = teste, prod = produção).

Passo 1 — Criar a extensão

Faça Abra Configurações › Extensões e clique em Nova extensão. Preencha Nome, Identificador (opcional) e Descrição. Clique em Criar.
Você deve ver A extensão aparece na lista com a etiqueta rascunho e uma versão inicial (ex.: 0.1.0).
Se der errado Não encontra o item Extensões? O editor pode não estar habilitado na sua instância, ou você não tem perfil de Administrador (ou a permissão de editar extensões).

Passo 2 — Escrever o manifesto

O manifesto é a carteira de identidade da extensão. Copie e ajuste:

{
  "manifestVersion": 1,
  "id": "minhaempresa.minhaextensao",
  "version": "1.0.0",
  "name": "Minha Extensão",
  "description": "Uma frase sobre o que ela faz.",
  "author": { "name": "Seu Nome" },
  "contributions": [
    {
      "id": "painel",
      "type": "chatPanel",
      "title": { "pt-BR": "Meu Painel" },
      "url": "index.html"
    },
    {
      "id": "menu",
      "type": "topMenu",
      "title": { "pt-BR": "Minha Extensão" },
      "presentation": { "mode": "dialog", "size": "lg" },
      "url": "index.html"
    }
  ]
}
CampoO que é
idNome único e global, no formato fornecedor.extensao (minúsculas, números e hífen; um ponto). Congela na 1ª publicação.
versionSempre X.Y.Z, maior que a anterior.
authorUm objeto { "name": "..." } — não escreva texto solto.
contributionsOnde a extensão aparece (chatPanel, topMenu, mainNav…). Cada uma precisa de id, type, title e url.
Pegadinha O campo icon, se usado, é um arquivo da extensão (ex.: assets/icone.svg), não o nome de um ícone do sistema.

Passo 3 — Escrever a tela

Este é o arquivo que o usuário vê. O Host injeta o SDK na variável window.omni:

<!DOCTYPE html>
<html lang="pt-BR">
<head><meta charset="UTF-8"><title>Meu Painel</title></head>
<body>
  <h1>Meu Painel</h1>
  <div id="quem">carregando…</div>
  <div id="atendimento"></div>
  <button id="recarregar">Recarregar</button>

  <script>
    async function carregar() {
      // 1) Quem está usando a extensão agora
      const u = await omni.session.getUser();
      document.getElementById('quem').textContent = u.name + " (id " + u.id + ")";

      // 2) O atendimento aberto na tela (pode não haver nenhum)
      const chat = await omni.chats.getSelected();
      document.getElementById('atendimento').textContent =
        chat ? ("Atendimento #" + chat.id) : "(nenhum atendimento aberto)";

      omni.ui.resize();   // avisa o Host para ajustar a altura
    }
    document.getElementById('recarregar').onclick = carregar;

    // O SDK aparece de forma assíncrona: espere antes de usar.
    (function esperar(){ window.omni ? (omni.ready ? omni.ready(carregar) : carregar()) : setTimeout(esperar,400); })();
  </script>
</body>
</html>
Chamada do SDKPara que serve
omni.session.getUser()Sabe quem está logado
omni.session.getInstance()Nome da instância e versão do sistema
omni.chats.getSelected()O atendimento aberto na tela
omni.chats.sendMessage(id, {text})Envia mensagem em nome do atendente
omni.ui.resize()Ajusta a altura do quadro ao conteúdo
Segurança Nunca escreva senhas ou chaves de API dentro da tela. Elas vão na configuração da instalação e são cifradas.

Passo 4 — Conferir

Faça Com o manifesto e o arquivo gravados, rode a conferência (o editor tem essa ação).
Você deve ver 0 erros. A conferência ainda mostra o "plano": cada combinação de tipo de usuário e contribuição que será montada (Administrador, Supervisor, Agente).
Erros mais comuns Campo id ausente; lista contributions vazia; author como texto; arquivo citado que não existe; icon apontando para um arquivo inexistente.

Passo 5 — Publicar

Faça Publique a versão (dá para dar um rótulo e notas).
Você deve ver A versão sai de "rascunho" e vira PUBLICADA. Mas nada aparece para ninguém ainda — publicar só congela.
Se der errado "Versão não maior que a publicada": suba o número. "CDN não configurada": a publicação não chega aos usuários — fale com o responsável pela instância.

Passo 6 — Apontar o canal

Faça Aponte o canal de teste (dev) para a versão publicada. Só depois de conferir, aponte a produção (prod).
Por que dev primeiro O canal de teste propaga na hora; o de produção tem cache (cerca de 15 minutos). Para atualizar depois, basta publicar uma versão nova e mover o ponteiro — sem reinstalar nada.

Passo 7 — Instalar e ver na tela

Faça A instalação é feita pelo superusuário (tela de Extensões Instaladas) ou pela integração de configuração. Informe a URL do manifesto, a configuração (se houver) e para quem entregar.
A pegadinha nº 1 Um filtro de público vazio significa NINGUÉM — não "todos". Se você quer restringir, liste as pessoas/filas/grupos. Se não informar filtro nenhum, aplica-se o padrão (todos os perfis).
Você deve ver Quem casa com o filtro passa a ver a extensão na hora. Um item de barra superior aparece como um ícone novo:
A pegadinha nº 2 A aba dentro do atendimento (chatPanel) só aparece para quem atende chats. Se quem está testando não é atendente, não há onde a aba aparecer — use um item de barra superior para demonstração.

Depois: atualizar e desfazer

  • Atualizar: crie uma versão nova (clone), publique e aponte o canal. Ninguém reinstala.
  • Voltar atrás (rollback): aponte o canal para a versão anterior. Nada é apagado.
  • Desligar: desabilite a instalação — sai do ar na hora e a configuração fica guardada.
  • Remover a instalação: apaga configuração e chave daquela empresa (não volta).
  • Apagar a extensão: remove tudo do servidor central; tem alcance externo (afeta outras empresas que instalaram) e não remove as instalações sozinho.

Lista de verificação

Tenho acesso ao Editor de Extensões (Configurações › Extensões).
Meu identificador segue o formato fornecedor.extensao e eu sei que ele congela na 1ª publicação.
Meu author é um objeto, não texto.
Todo arquivo citado no manifesto existe de verdade.
A conferência apontou 0 erros.
Publiquei e apontei o canal de TESTE antes do de produção.
Sei que quem instala é o superusuário.
Meu filtro de instalação não ficou vazio por engano.
Conferi a extensão na tela de um usuário real do público.
Não há senhas nem chaves escritas no código da tela.

Armadilhas (resumo)

Filtro vazio = ninguém

Uma lista de inclusão vazia não entrega para ninguém, e não gera erro nenhum.

Enxergar a extensão só em certas telas

O painel do atendimento depende de quem atende chats; o item de barra superior aparece para todos.

Identificador congelado

O id não muda depois da primeira publicação. Trocar = apagar e recriar.

Publicar e "nada acontece"

Falta apontar o canal. Publicar só congela a versão.

Remover/apagar exige confirmação

A remoção de instalação só acontece com uma confirmação explícita — leia a mensagem de retorno.

Apagar não limpa as instalações

Elas podem ficar apontando para algo que não existe mais. Remova-as também.

Produção demora a atualizar

Há cache (cerca de 15 minutos). Teste em dev.
