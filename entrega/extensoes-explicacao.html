Extensões — Como Funciona

Um guia simples: o que é, quem cria, quem instala, como publicar e como isso chega a outras empresas.

Se você ficou confuso com a tela de Extensões, não é problema seu: a funcionalidade separa em duas coisas diferentes algo que parece uma só. Este guia explica em linguagem simples.

1. A ideia em um minuto (a analogia da loja de aplicativos)

Pense numa loja de aplicativos (como a loja do seu celular):

  • O aplicativo existe uma vez só, na loja. Ele é global.
  • Cada aparelho que instala tem a sua instalação — com os seus dados, as suas escolhas. Ela é local.

Na plataforma é igual: a extensão é como o aplicativo (mora num servidor central), e a instalação é como "instalar no aparelho" — e cada empresa é um aparelho diferente.

Resumo: "criar a extensão" e "instalar a extensão" não são a mesma coisa, não acontecem na mesma tela e não são feitos pela mesma pessoa.

2. Os três papéis

1. AUTORAREscrever a extensão. Tela: Editor de Extensões. Quem: o Administrador (ou um Supervisor autorizado).
→
2. INSTALAREntregar a extensão nesta empresa. Tela: Extensões Instaladas. Quem: somente o superusuário.
→
3. DISTRIBUIREntregar em várias empresas de uma vez. Local: painel do parceiro.
AçãoQuem faz
Criar, editar e publicar a extensãoAdministrador (no Editor de Extensões)
Instalar, configurar, ligar/desligar e removerSomente o superusuário
Operar várias empresas de uma vez (em lote)Parceiro (painel do parceiro)
É por isso que, muitas vezes, aparecem coisas diferentes para pessoas diferentes: o Administrador vê a tela de criar; a tela de instalar pertence ao superusuário. E isso não é apenas "escondido na tela": o próprio servidor bloqueia o acesso de quem não é superusuário — mesmo que a pessoa tente abrir o endereço direto.

3. O que é "global" e o que é "local"

PeçaOnde ficaÉ…
A extensão (código e tela)Servidor centralGlobal — existe uma vez só, com um nome único
A instalação (quem recebe, com qual configuração)Dentro de cada empresaLocal — uma por empresa, independente

Ou seja: a mesma extensão instalada em duas empresas são duas instalações separadas — cada uma com a sua configuração, o seu público e os seus dados.

5. Criar a extensão (é mais simples do que parece)

Uma extensão é só isto:

  • 1 arquivo de identidade — o manifest.json (um texto pequeno que descreve a extensão);
  • 1 ou mais arquivos de tela — normalmente um index.html (a tela que o atendente vê).

Exemplo de manifest.json comentado:

{
  "manifestVersion": 1,
  "id": "fornecedor.extensao",   // nome único: minúsculas, números e hífen; um ponto.
  "version": "1.0.0",            // sempre maior que a versão anterior.
  "name": "Minha Extensão",
  "description": "O que ela faz.",
  "author": { "name": "Seu Nome" },  // atenção: aqui é um objeto, não texto solto.
  "contributions": [                 // ONDE a extensão aparece:
    { "id": "painel", "type": "chatPanel", "title": { "pt-BR": "Meu Painel" }, "url": "index.html" },
    { "id": "menu",   "type": "topMenu",   "title": { "pt-BR": "Minha Extensão" },
      "presentation": { "mode": "dialog" }, "url": "index.html" }
  ]
}
Regra de ouro: todo arquivo citado no manifesto precisa existir de verdade. Se citar um arquivo que não existe, a publicação é recusada.

Onde a extensão pode aparecer (os "pontos de encaixe")

TipoOnde aparece
chatPanelAba lateral dentro do atendimento
topMenuÍcone na barra superior (visível para todos)
mainNavItem na navegação principal
chatMenu / msgMenuMenus dentro do atendimento / da mensagem
cartAction / cartFooterActionBotões no painel de carrinho
callActionAção durante uma ligação

6. O fluxo completo, do zero ao uso

  1. Criar a extensão (nasce um rascunho).
  2. Escrever o manifesto e os arquivos da tela.
  3. Conferir — o sistema mostra cada erro antes de publicar.
  4. Publicar — a versão vai para o servidor central e fica "congelada". Publicar não liga a extensão.
  5. Apontar o canal — teste (para experimentar) ou produção (para valer). Só isso liga a versão.
  6. Copiar o endereço da extensão (a URL do manifesto).
  7. Instalar na empresa, informando o endereço, a configuração e para quem entregar.
  8. Conferir na tela de quem vai usar.
"Teste" e "Produção" são canais. Você publica uma vez e escolhe para onde apontar. Publicar não coloca no ar; apontar coloca. E atualizar depois é só publicar de novo e apontar para a versão nova — ninguém precisa reinstalar nada.

7. Instalar (e o detalhe que mais dá erro)

Ao instalar, você decide três coisas:

DecisãoO que é
Qual endereçoO teste (experimentar) ou o de produção (para valer)
Com qual configuraçãoCampos que a extensão pede (ex.: uma chave). Campos secretos ficam cifrados.
Para quemO público: por tipo de usuário, por pessoa, por fila ou por grupo
Cuidado nº 1: um filtro de público vazio significa "ninguém" — não significa "todos".
Cuidado nº 2: se você não escolher público nenhum, o sistema aplica "todos". Por segurança, instale primeiro só para você (ou para uma fila de teste), confira, e depois libere para a equipe.

A entrega é imediata: quem está no público passa a ver na hora, sem recarregar a página.

9. Isso vai para outras empresas? Sim.

A plataforma é whitelabel: cada empresa tem a sua instalação própria, com a sua cara e o seu endereço. Mas a extensão é um item global:

  • a extensão é criada e publicada uma vez, com um nome único no sistema;
  • qualquer outra empresa instala a mesma extensão, apenas informando aquele endereço;
  • cada empresa continua independente: configuração, público e dados são dela;
  • para levar a extensão a muitas empresas de uma vez, usa-se o painel do parceiro.

10. Desfazer

AçãoO que aconteceDá para voltar?
Desligar a extensãoSai do ar na hora; a configuração fica guardadaSim
Remover a instalaçãoApaga a configuração e a chave daquela empresaNão
Apagar a extensãoRemove a extensão inteira do servidor centralNão — e afeta quem já instalou
Remover a instalação é diferente de apagar a extensão. Apagar a extensão não remove sozinho as instalações que existiam — é preciso removê-las também.

11. Dúvidas comuns

O Administrador consegue criar a extensão?

Sim. Criar, editar e publicar é papel do Administrador. O que ele não faz é instalar na empresa.

E se ninguém tiver acesso de superusuário? Só dá para instalar pela integração (API)?

Na prática, sim. Como instalar é papel do superusuário, sem esse acesso a instalação é feita pela integração de configuração (API/MCP), que opera com esse perfil, ou pelo painel do parceiro.

A extensão que eu criei fica só na minha empresa?

O aplicativo é global (fica num servidor central); as instalações é que são de cada empresa. Outra empresa instala o mesmo aplicativo informando o endereço.

Para atualizar, preciso reinstalar em cada empresa?

Não. Basta publicar a versão nova e apontar a produção para ela. Todas as empresas que usam aquele endereço recebem a atualização.

Instalei, mas não aparece na minha tela. Por quê?

Quase sempre é o público. Confira se você está dentro do filtro. Lembre-se: filtro vazio não entrega para ninguém. E alguns pontos de encaixe só existem em certas telas (por exemplo, a aba lateral só aparece para quem atende chats).

Preciso saber programar?

Para usar e instalar, não. Para criar, é preciso alguém que saiba escrever um HTML simples — mas o manifesto é só um texto de configuração.
