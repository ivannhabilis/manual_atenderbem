1. Gravações do Sistema (System Recordings)

As Gravações do Sistema são a base sonora da central. Elas contêm as vozes que os clientes escutam ao ligar para a empresa.

Padrão Técnico de Áudio para Telefonia: Para máxima clareza e compatibilidade com o Asterisk, os arquivos de áudio devem estar no formato WAV PCM, 16-bit Mono, taxa de amostragem de 8000 Hz ou 16000 Hz. Arquivos em MP3 ou estéreo sofrem conversão e podem gerar ruído.

Como cadastrar um áudio no FreePBX:

  1. No menu do PABX, acesse Admin › System Recordings › + Add Recording.
  2. Clique em Upload Recording e selecione o arquivo .wav gravado em seu computador.
  3. Defina um Name descritivo (ex.: Audio_Menu_Principal ou Audio_Fora_Horario).
  4. Clique em Save e aplique as alterações com Apply Config.

2. Anúncios Informativos (Announcements)

Um Anúncio (Announcement) reproduz uma mensagem gravada para o cliente e, imediatamente após o fim da fala, transfere a chamada para o próximo destino automaticamente, sem esperar interação de teclas.

Casos de uso comuns:

  • "Esta ligação está sendo gravada para fins de controle de qualidade..." ➔ Direciona para a Fila de Atendimento.
  • "Nosso horário de atendimento é de segunda a sexta, das 8h às 18h..." ➔ Direciona para Desligar (Hangup) ou Caixa Postal.
  • "Estamos realizando manutenção técnica preventiva..." ➔ Direciona para a URA de Emergência.

Para configurar, acesse Applications › Announcements › + Add Announcement, selecione a gravação cadastrada no campo Recording e defina o destino final em Destination after playback.

3. Criação de URA / IVR (Interactive Voice Response)

A URA (IVR) é o menu eletrônico que orienta o cliente: "Olá, bem-vindo à Central de Atendimento! Digite 1 para Suporte Técnico, 2 para Financeiro, ou 3 para Vendas."

Passo a passo no FreePBX (`Applications › IVR`):

  1. Acesse Applications › IVR › + Add IVR.
  2. Defina o IVR Name (ex.: URA_Principal_Diurna).
  3. No campo Announcement, selecione a gravação com as opções de menu (ex.: Audio_Menu_Principal).
  4. Timeout: Defina o tempo de espera pelo dígito do cliente (padrão: 5 segundos).
  5. Invalid Retries: Número de tentativas permitidas se o cliente digitar uma opção inexistente (ex.: 2).
  6. Timeout Destination: O que fazer se o cliente não digitar nada (ex.: repetir o menu ou transferir para a recepção).
  7. Tabela de Entradas (IVR Entries): Mapeie os dígitos numéricos para seus destinos:
    Dígito DTMFDestino (Destination)Descrição
    1Queues › Fila_SuporteDireciona para os técnicos de suporte.
    2Queues › Fila_FinanceiroDireciona para faturamento/cobrança.
    3Queues › Fila_ComercialDireciona para o time de vendas.
    9Extensions › 1000 (Recepção)Atendimento humano geral.

  8. Clique em Submit e em Apply Config.
URA = Unidade de Resposta Audível. É o recurso de autoatendimento que resolve demandas simples sem intervenção humana — por exemplo: consulta de 2ª via de fatura, atualização de dados de contato, confirmação de pagamento, verificação de faturas em atraso, agendamento/cancelamento de visita técnica. Cada um desses serviços pode virar um dígito do menu ou um bloco do fluxo.

4. Vinculação da URA de Telefonia ao Sistema Omnichannel

Nem toda URA precisa viver dentro do FreePBX. Em vez de montar a árvore toda no PABX, é possível entregar a chamada para o Sistema de Atendimento (Omnichannel) por meio de uma fila do tipo Telefonia (URA). Neste modelo, o PABX faz apenas o "handoff" da ligação via Custom Destination e o fluxo de decisão é construído no construtor visual de URAs da plataforma.

Quando usar este modelo: quando o menu precisa continuar dentro do sistema de atendimento — para reaproveitar blocos modernos (Pesquisas, Horário de Atendimento, IA) e centralizar relatórios. A URA tradicional do FreePBX continua válida para árvores simples que não dependem de dados da plataforma.

Passo a passo da vinculação:

  1. No PABX, acesse Admin › Custom Destinations › + Add Destination.
  2. No campo Target, informe o destino no formato ari-bridge,<nome_da_fila>,1 — por exemplo, ari-bridge,apptest,1 (o nome apptest é livre e deve ser reaproveitado no próximo passo).
  3. Preencha Description e Notes de forma descritiva (ex.: "Enviar para a fila apptest") e mantenha Return em No.
  4. Clique em Submit e depois em Apply Config para publicar o destino no PABX.
  5. No sistema de atendimento, vá em Configurações › Filas › + Adicionar e crie uma fila com o MESMO NOME usado no Custom Destination (no exemplo, apptest). O Tipo da fila deve ser Telefonia (URA).
  6. Na aba Conexão da fila, ative a chave Habilitar Servidor e clique em Salvar.
  7. Em Configurações da fila, na opção Enviar para a URA, crie uma nova URA do tipo URA Avançada (telefonia) ou atribua uma já existente do mesmo tipo.

5. Pesquisas de Satisfação em URAs (v13+)

A partir da versão 13, o Módulo de Pesquisas substitui os fluxos longos e repetitivos de perguntas dentro da URA. Em vez de encadear dezenas de blocos de "digite 1 a 5", a pesquisa é montada uma única vez em Configurações › Pesquisas e reaproveitada no fluxo por blocos dedicados.

Elemento de URA / FluxoFunção
Gerar Link de PesquisaCria uma URL única de acesso externo à pesquisa, com validade configurável em dias (mínimo de 1 dia). A URL é gravada em uma variável e deve ser enviada ao cliente (ex.: por WhatsApp).
Submeter Resposta de PesquisaRegistra respostas vindas de outros canais: interação direta no atendimento, preenchimento por agentes ou processamento via IA (Processar com IA), mapeando variáveis de fluxo para os campos da pesquisa.
Completar Resposta de PesquisaComplementa perguntas ocultas do formulário, preenchendo metadados por automação.

Variáveis e regras de negócio:

  • Cada pergunta expõe duas chaves em tempo de execução: survey_q_<id> (valor bruto) e survey_q_<id>_label (rótulo amigável).
  • O id é numérico e incremental, gerado no cadastro da pergunta.
  • Links gerados dinamicamente aceitam uma única submissão: uma segunda tentativa retorna "Link já utilizado".
  • Links não respondidos dentro do prazo de validade expiram automaticamente por timeout.
  • É possível configurar uma Automação Pós-Resposta, disparada assim que o cliente envia o formulário, para tratar as respostas em um fluxo assíncrono.

6. Horário de Atendimento Dentro do Fluxo da URA

Nos fluxos de URA e automação, o expediente pode ser validado por um elemento nativo de Horário de Atendimento, configurado com o ID do horário desejado. O sistema avalia automaticamente dias, feriados e datas especiais no momento da chamada e direciona o cliente para a saída Aberto ou Fechado.

Fluxo único para todos os casos fora de horário: usando as variáveis bh_reason_label e bh_reason, é possível saber por que o horário está fechado (data especial, feriado, fora do expediente) e ramificar dentro do mesmo fluxo com mensagens diferentes para cada situação.

O cadastro dos expedientes, feriados e datas especiais é detalhado no capítulo Condições de Horário.
