Extensões (Micro-Frontends & SDK)

Integração avançada, barramento de eventos em tempo real e SDK de desenvolvimento para acoplar aplicativos externos ao AtenderBem.

Arquitetura de Micro-Frontends: O AtenderBem implementa uma arquitetura baseada em sandboxing (via iframes isolados e Web Workers em segundo plano) que permite a incorporação de aplicativos web de terceiros. Essas aplicações se integram perfeitamente às telas de chat, CRM e cadastros usando o barramento de comunicação do SDK omni.

1. Visão Geral e Conceitos Básicos

A funcionalidade de Extensões (localizada administrativamente no path /base/config/extensioninstalls) resolve o clássico problema de silos de software em centrais de atendimento. Em vez de forçar o agente de suporte ou vendas a alternar entre o AtenderBem e um ERP/CRM corporativo externo (gerando cliques repetitivos e lentidão), a plataforma permite embutir telas e automações personalizadas no fluxo de trabalho.

A comunicação ocorre através de um protocolo bidirecional seguro, em que o AtenderBem (o "Host") expõe APIs de leitura e escrita e envia notificações de eventos do sistema, e a extensão (o "Guest") responde e executa ações de interface.

2. Central de Gerenciamento (/base/config/extensioninstalls)

É a tela destinada aos administradores da instância para homologar e parametrizar as extensões de produção. A grade de controle reúne as seguintes colunas:

  • Instalação: O rótulo amigável (label) atribuído à extensão.
  • Extensão: O identificador exclusivo textual (extid) que mapeia o aplicativo.
  • Estado: Status ativo ou inativo da extensão ("Habilitada" ou "Desabilitada").
  • Avisos: Erros de manifesto ou dependências ausentes na instância.
  • Entrega: Critérios de público-alvo (audiência) e permissões de quem poderá visualizar o recurso.
  • Canal: Estado do barramento de comunicação e segurança da extensão.
  • Verificado em: Data e hora da última validação e atualização do manifest.

Ações Administrativas Disponíveis

Operação Descrição Técnica Efeito Prático
Add (Adicionar) Dispara o diálogo de instalação exigindo a URL pública do manifest.json. Realiza a leitura remota via fetch, valida o JSON, mapeia as contribuições e inclui a extensão na grade como ativa.
Edit (Configurar) Abre o formulário de edição de variáveis de ambiente. Permite que o administrador preencha segredos, chaves de API externas e tokens exigidos por aquela extensão específica.
Toggle (Habilitar/Desabilitar) Chama o serviço interno admin.setEnabled(id, boolean). Garante o desligamento de segurança imediato de qualquer script ou iframe da extensão em todas as sessões ativas de agentes.
Refresh Manifest (Sincronizar) Executa admin.refreshManifest(id). Força uma requisição de bypass de cache para ler novamente o manifest.json hospedado no servidor do fornecedor, atualizando versões e caminhos de tela.
Rotate Token (Rotacionar) Executa admin.rotateToken(id). Rotaciona a chave de criptografia exclusiva usada pelo Webhook e barramentos da extensão. Alerta: o token anterior para de funcionar de imediato.
Reset Breaker (Rearmar Disjuntor) Chama admin.resetChannelBreaker(id). Rearma o fusível de segurança contra abuso de chamadas. Se uma extensão gerar requisições descontroladas ou loops, o AtenderBem desliga o barramento daquele canal. Esta ação o reativa.
Remove (Remover) Exclui o registro e desinstala o plugin. Elimina permanentemente a extensão da instância do cliente, limpando seus dados associados e retirando seus botões das telas.

3. O SDK Global: Objeto `omni`

Quando o AtenderBem cria o iframe de uma extensão, ele injeta automaticamente na janela global um SDK sob a variável window.omni. Todas as APIs retornam Promises, facilitando o encadeamento via async/await.

Abaixo está a documentação profunda de todas as APIs disponíveis no SDK, separadas por namespace operacional:

3.1. Sessão & Metadados (`omni.session`)

Permite à extensão mapear onde está executando e quem a está operando.

  • omni.session.getUser() Leitura
    Retorna dados do agente logado na sessão ativa.
    Retorno: Promise<{ id: number, name: string, type: string, email: string, queues: number[], groups: number[] }>
  • omni.session.getPermissions() Leitura
    Retorna os privilégios administrativos e operacionais do usuário.
    Retorno: Promise<{ isAdmin: boolean, isSupervisor: boolean, isSuperAdmin: boolean, flags: object }>
  • omni.session.getLocale() Leitura
    Devolve o idioma e a formatação regional ativa na conta do agente (padrão BCP 47).
    Exemplo: 
    const locale = await omni.session.getLocale(); // Retorna "pt-BR"
  • omni.session.getTheme() Leitura
    Informa se o sistema está em modo claro ou escuro e fornece os tokens de cor da marca corporativa (primária, secundária, fundos).
    Retorno: Promise<{ mode: "light" | "dark", tokens: Record<string, string> }>
  • omni.session.getInstance() Leitura
    Informa o nome e domínio do cliente, permitindo segmentar comportamentos no ERP.
    Retorno: Promise<{ name: string, domain: string, hostVersion: string, viewVersion: string }>

3.2. Navegação (`omni.nav`)

Permite navegar e ler parâmetros da URL do sistema sem forçar um recarregamento (SPA).

  • omni.nav.getRoute() Leitura
    Lê o path e os parâmetros da rota principal em que o agente se encontra.
    Retorno: Promise<{ path: string, params: object, query: object }>
  • omni.nav.navigate(rota) UI
    Redireciona o AtenderBem para outra rota interna (ex: abrir o Kanban de Tickets).
    Argumentos: rota: string | string[] (ex: ["/base", "ticketspanel"])
  • omni.nav.openFullscreen(contributionId) UI
    Abre uma contribuição de tela cheia declarada no manifest da própria extensão.

3.3. Gestão de Chats (`omni.chats`)

Este é o núcleo das integrações de atendimento, fornecendo acesso direto aos chats.

  • omni.chats.getSelected() Leitura
    Obtém detalhes do atendimento que está atualmente aberto e focado na tela do atendente.
    Retorno: Promise<ChatObject> contendo ID, fila, usuário, canal de origem, protocolo e o objeto completo de contato (nome, telefone).
  • omni.chats.select(chatId) UI
    Força o AtenderBem a focar e abrir a janela de chat do ID especificado.
  • omni.chats.get(chatId) Leitura
    Lê dados completos de um chat específico (mesmo que não esteja aberto na tela).
  • omni.chats.listMine() Leitura
    Lista todos os chats ativos sob custódia do próprio agente.
  • omni.chats.getMessages(chatId) Leitura
    Retorna o histórico de mensagens trocadas no chat especificado.
  • omni.chats.sendMessage(chatId, opts) Escrita
    Envia uma mensagem (texto ou mídia) em nome do agente no chat.
    Argumentos: chatId: number, opts: { text: string, fileId?: number }
  • omni.chats.transfer(chatId, opts) Escrita
    Transfere o atendimento ativo para outro atendente ou fila de espera.
    Argumentos: opts: { queueId?: number, userId?: number }

3.4. Catálogo & Carrinho de Compras (`omni.cart`)

API extremamente robusta para e-commerce integrado e envio de links de catálogo do WhatsApp.

  • omni.cart.get(opts?) Leitura
    Lê os itens presentes no carrinho de compras do chat ativo ou de outro chat visível.
    Retorno: Promise<{ total: number, items: Array<{ productId: number, name: string, price: number, qty: number, discount?: number }> }>
  • omni.cart.mutate(opts) Escrita
    Aplica mutações atômicas estruturadas (adicionar, alterar quantidade, remover e dar descontos) de uma só vez.
    Argumentos: opts: { ops: Array<{ op: "add" | "qty" | "remove" | "discount", productId: number, qty?: number, discount?: number }> }
  • omni.cart.sendCartMessage(opts) Escrita
    Dispara um link direto do carrinho interativo no WhatsApp do cliente com um botão "Ver Meu Carrinho".
    Argumentos: opts: { bodyText?: string, buttonText?: string }
  • omni.cart.setFreight(valor) Escrita
    Seta o valor de frete na unidade da moeda da transação.
  • omni.cart.convert() Escrita
    Fecha o carrinho e gera um pedido formal ou oportunidade vitoriosa.

3.5. Formulários Dinâmicos (`omni.forms`)

Permite acionar interfaces nativas de captura de dados sem precisar desenhar o HTML.

  • omni.forms.openDynamic(opts) UI
    Abre um modal nativo e desenha um formulário interativo completo na hora, baseado na definição do JSON fornecido. O AtenderBem gerencia a validação de obrigatoriedade e devolve as respostas estruturadas ao fechar.
    Tipos de campos suportados:
    CódigoTipoDescrição
    1Texto simplesInput de texto padrão.
    2Área de textoTextarea para parágrafos.
    3InteiroInput numérico de inteiros.
    4DecimalInput de ponto flutuante/dinheiro.
    20TítuloElemento visual para organizar seções.
    22ImagemExibe uma imagem a partir de uma URL ou URI Base64.
    Exemplo de chamada estruturada: 
    const formData = await omni.forms.openDynamic({
  formulario: {
    name: "Cadastro de Faturamento",
    fields: [
      { id: "lbl_header", label: "Dados Fiscais", type: 20 },
      { id: "cnpj", label: "CNPJ da Empresa", type: 1, required: true, width: 6 },
      { id: "ie", label: "Inscrição Estadual", type: 1, required: false, width: 6 }
    ]
  }
});
if (formData) {
  console.log("CNPJ:", formData.cnpj);
}

3.6. CRM & Oportunidades (`omni.crm`)

Fornece integração profunda com o módulo de vendas.

  • omni.crm.create(dados) Escrita
    Cria uma oportunidade de venda no funil do CRM.
    Campos obrigatórios: pipelineId e title.
    Campos aceitos: stageId, description, value, recurrentvalue, freight, expectedclosedate, contacts, products, formsdata.
  • omni.crm.changeStage(id, stageId) Escrita
    Move a oportunidade para outra etapa do funil.
  • omni.crm.win(id) / omni.crm.lose(id) Escrita
    Fecha a oportunidade marcando-a como Ganha ou Perdida.

3.7. Interface com o Usuário (`omni.ui`)

Permite emitir alertas, toasts e controlar modais do Host.

  • omni.ui.toast(opts) UI
    Exibe uma pequena notificação flutuante de sucesso/erro no canto da tela do atendente.
    Argumentos: opts: { msg: string }
  • omni.ui.confirm(opts) UI
    Abre um diálogo nativo de pergunta com botões configuráveis (ex: "Faturar" e "Cancelar").
    Retorno: Promise<boolean> (true se o usuário clicar no botão OK).
  • omni.ui.alert(opts) UI
    Abre uma caixa de diálogo nativa com mensagem de aviso e botão de fechar.
  • omni.ui.loading(boolean) UI
    Ativa ou desativa o indicador global de carregamento do AtenderBem, bloqueando a tela contra cliques duplicados enquanto processa a chamada no ERP.

3.8. Recursos Adicionais de Integração

  • omni.http.request(opts) Escrita
    Realiza uma requisição HTTP externa através do proxy do Host, eliminando erros de CORS no navegador.
    Limitações e Segurança:
    • Bloqueia IPs privados (10.x, 172.x, 192.168.x) e loopback (127.x) para segurança interna.
    • Tamanho máximo da resposta: 5 MB.
    • Limite de taxa (Rate Limit): 30 requisições por minuto por instalação de extensão e usuário.
  • omni.storage.get(key) / omni.storage.set(key, val) Local
    Salva dados persistentes (Key-Value) no navegador de forma totalmente isolada (namespaceada automaticamente por extensão e usuário).
  • omni.channel.publish(topic, data) / omni.channel.subscribe(topic) Local
    Barramento de publicação e subscrição de tópicos em tempo real para sincronização instantânea.

4. Catálogo de Eventos em Tempo Real

O Host dispara eventos para os iframes e Workers sempre que há uma mudança de estado no sistema. Para se registrar, o aplicativo usa omni.on("nomeDoEvento", (dados) => { ... }). O catálogo completo de eventos homologados é composto por:

Área Eventos Disponíveis Dados Enviados no Callback
Sessão & UI localeChanged, themeChanged O novo locale ativo (ex: "pt-BR") ou o tema de cores atualizado.
Painel de Atendimento chatPanelOpened, chatPanelClosed, chatListChanged Sinalizações de abertura/fechamento do painel do agente e atualizações de novas mensagens na fila.
Conversas messageSent Objeto contendo ID do chat, remetente, mensagem e carimbo de data/hora.
CRM Oportunidades opportunityOpened, opportunityCreated, opportunityUpdated, opportunityStageChanged, opportunityWon, opportunityLost Informações completas do lead alterado, incluindo ID, valor, etapa de destino e canal vinculado.
Tickets (Help Desk) ticketOpened, ticketCreated, ticketUpdated, ticketStatusChanged Metadados do ticket, equipe designada, prioridade, SLA e estágio.
Tarefas de Equipe taskCreated, taskUpdated, taskDone Status da tarefa do agente, prazo de entrega e responsável.
Base de Contatos contactOpened, contactCreated, contactUpdated ID do contato alterado, nome, telefone e campos extras de faturamento vinculados.

5. Ambiente de Desenvolvimento e Testes: O "Ensaio"

Desenvolver extensões diretamente no ambiente de produção de uma central de atendimento é perigoso. Para mitigar esse risco, o AtenderBem traz um módulo inovador no path /base/extensions-editor chamado Ensaio (Trial Run):

  1. Rascunho de Desenvolvimento: O programador cria seu manifest e arquivos de tela localmente ou em uma CDN de desenvolvimento.
  2. Emissão do Link de Ensaio: No editor, ele fornece a URL de teste e gera um link temporário exclusivo de Ensaio, válido por algumas horas.
  3. Teste em Sessão Real: Quem abrir este link especial passa a carregar o rascunho da extensão no lugar da versão homologada de produção.
  4. Ambiente Real: Ao contrário de um ambiente simulado estático, o Ensaio roda sob sessões reais do agente, visualizando atendimentos reais, CRM real e permissões reais, garantindo fidelidade de 100% nos testes.
  5. Indicador de Segurança: Durante toda a execução do Ensaio, uma faixa de alerta amarela proeminente é renderizada no topo do painel do agente com a mensagem de que um teste real de extensão está em curso naquela aba. Ela some instantaneamente ao expirar ou revogar o token de preview.

6.3. Passo a Passo para Instalação Prática no AtenderBem

  1. Acesse o painel com perfil de administrador.
  2. Navegue até o menu de Configurações › Extensões (ou digite diretamente a URL: https://fastcorte.atenderbem.com/base/config/extensioninstalls).
  3. Clique no botão Add (Adicionar).
  4. No formulário de inclusão, preencha a URL do manifesto oficial da FastCorte:
    https://raw.githack.com/ivannhabilis/manual_atenderbem/main/ext/demo-vendas/manifest.json
  5. Clique em Salvar. O sistema irá consultar a URL, validar as permissões de barramento, carregar o ícone de carrinho e exibir a extensão na grade como Habilitada.
  6. Abra a tela de atendimentos do agente em /base/agentchat. Selecione qualquer chat ativo.
  7. No painel lateral direito, selecione a nova aba Assistente de Vendas ERP. A interface desenhada pelo nosso arquivo HTML/JS será renderizada perfeitamente, isolada de forma segura e se conectando instantaneamente ao atendimento em curso.

7. FAQ — Perguntas Frequentes (Módulo de Extensões)

Q1. Qual é a tecnologia por trás do isolamento das extensões?

As extensões de tela rodam dentro de um elemento <iframe> seguro com políticas de sandbox estritas e Content Security Policy (CSP) injetadas de forma dinâmica. Os scripts de background opcionais são executados em Web Workers isolados da thread principal do DOM do AtenderBem, impedindo que falhas de script travem o fluxo do atendente.

Q2. Como as extensões superam os problemas de segurança de requisições externas (CORS)?

Requisitar dados de um ERP externo diretamente pelo JavaScript do navegador costuma ser bloqueado por políticas de segurança de CORS. O AtenderBem resolve isso oferecendo o método omni.http.request, que atua como um proxy reverso seguro. O navegador fala com o servidor do AtenderBem, e o servidor faz a requisição final para a API do ERP, permitindo uma comunicação limpa livre de CORS.

Q3. O que é o "disjuntor" (Circuit Breaker) e como rearmá-lo se a extensão cair?

O AtenderBem implementa uma proteção de sistema contra loops de código ineficientes. Se uma extensão instalada exceder 30 requisições por minuto por usuário, ou devolver uma quantidade massiva de erros de rede consecutivos, o barramento de comunicação é cortado preventivamente ("Desligado pelo disjuntor"). Para reativá-lo após correções no código, o administrador deve acessar /base/config/extensioninstalls e clicar em Reset Breaker (Rearmar Canal).

Q4. Onde os dados gravados por `omni.storage` ficam armazenados fisicamente?

Os dados persistidos via omni.storage.set() são salvos localmente na base do navegador do agente de suporte. Os registros são totalmente isolados e criptografados sob uma chave contendo o prefixo da extensão, impedindo de forma absoluta que uma extensão de terceiros acesse dados armazenados por outra.

Q5. Qual é a diferença entre um teste de "Ensaio" e a ativação direta de produção?

A ativação de produção (Add) habilita o módulo de forma definitiva para todos os agentes selecionados no filtro de visibilidade da empresa. O "Ensaio" (Trial Run) gera uma credencial de bypass temporária. Apenas as pessoas que clicarem no link de Ensaio verão a versão experimental da extensão, permitindo homologação em tempo real sem expor o restante da equipe.

Q6. Como funcionam as permissões de público-alvo (Audience) em uma extensão?

Durante a instalação ou edição da extensão no AtenderBem, o administrador pode amarrar a visibilidade da extensão a grupos visuais ou perfis de usuários específicos. Por exemplo, o "Assistente de Faturamento ERP" pode ser exposto exclusivamente para agentes do setor "Financeiro", enquanto o "Assistente de Logística" fica visível apenas para a equipe de "Expedição".

Q7. Uma extensão pode atuar de forma invisível/plano de fundo?

Sim. O manifesto aceita a contribuição do tipo backgroundWorker. Esse recurso não exibe nenhum iframe na tela do atendente; em vez disso, executa um worker silencioso que fica monitorando barramentos de eventos (como messageSent ou ticketStatusChanged) para registrar logs em bancos externos ou acionar webhooks em tempo real de forma invisível.

Q8. O AtenderBem aceita arquivos locais ou a extensão precisa ser hospedada externamente?

O manifesto deve residir em uma URL acessível pela plataforma, mas os arquivos de interface (como HTML, CSS e JavaScript) podem ser servidos a partir de qualquer servidor web seguro do cliente ou CDN (como o GitHub Pages, servidores VPS locais, ou CDN Cloudflare). Toda a renderização final ocorre de forma segura no lado do cliente.

Q9. O que são os "warnings" de dependência (missingrequireslabels) exibidos no AtenderBem?

Se a extensão necessitar de recursos exclusivos do sistema para rodar (por exemplo, acesso ao módulo de CRM ou ao catálogo integrado de produtos do WhatsApp) e esses recursos estiverem desativados na licença corrente da empresa no AtenderBem, a plataforma listará avisos preventivos na grade de configurações para sinalizar o bloqueio dessas APIs.

Q10. Como o tema escuro do AtenderBem é repassado para a extensão?

Ao mudar de modo (claro/escuro) no menu do AtenderBem, o Host dispara imediatamente o evento de sistema themeChanged para todos os iframes ativos de extensões. O SDK capta e repassa esses dados para o callback registrado no JavaScript da extensão, permitindo ao desenvolvedor alterar as variáveis de estilos CSS na hora.

Q11. É seguro trafegar chaves e segredos de API nas URLs das extensões?

Não. Nenhuma chave secreta ou token de banco de dados do ERP deve ser gravado diretamente no código JavaScript do iframe. Em vez disso, o desenvolvedor declara as credenciais necessárias no manifesto e o administrador preenche essas variáveis na tela de configurações da extensão (Config). Essas variáveis de configuração do AtenderBem são trafegadas de forma segura por canais criptografados no handshake (omni.ready).

Q12. Qual é a versão mínima exigida do Host para usar Extensões?

A funcionalidade requer o AtenderBem Host na versão 1.40.0 ou superior. Caso a extensão declare a tag minHostVersion no arquivo de manifesto e a versão da central de atendimento seja anterior, a plataforma registrará um alerta de incompatibilidade e poderá impedir a execução dos barramentos.

Q13. Como fechar ou redimensionar um painel de extensão de forma programática?

Para fechar um modal ou um painel aberto pela extensão, chame o método omni.ui.close(). Para ajustar a altura do iframe de forma responsiva baseado em transições visuais internas do seu HTML, use o método omni.ui.resize(alturaEmPixels).

Q14. O que acontece com a extensão se a internet do agente de atendimento cair?

O AtenderBem detecta a perda de conectividade e entra em modo offline. O iframe da extensão permanece na tela, mas chamadas de API como omni.http.request ou mutações do carrinho falharão de forma imediata. O barramento de eventos é re-estabelecido automaticamente assim que a conexão de rede do agente for restaurada.

Q15. Onde encontrar suporte e atualizações técnicas do SDK de extensões?

Dúvidas adicionais e homologações de segurança de novos plugins de canais podem ser esclarecidas diretamente com a equipe corporativa de engenharia de software e canais no e-mail suporte@atenderbem.com.br.
