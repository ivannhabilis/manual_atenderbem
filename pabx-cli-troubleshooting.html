1. Como Acessar a Linha de Comando (CLI)

Você pode executar comandos do Asterisk de duas formas:

  • Via Painel Web do FreePBX: Acesse o menu Admin › Asterisk CLI, digite o comando no campo e clique em Send Command.
  • Via Terminal SSH no Servidor: Execute asterisk -rx "SEU_COMANDO_AQUI" para uma execução rápida e segura sem travar a sessão.

3. Guia de Resolução dos 5 Maiores Problemas (Troubleshooting)

Problema 1: Áudio Mudo ou de Uma Via Só (One-Way Audio)

  • Causa Raiz: O PABX está atrás de um roteador/NAT e não está enviando seu IP público correto no cabeçalho SDP dos pacotes de voz (RTP).
  • Solução: Acesse Settings › Asterisk SIP Settings › General SIP Settings, clique em Detect Network Settings para preencher o External Address e confirme se as portas UDP 10000 a 20000 estão liberadas no firewall.

Problema 2: Tronco WhatsApp Meta Offline (Canal Não Sobe)

  • Causa Raiz: Falha de handshake TLSv1.2 ou certificado Let's Encrypt gerado com hostname incorreto.
  • Solução: Certifique-se de que o certificado em Admin › Certificate Management tem o mesmo hostname com sufixo -direct fornecido pelo AtenderBem e que o transporte está como 0.0.0.0-tls com codec opus habilitado.

Problema 3: Ramal do Webphone no AtenderBem Não Conecta

  • Causa Raiz: Senha (secret) digitada incorretamente no cadastro do usuário ou bloqueio de porta WebSocket.
  • Solução: Copie novamente a senha do ramal em Applications › Extensions no PABX e cole em Configurações › Usuários › Habilitar Softphone no AtenderBem.

Problema 4: O Cliente Digita os Números na URA e o PABX Não Reconhece

  • Causa Raiz: Incompatibilidade no envio de tons DTMF entre a operadora e o Asterisk.
  • Solução: No tronco SIP da operadora, ajuste o parâmetro DTMF Mode para rfc4733 ou rfc2833.

Problema 5: Chamada Cai Imediatamente Após Atender

  • Causa Raiz: Incompatibilidade de codecs de áudio entre as duas pontas.
  • Solução: No FreePBX, em Settings › Asterisk SIP Settings, ative os codecs ulaw, alaw, g729 e opus para garantir compatibilidade universal.

4. Fluxo de Diagnóstico de uma Chamada em Tempo Real

Quando o parceiro relata uma falha genérica (“não completa”, “sem áudio”, “cai sozinho”), siga esta sequência para isolar a causa antes de alterar qualquer configuração:

  1. Confirme o estado geral do servidor: versão, tempo de atividade e recursos.
  2. Suba temporariamente o nível de detalhe do console para enxergar o que o Asterisk está fazendo.
  3. Ative o log específico do sintoma: pacotes SIP para falhas de registro/autenticação, pacotes RTP para problemas de áudio.
  4. Peça ao parceiro para reproduzir a chamada e observe a saída no console/SSH em tempo real.
  5. Isole a ponta com falha: verifique se o ramal/tronco está registrado, se o canal subiu e como está a fila.
  6. Encerre o diagnóstico desativando os logs para não sobrecarregar o servidor e os arquivos de log.
# 1. Estado geral
asterisk -rx "core show version"
asterisk -rx "core show uptime"
asterisk -rx "core show sysinfo"

# 2. Nível de detalhe
asterisk -rx "core set verbose 5"
asterisk -rx "core set debug 5"

# 3. Logs específicos
asterisk -rx "pjsip set logger on"     (falhas de SIP: 401, 404, 486)
asterisk -rx "rtp set debug on"        (problemas de áudio)

# 5. Isolamento da ponta
asterisk -rx "pjsip show endpoints"
asterisk -rx "pjsip show registrations"
asterisk -rx "core show channels"
asterisk -rx "queue show 100"

# 6. Encerramento
asterisk -rx "pjsip set logger off"
asterisk -rx "rtp set debug off"
asterisk -rx "core set verbose 0"
asterisk -rx "core set debug 0"
Exemplo de retorno de status: core show version retorna algo como Asterisk 18.12.0; core show uptime retorna algo como System uptime: 5 days, 3 hours; e core show calls retorna, por exemplo, 2 active calls. Um uptime menor do que o esperado indica reinício inesperado do Asterisk.
Atenção com os logs: pjsip set logger on e rtp set debug on geram muita saída. Mantenha-os ativos apenas durante a reprodução do problema e desative-os em seguida. Os logs também ficam gravados em /var/log/asterisk/full (verificável com logger show channels).

Derrubar uma Chamada Travada

Se um canal ficar preso (ramal ocupado mesmo sem ligação ativa), identifique o canal exato e solicite o desligamento:

asterisk -rx "core show channels"
asterisk -rx "channel request hangup PJSIP/1001-00000042"

5. Referência Rápida: Comandos Essenciais para Filas

O que você quer fazerComando prático
Ver o status de uma filaqueue show 100
Ver todas as filasqueue show
Adicionar ramal à filaqueue add member PJSIP/2000 to 100
Remover ramal da filaqueue remove member PJSIP/2000 from 100
Remover ramal Local da filaqueue remove member Local/7078@from-queue/n from 200

Despausar ramalqueue unpause member PJSIP/2000 from 100

Dica de uso combinado: comandos set (logger, debug, verbose) alteram o comportamento da sessão atual do console. Prefira sempre a forma asterisk -rx "COMANDO" via SSH para execuções pontuais, pois ela não trava a sessão e devolve apenas o resultado do comando.
