Automações e URA — Catálogo de Elementos

Os 144 elementos do editor de Fluxo de Automação e URA, com campos, ramos, variáveis e exemplos verificados.

O que este capítulo cobre. Os 144 elementos do catálogo de Fluxo de Automação e URA, com o que fazem, em que tipo de fluxo funcionam, os campos de configuração, as saídas e ramos, e exemplos de uso encadeado. Cobre também as variáveis e expressões que se escrevem entre {{ }} e a linguagem de fluxo usada para montar tudo isso. Dois elementos que existem no editor mas não constam do catálogo da API — sentDTMF e startCall — aparecem nos respectivos grupos com a ressalva técnica de cada um.

1. Como ler as fichas de elemento

Cada elemento tem uma ficha com o seguinte conteúdo:

Parte da fichaO que traz
O que fazA função do elemento e as observações de comportamento que a própria plataforma registra.
Disponível emEm quais filas o elemento pode ser usado (alguns só existem na voz, outros só na automação).
Como se escreveA forma dele na linguagem de fluxo, com o rótulo e os campos.
Saídas e ramosPara onde o fluxo vai depois dele: seta, ramo case, else ou a porta body do laço.
CamposCada campo com o tipo e se é obrigatório.
Exemplo de usoUm fluxo completo e verificado que usa o elemento.

2. Os três tipos de fluxo

Ao criar um fluxo escolhe-se o tipo. O tipo define quais elementos ficam disponíveis:

TipoPara que serveExemplo de elemento exclusivo
URAFluxo de atendimento por mensagem — conversa com o cliente no chat, com perguntas, opções e espera de resposta.question, options
AutomaçãoFluxo de bastidor: roda por gatilho (mensagem recebida, abertura de atendimento, encerramento, tempo, mudança no CRM) sem prender a conversa.addOpportunity, addPersistent
URA telefônicaFluxo de voz: toca áudio, lê o teclado do telefone e desvia a chamada.callPlayAudio, sentDTMF
Atenção: o tipo escolhido na criação é imutável. Para mudar o canal, crie outro fluxo.

3. A linguagem do fluxo

Todo fluxo pode ser lido e escrito como texto. É esse mesmo texto que a importação e a exportação usam, e é ele que aparece nos exemplos deste capítulo.

  1. Um elemento por linha: rotulo: tipoDoElemento campo=valor outroCampo=valor.
  2. A linha seguinte continua o fluxo. Nada de escrever "próximo elemento": a queda é implícita.
  3. Desvios e fim: -> outroRotulo desvia; -> end encerra a cadeia.
  4. Valores entre aspas duplas. Texto longo aceita """ ... """.
  5. Ramos abrem na mesma linha do elemento: checa: varCondition value="{{total}}" { case alto conditionOperator=">" conditionValue="100" { ... } else { ... } }.
  6. Laço: laco: loop mode="forEach" list="{{lista}}" { body { ... -> laco } } — o último elemento do corpo volta para o laço.
  7. Elemento já existente: o que não for escrito permanece como está; para apagar um campo, escreva !campo.
Por que isso importa: com o texto em mãos, dá para versionar, comparar e restaurar fluxos — e para reaproveitar um exemplo deste capítulo importando-o direto no seu ambiente.

5. Como testar antes de publicar

  1. Monte ou edite o texto do fluxo.
  2. Valide antes de salvar: o próprio sistema compila o texto e devolve erro de sintaxe com linha e coluna, e os erros de configuração por elemento.
  3. Só depois grave. Ao gravar, cada versão fica no histórico e pode ser comparada e restaurada.

Todos os exemplos deste capítulo passaram por essa compilação antes de serem publicados.

6. Do texto ao arquivo .ivr

O mesmo fluxo existe em duas formas, e vale entender a diferença para não perder tempo:

FormaOnde aparecePara que serve
Linguagem de fluxo (texto)Nos exemplos deste capítulo e nas telas de importação/exportação por API e no histórico de versões.Ler, comparar, versionar e criar/atualizar o fluxo por API.
Arquivo .ivrBotão Exportar da tela Fluxo de Automação e URA; é o que o botão Importar aceita.Levar um fluxo pronto de um ambiente para outro, com os elementos já ligados.

Por dentro, o .ivr é o registro do fluxo codificado: um JSON com os dados do cabeçalho (nome, tipo, timeout) e o campo options com a lista de elementos. Cada elemento tem id, type (o número do tipo), posição na tela (x/y) e config (os campos da ficha). As ligações ficam em config.nextElementId; os ramos de uma condição ficam em config.options, cada um com o seu nextElementId.

O número do tipo é o mesmo em todo lugar. 0 é Enviar mensagem, 4 é Encerrar atendimento, 5 é Transferir atendimento, 13 é Gerar protocolo e assim por diante — é exatamente o tipo interno mostrado em cada ficha deste capítulo.

Todo exemplo deste capítulo tem as duas formas: o texto (para ler e entender) e o arquivo .ivr (para importar e usar).
