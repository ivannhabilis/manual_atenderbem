Custom Destinations e Integração ARI Bridge com AtenderBem

Como conectar o motor de telefonia do Asterisk à inteligência de URA Avançada e fluxos de atendimento do AtenderBem via ARI (Asterisk REST Interface).

1. O que é o ARI Bridge?

O ARI (Asterisk REST Interface) é uma API moderna do Asterisk que permite que aplicações externas controlem canais de voz em tempo real. Através do destino especial ari-bridge, o PABX Fácil transfere a chamada recebida para a URA Visual Avançada do sistema AtenderBem, permitindo fluxos com inteligência artificial, integração de banco de dados e roteamento dinâmico.

2. Passo 1: Criando o Custom Destination no FreePBX

  1. No menu superior do PABX, acesse Admin › Custom Destinations.
  2. Clique no botão + Add Destination.
  3. Preencha os campos com os parâmetros exatos:
    • Target: ari-bridge,NOME_FILA,1 (Exemplo: ari-bridge,apptest,1). Importante: O nome apptest será o identificador da fila no sistema web.
    • Description: Ponte ARI - URA Telefonia AtenderBem.
    • Notes: Encaminha chamada de voz para o fluxo de URA do sistema omnichannel.
    • Return: Selecione No.
  4. Clique em Submit e em Apply Config.

3. Passo 2: Criando a Fila no AtenderBem

  1. No painel do AtenderBem, acesse Configurações › Filas › + Adicionar.
  2. No campo Nome da Fila, digite RIGOROSAMENTE O MESMO NOME informado no target do PABX (no exemplo: apptest).
  3. No campo Tipo da Fila, selecione a opção Telefonia (URA).
  4. Na seção de configurações da fila, na opção Enviar para a URA, selecione a URA do tipo "URA Avançada (telefonia)" que você deseja que atenda as chamadas.
  5. Clique em Salvar.
Vínculo Estabelecido: A partir deste momento, qualquer rota de entrada no PABX que tiver como destino este Custom Destination entregará a chamada diretamente para o fluxo de URA inteligente do AtenderBem.

4. Referência dos Campos do Custom Destination

Os campos do formulário de Custom Destination no FreePBX e o que preencher em cada um:

CampoO que preencherObservação
Targetari-bridge,NOME_FILA,1Aponta para o destino ARI e para o nome da fila (ex.: apptest). O nome apptest pode ser alterado.
Destination Quick PickSeleção de destino existenteAtalho (pick destination) para reaproveitar um destino já cadastrado no PABX como ponto de partida.
DescriptionTexto descritivoDescrição do destino (ex.: Ponte ARI - URA Telefonia AtenderBem).
NotesNotas / informações adicionaisCampo livre para documentar a finalidade do destino.
ReturnNoIndica que a chamada não retorna ao ponto de origem após executar o destino.
Nome da fila: o identificador usado no Target (no exemplo, apptest) deve ser exatamente o mesmo cadastrado como nome da fila no AtenderBem — é essa correspondência que faz a ponte ARI encontrar a fila correta.

5. Parâmetros de Integração do Módulo de Telefonia

A comunicação entre o AtenderBem e o Asterisk é definida por um objeto de configuração do módulo de telefonia. Os parâmetros documentados no acervo são:

ChaveDescrição
enableTelephonyHabilita (true) ou desabilita o módulo de telefonia na instância.
asteriskHostEndereço do servidor Asterisk que hospeda o PABX.
amiUser / amiPortCredenciais e porta do Asterisk Manager Interface — AMI (5038 por padrão), usado para controlar e monitorar chamadas.
asteriskWssHost / asteriskWssPortHost e porta do WebSocket seguro (2087) usado pelo webphone no navegador.
pjsipIndica que o driver de canais é o chan_pjsip (true).
asteriskCDREnabled / asteriskCDRDBHost / asteriskCDRDBName / asteriskCDRDBPortHabilitação e conexão com o banco de CDR (asteriskcdrdb, porta 3306) usado pela auditoria de chamadas.
audioMode / audioServer / audioPathModo de áudio (remote) e servidor/caminho onde ficam armazenados os áudios das URAs.
Segurança: campos de credencial (amiPass, asteriskCDRDBPass, audioServerToken) são segredos da instalação. Nunca os exponha em documentação compartilhada — trate-os como dados sensíveis do cliente.
