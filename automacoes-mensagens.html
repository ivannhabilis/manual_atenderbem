message

Envia uma mensagem para o cliente. Não aguarda resposta e segue para o próximo elemento imediatamente.

Quando utilizado em uma automação, é necessário que um atendimento esteja associado a essa.
Caso nenhum atendimento esteja associado a automação, esse elemento será ignorado.
Pode acompanhar botões de resposta rápida (campo buttons da MessageConfig). Diferente do elemento options, esses botões NÃO interrompem o fluxo: a mensagem é enviada com os botões e o fluxo segue imediatamente para o próximo elemento, sem aguardar a escolha do cliente. São úteis para enviar respostas rápidas em que não se aguarda retorno, ou cujo retorno virá de forma assíncrona em outro atendimento. Máximo de 3 botões. Os botões só são enviados em filas Webchat, WAGS, WA Cloud API, WA Dialog, WA Dialog Cloud, WA Smarte, FB e IG; nas demais filas apenas o texto é enviado.
ENVIO FORA DO ATENDIMENTO DO FLUXO (campos opcionais da MessageConfig; vazios = comportamento acima):
- chatId: envia em OUTRO atendimento aberto (por exemplo o aberto por openChat sem associar, ou um item da lista do queueChats). O fluxo não espera resposta dele. Em fila oficial com a janela de 24 horas fechada nada é enviado (WINDOW_CLOSED).
- phoneNumber (com countryCode e, opcionalmente, queueId; vazio = fila do fluxo): envia para um NÚMERO sem abrir atendimento. Filas aceitas: WhatsApp não oficial e oficiais; Telegram e demais canais recusam (QUEUE_TYPE_UNSUPPORTED). Se já houver atendimento aberto para o número, actionWhenOpen decide: 0 envia nele, 1 não envia (CHAT_OPEN). Sem atendimento aberto: em fila OFICIAL só envia com a janela de 24 horas do número aberta (senão WINDOW_CLOSED; fora da janela use sendTemplate); em fila NÃO OFICIAL a mensagem entra na fila de disparo (a mesma das mensagens enviadas pela API), que respeita o ritmo de envio e confere se o número tem WhatsApp — ela sai logo depois, não na hora, e isso protege o número contra bloqueio por disparo em massa. Os botões são enviados também sem atendimento.
- Fila NÃO OFICIAL que autenticou (conectou ou reconectou) há menos de 5 minutos: nada é enviado nem enfileirado — nem mesmo num atendimento já aberto para o número — e o erro é QUEUE_NOT_READY; trate o erro ou tente de novo mais tarde.
- Com chatId ou phoneNumber o elemento roda também em automação sem atendimento associado. Na aba "Testar" nada é enviado (VIRTUAL_CHAT).
- resultVariableName (opcional) recebe o ID da mensagem (ou do registro enfileirado), resultVariableName + "_status" recebe SENT ou QUEUED e resultVariableName + "_error" o código da recusa ("" em sucesso). Só recusas locais voltam ao fluxo: uma falha posterior do provedor não volta.
VÍNCULO INTERNO COM PRODUTOS (campo opcional productIds): um ID de produto, lista de IDs separados por vírgula ("5,7"), array de números ou variável que resolva para um desses formatos. Os IDs viram o atalho "Ver produto(s)" no painel do atendente, para ele abrir o cadastro do item a partir da conversa. A mensagem enviada ao cliente continua sendo a mensagem de texto comum — não vira mensagem de produto em canal nenhum. Use quando a resposta da automação recomenda produtos que o atendente precisa enxergar (ex.: IDs vindos de um webhook de ERP). IDs inexistentes são descartados com aviso na depuração; se nenhum resolver, a mensagem sai sem vínculo. Vazio/omitido = sem vínculo.
Esses campos valem só para o elemento message: info, question e requestLocation não os têm.

changeMessageVisualGroup

Altera o grupo de visualização (fk_visualgroup) de uma mensagem do chat atual, restringindo quem pode vê-la. Somente mensagens do próprio atendimento associado ao fluxo podem ser alteradas — se a mensagem não for encontrada no chat atual, o elemento é ignorado e o fluxo segue normalmente. Tipicamente usado para ocultar uma mensagem (por exemplo, uma resposta de pesquisa) de agentes comuns antes de o atendimento ser atribuído; administradores e supervisores continuam vendo. A alteração é aplicada em memória e no banco de dados. Não gera variáveis.

Exemplos de uso

Fluxos completos que usam os elementos deste grupo. Cada exemplo foi compilado pelo próprio sistema antes de entrar aqui.

Boas-vindas, menu principal e consulta com validação de CPF

Receber o cliente no primeiro contato, oferecer as opções da central em um menu tocável e só pedir o CPF quando ele escolhe consultar um pedido.

  1. message — cumprimenta o cliente pelo nome e avisa que ele falou com a central de atendimento.
  2. info — grava uma nota interna (só o atendente vê) dizendo que o cliente está sendo triado pelo menu.
  3. options — apresenta o menu com três caminhos (consultar pedido, segunda via e falar com atendente) e um else para a escolha que não existe.
  4. question — no caminho do pedido, pede o CPF do titular e valida o formato antes de seguir; se vier inválido, usa o texto de validateError.
  5. message — confirma o CPF recebido e mostra o protocolo do atendimento.
  6. url — no caminho da segunda via, envia um botão de ação com o link do boleto montado com o telefone do cliente.
  7. terminate — fecha cada caminho com o motivo correspondente.
boas_vindas: message text="Olá, {{chat_client_name}}! Você está falando com a Central de Atendimento."
nota_triagem: info text="Triagem automática pelo menu principal. O cliente ainda não escolheu uma opção."
menu_principal: options text="Escolha uma opção para eu te ajudar mais rápido:" type=0 {
  case pedido text="Consultar um pedido" {
    pede_cpf: question varName="cpf_cliente" text="Informe o CPF do titular do pedido, apenas os números." validate=1 validateError="CPF inválido. Envie os 11 números, sem pontos nem traços."
    cpf_recebido: message text="Obrigado! Com o CPF {{cpf_cliente}} eu localizo o pedido e sigo com a consulta."
    aviso_protocolo: message text="Guardei este atendimento no protocolo {{chat_protocol}}."
    fim_pedido: terminate reason="Consulta de pedido iniciada"
  }
  case boleto text="Segunda via de boleto" {
    link_boleto: url text="Toque no botão abaixo para abrir a segunda via:" btnText="Abrir segunda via" data="https://financeiro.exemplo.com.br/boleto/{{chat_client_number}}"
    aviso_boleto: message text="Se o botão não abrir, responda esta conversa que um atendente gera o boleto para você."
    fim_boleto: terminate reason="Segunda via enviada ao cliente"
  }
  case humano text="Falar com um atendente" {
    aviso_fila: message text="Combinado! Estou te colocando na fila de atendimento humano agora."
    fim_humano: terminate reason="Cliente pediu atendimento humano"
  }
  else {
    nao_entendi: message text="Não entendi a opção. Sem problema: vou te encaminhar para um atendente para não te deixar esperando."
    fim_invalido: terminate reason="Opção inválida no menu principal"
  }
}
Resultado: O cliente vê a saudação, toca em uma opção e recebe a confirmação (com o link do boleto ou o pedido de CPF validado); cada caminho encerra o atendimento com um motivo registrado.

Pesquisa de satisfação com a nota protegida

Colher a nota do cliente no fim do atendimento e esconder a resposta dele dos atendentes comuns, deixando-a visível só para supervisores.

  1. message — avisa que o atendimento está terminando e que vem uma pergunta rápida.
  2. question — pergunta a nota de 0 a 10 e guarda a resposta na variável nota_atendimento, esperando a resposta do cliente.
  3. changeMessageVisualGroup — move a mensagem mais recente ({{message_id}}) para o grupo de visualização 1, restringindo quem pode vê-la.
  4. info — deixa a nota registrada como informação interna para quem pode ver a mensagem.
  5. terminate — encerra o atendimento com o motivo pesquisa respondida.
abre_pesquisa: message text="Antes de encerrar, quero saber como foi este atendimento."
pede_nota: question varName="nota_atendimento" text="De 0 a 10, que nota você dá para o atendimento de hoje? Responda apenas com o número."
protege_nota: changeMessageVisualGroup messageId="{{message_id}}" visualGroupId="1"
nota_interna: info text="Nota informada pelo cliente: {{nota_atendimento}}. A mensagem com a resposta foi movida para o grupo de visualização 1: supervisores e administradores continuam vendo, atendentes comuns não."
agradece_nota: message text="Obrigado pela avaliação, {{chat_client_name}}! Sua nota {{nota_atendimento}} foi registrada e vai nos ajudar a melhorar."
fim_pesquisa: terminate reason="Pesquisa de satisfação respondida"
Resultado: O cliente responde uma única pergunta e recebe o agradecimento; o atendente comum não vê a nota na conversa, mas o supervisor e o administrador continuam vendo.

Coleta de endereço com Whatsapp Flow e limpeza do dado sensível

Pedir o endereço de entrega em um formulário nativo do WhatsApp, usar a localização compartilhada como conferência e apagar o conteúdo do Flow logo depois.

  1. sendTemplate — abre a conversa com um template pré-aprovado (exemplo para fila WA Cloud API).
  2. waitMessage — espera o cliente mandar a primeira mensagem antes de pedir dados.
  3. requestLocation — envia o pedido de localização para conferir a região da entrega.
  4. sendFlow — manda o Whatsapp Flow de endereço, com cabeçalho, corpo, rodapé e o texto do botão.
  5. clearFlowDataFromMessage — limpa a resposta do Flow da última mensagem recebida, inclusive no banco de dados.
  6. message — confirma o recebimento dos dados e avisa que o frete será calculado.
  7. sendMail — envia o e-mail de confirmação de endereço usando o modelo cadastrado.
  8. terminate — encerra o atendimento com o motivo endereço coletado.
abre_confirmacao: sendTemplate templateId=0
aguarda_cliente: waitMessage
pede_localizacao: requestLocation text="Para calcular o frete, toque em Anexar e compartilhe sua localização."
form_endereco: sendFlow flowId="flow-endereco-entrega" initialScreenId="ENDERECO_ENTREGA" headerText="Dados de entrega" bodyText="Confirme o endereço de entrega do pedido {{chat_protocol}}." footerText="Leva menos de um minuto." btnText="Preencher endereço"
limpa_dados_flow: clearFlowDataFromMessage
confirma_recebimento: message text="Prontinho, {{chat_client_name}}! Recebemos seus dados com segurança e o frete já vai ser calculado."
confirma_por_email: sendMail mailQueueId="fila-email-transacional" modelId="modelo-endereco-confirmado" mails="{{chat_client_email}}"
fim_endereco: terminate reason="Endereço coletado pelo Whatsapp Flow"
Resultado: O cliente preenche o endereço dentro do WhatsApp, recebe a confirmação no chat e o e-mail; os dados do formulário deixam de ficar guardados na conversa.

Comentário no Instagram respondido e convertido em atendimento no direct

Responder o comentário na publicação, chamar o cliente no direct e oferecer um menu com o contato do consultor para quem quer falar de planos.

  1. replyComment — responde publicamente o comentário recebido na publicação (exemplo para fila IG).
  2. message — continua a conversa no direct, já com o nome do contato.
  3. options — mostra o menu com preços, suporte técnico e um else para quem escreve outro assunto; erra duas vezes e reapresenta com errorRetryMessage.
  4. shareContact — no caminho de preços, compartilha o cartão de contato do consultor da região.
  5. info — registra, no caminho sem escolha, que o comentário virou atendimento no direct.
  6. terminate — fecha cada caminho com o motivo do encerramento.
responde_comentario: replyComment text="Oi, {{contact_name}}! Trouxe a conversa para o direct para te ajudar por lá."
boas_vindas_direct: message text="Vi seu comentário na publicação e vim falar com você por aqui. Como posso ajudar?"
menu_direct: options text="Me diga sobre o que você quer falar:" type=0 errorRetryCount=2 errorRetryMessage="Não entendi. Por favor, toque em uma das opções acima." {
  case precos text="Preços e planos" {
    resumo_precos: message text="Nossos planos incluem implantação assistida e suporte em horário comercial. Vou te passar o contato do consultor."
    contato_consultor: shareContact contactId="consultor-regiao-sul"
    orienta_contato: message text="Salve o contato acima: ele é o consultor responsável pela sua região e fala com você pelo WhatsApp."
    fim_precos: terminate reason="Comentário do Instagram atendido - planos"
  }
  case suporte text="Suporte técnico" {
    encaminha_suporte: message text="Certo! Vou te encaminhar para o time de suporte técnico, que responde em horário comercial."
    fim_suporte: terminate reason="Comentário do Instagram atendido - suporte"
  }
  else {
    outro_assunto: message text="Sem problema! Escreva aqui o que você precisa que eu sigo com você."
    nota_comentario: info text="Comentário do Instagram respondido e convertido em atendimento no direct; o cliente não escolheu uma opção do menu."
    fim_outros: terminate reason="Comentário do Instagram atendido - outros assuntos"
  }
}
Resultado: Quem comentou recebe uma resposta pública e é atendido no direct; quem quer falar de planos sai da conversa com o contato do consultor salvo no aparelho.

Cancelar a mensagem programada fora do horário comercial

Impedir que uma mensagem programada chegue ao cliente fora do horário de funcionamento, cancelando o envio e deixando o registro para o próximo dia útil.

  1. businesshoursCheck — consulta a configuração de horário de funcionamento: dentro do horário o fluxo segue no caminho aberto, fora dele cai no bloco closed.
  2. cancelMessage — no caminho fechado, interrompe o envio da mensagem programada.
  3. info — explica no atendimento por que o envio foi interrompido e quando ele será retomado.
  4. marker — no caminho aberto, etiqueta o atendimento para o controle de envios.
  5. terminate — encerra os dois caminhos, cada um com o seu motivo.
checa_envio: businesshoursCheck configId="horario_comercial" {
  closed {
    cancela_envio: cancelMessage
    registra_cancelamento: info text="Envio cancelado: o cliente está fora do horário comercial e a mensagem programada só será retomada no próximo período de atendimento."
    fim_cancelado: terminate reason="Mensagem programada cancelada fora do horário"
  }
}
libera_envio: info text="Dentro do horário de funcionamento: a mensagem programada seguiu normalmente para o cliente."
etiqueta_envio: marker markerId="etiqueta-envio-controlado"
fim_liberado: terminate reason="Mensagem programada liberada"
Resultado: O cliente só recebe a mensagem em horário comercial; fora dele o envio é cancelado e fica registrado no atendimento com etiqueta e motivo do encerramento.
