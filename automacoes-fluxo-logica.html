varCondition

Controla o fluxo de acordo com o valor de uma variável ou com expressões lógicas. Cada item de options é um ramo; os ramos são testados NA ORDEM e o primeiro que casar define o caminho. Se nenhum casar, o fluxo segue por nextElementId (saída padrão).

Há dois tipos de ramo, que podem ser misturados no mesmo elemento:
1) Ramo de OPERADOR (=, !=, >, >=, <, <=, in, not null): compara o resultado de value com conditionValue (ou com a lista conditionArray, no "="). Só é testado quando value resolve para algo não vazio — com value vazio, nenhum ramo de operador casa. "in" verifica se o texto de value CONTÉM o texto de conditionValue (trecho de texto, não pertinência a lista). >, >=, <, <= convertem conditionValue para número: vírgula decimal ("10,5") não é número e o ramo não casa.
2) Ramo de EXPRESSÃO (conditionOperator "expression"): conditionValue guarda uma expressão lógica completa, escrita SEM chaves e com as variáveis citadas pelo nome, ex.: pedido_valor > 100 && cidade == "SP". É avaliada SEMPRE, sem depender de value — que pode ficar vazio ("") quando todos os ramos forem de expressão. Aceita a mesma sintaxe das expressões {{...}}: && || !, == != > >= < <=, + - * / %, ternário, parênteses, prefixo global. e filtros (ex.: (chat_client_name | toLowerCase) == "maria"). Use conditionArray: [].
O ramo de expressão casa quando o resultado é VERDADEIRO no sentido do JavaScript: false, 0, "" (texto vazio), null e variável inexistente são falsos; qualquer texto não vazio é verdadeiro — inclusive "0" e "false".
ARMADILHAS da expressão: variáveis costumam chegar como TEXTO — para comparar ou somar números com segurança converta com x * 1 ou +x (ex.: pedido_valor * 1 > 100); não existe Number(), parseInt() nem chamada de método (x.toString()): valem sempre vazio. Vírgula decimal ("10,5") não é número. Variável inexistente não é igual a "" (x == "" dá falso); para "vazia ou inexistente" use !x. Não use atribuição (= isolado; para comparar use ==), ponto e vírgula, nem {{ }} dentro da expressão.
Expressão inválida (sintaxe, atribuição, filtro inexistente) é recusada na validação dos elementos. Se a avaliação falhar durante a execução, o ramo vale como falso, o fluxo segue para o ramo seguinte e o passo fica marcado como erro na depuração.

loop

Laço de repetição declarado — o jeito certo de repetir um trecho do fluxo (em vez de ligar a saída de um elemento de volta a um elemento anterior). Tem DUAS saídas: bodyNextElementId (porta "body": o primeiro elemento do CORPO, o trecho que se repete) e nextElementId (saída "concluído", seguida quando o laço termina).

COMO MONTAR: ligue bodyNextElementId ao primeiro elemento do corpo e ligue a saída do ÚLTIMO elemento do corpo de volta a ESTE laço — é essa volta que inicia a próxima repetição. Um caminho do corpo que não volte ao laço sai dele. Pelo MCP: automations_connect_element com edge "body" (corpo) e edge "default" (saída "concluído").
MODOS: forEach — uma volta por item de list, uma expressão entre chaves que resulta numa lista, ex.: "{{chat_opportunities_list}}" (o texto JSON de uma lista também é aceito). repeat — count voltas: um número inteiro >= 0 ou uma expressão entre chaves, ex.: "3" ou "{{quantidade}}".
A cada volta, a variável itemVar (padrão loop_item) recebe o item atual (forEach) ou o número da volta começando em 1 (repeat), e indexVar (padrão loop_index) recebe a posição começando em 0. Use-as no corpo, ex.: {{loop_item.opportunity_title}}. Em laços dentro de laços, use nomes diferentes em cada um. Lista vazia ou contagem 0: nenhuma volta, segue direto pela saída "concluído".
TETO POR LAÇO: maxIterations (padrão 100, máximo 1000). Lista ou contagem acima do teto: o laço NÃO executa nenhuma volta (não processa só uma parte) e segue pela saída "concluído" com erro. Para percorrer a lista do elemento queueChats, use maxIterations >= o limit dele.
TETO POR TURNO: vale para toda execução, dentro ou fora de laço — por padrão, numa automação, 1.000 elementos, 100 mensagens enviadas, 100 requisições e 10 minutos de execução ativa entre duas esperas pelo cliente (numa URA, 5.000 / 500 / 500 / 24 horas). Estourado, a execução é interrompida (erro na depuração) e a automação é marcada como possível laço.
ERRO: a variável <itemVar>_error (ex.: loop_item_error) fica vazia quando o laço começa normalmente e recebe o motivo quando ele não pôde começar — lista inválida, contagem inválida, acima do teto ou corpo não conectado; nesse caso nenhuma volta roda e o fluxo segue pela saída "concluído".
Os elementos do trecho repetido (os que voltam ao laço) não sofrem a espera progressiva por repetição enquanto o laço está ativo; um caminho que sai do meio do corpo volta a sofrê-la. Elementos de interação (pergunta, opções) funcionam no corpo de uma URA: a volta continua depois da resposta do cliente.
execAutomation NO CORPO: cada volta é uma nova partida da sub-automação e conta no limite de 50 partidas da mesma automação por atendimento a cada 2 minutos — a partir da 51ª ela não é executada e é marcada como possível laço; cada partida também grava uma mensagem de sistema no atendimento. Para muitos itens, faça o trabalho no próprio corpo.
Não use o campo options neste elemento.

businesshoursCheck

Verifica se o momento atual está dentro do horário de funcionamento de uma configuração de horários cadastrada no sistema (considerando horário semanal, feriados e datas especiais).

É um elemento de ramificação com dois caminhos: se estiver dentro do horário (aberto), o fluxo segue para nextElementId; se estiver fora do horário (fechado), o fluxo segue para closedNextElementId.
As seguintes variáveis são criadas automaticamente:
bh_is_open: true se está dentro do horário de funcionamento, false caso contrário.
bh_reason: motivo do resultado. Valores possíveis: "weekly" (horário semanal), "special_date" (data especial), "holiday" (feriado), "holiday_no_config" (feriado sem configuração específica), "day_closed" (dia fechado), "config_inactive" (configuração inativa) e "config_not_found" (configuração não encontrada).
bh_reason_label: descrição amigável do motivo.
bh_message: mensagem configurada para o período, se houver.
bh_description: descrição do período, exemplo: nome do feriado ou da data especial.
bh_close_time: horário de fechamento do período atual no formato "HH:MM", quando aberto.
bh_minutes_to_close: minutos restantes até o fechamento, quando aberto. Se o funcionamento for 24h sem interrupção prevista, o valor é -1.
bh_minutes_to_open: minutos até a próxima abertura, quando fechado.
bh_opens_within_24h: 1 se a próxima abertura ocorre em até 24 horas, 0 caso contrário.
bh_next_open_date: data/hora da próxima abertura.
bh_message_formatted: mensagem configurada com as variáveis de horário já substituídas.
Se o configId for inválido ou a configuração não for encontrada, bh_is_open recebe false, bh_reason recebe "config_not_found" e o fluxo segue para closedNextElementId.

transfer

Transfere o atendimento associado, quando este existir. O elemento transfer não possui um próximo elemento, pois ele encerra o fluxo de execução — exceto com chatId de OUTRO atendimento (ver abaixo).

A transferência acontece sempre dentro da fila do atendimento: para colocar um cliente em outra fila, abra um atendimento lá com openChat/openChatCloud (queueId).
OUTRO ATENDIMENTO (chatId, opcional): com o ID de outro atendimento aberto (por exemplo o aberto por openChat/openChatCloud sem associar, ou um item da lista do queueChats), o elemento transfere ESSE atendimento — destinationType 0 redistribui na fila dele com o filtro calculado pelas variáveis do fluxo, 1 entrega ao atendente (mesmas regras de disponibilidade), 2 inicia nele a URA indicada ou executa sobre ele a automação indicada — e o fluxo NÃO termina: segue por nextElementId, a saída que o elemento ganha só nesse modo (sem ela, o fluxo termina ali). As variáveis do fluxo NÃO são copiadas para o atendimento transferido. Atendimento não encontrado ou encerrado: nada acontece, o motivo fica na depuração e o fluxo segue. Com chatId vazio, ou com o ID do próprio atendimento do fluxo, vale o comportamento acima e nextElementId é ignorado.

Triagem por horário de funcionamento com protocolo e rodízio de plantão

Separar quem chega dentro e fora do horário de funcionamento, registrar o protocolo e a etiqueta do atendimento e encaminhar por dia e hora (domingo, plantão noturno ou fila normal).

  1. businesshoursCheck — testa o momento atual contra a configuração horario_comercial: dentro do horário segue na queda para a saudação, fora dele cai no bloco closed, que avisa o cliente, registra a informação interna e encerra.
  2. message — cumprimenta o cliente pelo nome quando o atendimento está dentro do horário.
  3. protocol — gera o protocolo automático do atendimento.
  4. marker — aplica a etiqueta de triagem no atendimento.
  5. info — registra na conversa que o cliente chegou fora do horário comercial.
  6. timetable — decide pelo dia e pela hora: domingo inteiro, dias úteis das 18h às 23h59 no plantão e o restante no else.
  7. transfer — encaminha o atendimento para a URA de plantão (destinationType=2) ou para a distribuição normal da fila (destinationType=0).
  8. terminate — encerra o caminho de domingo e o caminho fora do horário, cada um com o seu motivo.
checa_expediente: businesshoursCheck configId="horario_comercial" {
  closed {
    fora_aviso: message text="No momento estamos fora do horário de atendimento. Funcionamos de segunda a sexta, das 8h às 18h."
    fora_registro: info text="Cliente chegou fora do horário comercial. Aviso automático enviado e atendimento encerrado sem agente."
    fora_fim: terminate reason="Fora do horário de atendimento"
  }
}
saudacao: message text="Olá, {{chat_client_name}}! Estamos em horário de atendimento e você já vai ser atendido."
cria_protocolo: protocol type=0
etiqueta_triagem: marker markerId="etiqueta-triagem"
avisa_protocolo: message text="Seu atendimento está registrado no protocolo {{chat_protocol}}."
rodizio_plantao: timetable {
  case domingo type=0 weekDayBegin=0 weekDayEnd=0 hourBegin=0 minuteBegin=0 hourEnd=23 minuteEnd=59 {
    aviso_domingo: message text="Aos domingos atendemos apenas por mensagem, sem atendente de plantão."
    protocolo_domingo: protocol type=0
    fim_domingo: terminate reason="Atendimento de domingo"
  }
  case plantao_noturno type=0 weekDayBegin=1 weekDayEnd=5 hourBegin=18 minuteBegin=0 hourEnd=23 minuteEnd=59 {
    vai_plantao: transfer destinationType=2 destinationId="ura-plantao"
  }
  else {
    distribui_fila: transfer destinationType=0
  }
}
Resultado: Quem escreve dentro do horário ganha protocolo e etiqueta e vai para a fila ou para o plantão conforme o dia e a hora; quem escreve fora do horário recebe o aviso e o atendimento é encerrado com o motivo registrado.

Resumo do carrinho item a item com laço de repetição

Percorrer as linhas do carrinho sincronizado com um laço, enviando uma mensagem por item com uma pequena pausa entre elas, e fechar com o total.

  1. newVar — cria a variável resumo_carrinho já vazia, para ser preenchida mais adiante no fluxo.
  2. varCondition — compara a quantidade de itens do carrinho com 1: o ramo carrinho_vazio avisa e encerra, o else segue com o resumo.
  3. jscode — monta o texto de abertura do resumo com a contagem de itens do carrinho.
  4. loop — percorre a lista do carrinho: a cada volta, o item cai em item e a posição em posicao; o corpo devolve o fluxo ao laço e a volta seguinte começa.
  5. message — mostra a linha do item atual (posição, produto, quantidade e valor) e depois o total do carrinho.
  6. sleep — espera um segundo entre uma linha e outra do carrinho, para as mensagens não chegarem todas de uma vez.
  7. terminate — encerra o atendimento depois do resumo (ou avisa o carrinho vazio).
comeca_resumo: newVar variableName="resumo_carrinho" value=""
confere_carrinho: varCondition value="{{chat_cart_items_count}}" {
  case carrinho_vazio conditionOperator="<" conditionValue="1" {
    sem_itens: message text="Seu carrinho está vazio no momento, {{chat_client_name}}. Quer ver as novidades da loja?"
    fim_sem_itens: terminate reason="Carrinho vazio"
  }
  else {
    cabecalho: message text="Confira o que já está no seu carrinho:"
    prepara_titulo: jscode code="vars[\"resumo_carrinho\"] = \"Carrinho com \" + vars[\"chat_cart_items_count\"] + \" itens\""
    laco_itens: loop mode="forEach" list="{{chat_cart_lines}}" itemVar="item" indexVar="posicao" {
      body {
        mostra_item: message text="{{posicao}}. {{item.product_name}} - quantidade {{item.product_quantity}} - valor unitário {{item.product_value}}"
        pausa_envio: sleep time=1 -> laco_itens
      }
    }
    mostra_total: message text="{{resumo_carrinho}}. Total: {{chat_cart_total}}."
    fim_com_itens: terminate reason="Resumo do carrinho enviado"
  }
}
Resultado: O cliente recebe uma lista organizada, com um item por mensagem e o total no fim; com o carrinho vazio, recebe o aviso e o atendimento encerra.

Orçamento com acompanhamento agendado e cancelamento

Perguntar quando o cliente quer receber o orçamento, agendar a execução de uma automação de retorno e cancelar esse agendamento se o cliente responder antes.

  1. options — pergunta se o cliente quer o orçamento agora ou amanhã e tenta de novo (duas vezes) quando não entende a resposta.
  2. message — confirma a escolha do cliente e explica o que vai acontecer em cada caminho.
  3. scheduleAutomation — agenda a automação de orçamento para 10 minutos depois (ou a de acompanhamento para 24 horas) e guarda o id do agendamento em uma variável.
  4. waitMessage — para o fluxo até o cliente enviar uma nova mensagem.
  5. cancelSchedule — cancela o agendamento pendente pelo id guardado, porque o cliente respondeu antes.
  6. info — registra no atendimento o id do agendamento criado.
  7. sleep — dá uma pequena pausa antes de encerrar o caminho do amanhã, para o cliente ler a confirmação.
  8. varCondition — no caminho sem escolha, verifica se a fila do atendimento comercial cuida do assunto (operador in) para encaminhar via transfer; senão encerra.
  9. transfer — encaminha para a distribuição normal da fila no caminho de fallback.
  10. terminate — encerra os caminhos do agora, do amanhã e da falta de escolha.
pergunta_quando: options text="Posso te mandar o orçamento agora ou prefere que eu retome amanhã?" type=0 errorRetryCount=2 errorRetryMessage="Não entendi. Toque em uma das opções acima, por favor." {
  case agora text="Quero agora" {
    manda_agora: message text="Perfeito! Estou montando o orçamento e te envio por aqui em instantes."
    agenda_retorno: scheduleAutomation automationId="automacao-orcamento" delaySeconds="600" resultVariableName="agendamento_orcamento"
    aguarda_cliente: waitMessage
    cancela_retorno: cancelSchedule scheduleId="{{agendamento_orcamento}}"
    cliente_respondeu: message text="Recebi sua mensagem, {{chat_client_name}}! O acompanhamento automático foi cancelado e eu sigo com você por aqui."
    fim_agora: terminate reason="Cliente respondeu antes do retorno programado"
  }
  case amanha text="Prefiro amanhã" {
    combinado: message text="Combinado! Vou retomar este assunto amanhã pela manhã por aqui mesmo."
    agenda_manha: scheduleAutomation automationId="automacao-followup" delaySeconds="86400" resultVariableName="agendamento_followup"
    registro_agenda: info text="Retorno agendado para daqui a 24 horas. Id do agendamento: {{agendamento_followup}}."
    respira: sleep time=2
    fim_amanha: terminate reason="Retorno agendado pelo cliente"
  }
  else {
    sem_escolha: varCondition value="{{chat_fila}}" {
      case fila_comercial conditionOperator="in" conditionValue="Comercial" {
        encaminha_fila: transfer destinationType=0
      }
      else {
        sem_encaminhamento: message text="Vou encerrar por aqui, mas você pode escrever de novo a qualquer momento."
        fim_sem_escolha: terminate reason="Cliente não escolheu uma opção"
      }
    }
  }
}
Resultado: O cliente escolhe quando quer o orçamento; ou o retorno automático fica agendado, ou é cancelado porque ele respondeu antes, e o atendimento encerra com o motivo certo.

Classificar o cliente com código, variáveis e gatilhos

Descobrir no início do atendimento se o cliente já é cadastrado, gravar a fila de destino em uma variável e usar gatilhos para que a automação pare de se repetir em quem já foi classificado.

  1. jscode — roda um trecho de JavaScript que olha o documento do contato e grava cadastrado ou novo na variável tipo_cliente.
  2. newVar — grava o nome da fila de destino na variável fila_destino, escolhendo entre Clientes e Novos atendimentos.
  3. marker — etiqueta o atendimento para a triagem visual na fila.
  4. protocol — gera o protocolo automático do atendimento antes de qualquer desvio.
  5. message — informa o protocolo ao cliente.
  6. varCondition — usa um ramo de operador (=) para o cliente cadastrado e um ramo de expressão (!contact_document) para o cliente novo, deixando o else para os casos que não casarem.
  7. removeTrigger — no caminho do cadastrado, remove o gatilho que provocou a execução, para a automação não se repetir na mesma mensagem.
  8. setTriggers — aplica o conjunto de gatilhos do atendimento já classificado.
  9. removeAllTriggers — no caminho do cliente novo, limpa todos os gatilhos do atendimento antes de encaminhar.
  10. execAutomation — dispara a automação que sincroniza os dados do cliente no CRM antes do encaminhamento.
  11. transfer — encaminha para a fila de clientes (distribuição normal) ou para a URA de cadastro (destinationType=2).
  12. terminate — encerra o caminho de quem não entrou em nenhuma classificação.
identifica_tipo: jscode code="vars[\"tipo_cliente\"] = vars[\"contact_document\"] ? \"cadastrado\" : \"novo\""
define_fila: newVar variableName="fila_destino" value="{{tipo_cliente == \"cadastrado\" ? \"Clientes\" : \"Novos atendimentos\"}}"
etiqueta_cadastro: marker markerId="etiqueta-triagem"
cria_protocolo: protocol type=0
avisa_protocolo: message text="Atendimento registrado no protocolo {{chat_protocol}}."
decide_caminho: varCondition value="{{tipo_cliente}}" {
  case cadastrado conditionOperator="=" conditionValue="cadastrado" {
    tira_gatilho: removeTrigger
    aplica_gatilhos: setTriggers triggerSetId=0
    sincroniza_crm: execAutomation automationId="automacao-crm"
    avisa_fila: message text="Cadastro localizado. Vou te encaminhar para a fila {{fila_destino}}."
    encaminha_cadastrado: transfer destinationType=0
  }
  case novo_contato conditionOperator="expression" conditionValue="!contact_document" {
    limpa_gatilhos: removeAllTriggers
    acolhe_novo: message text="Não encontrei seu cadastro por aqui. Vou te encaminhar para o time de novos clientes para agilizarmos."
    encaminha_novo: transfer destinationType=2 destinationId="ura-cadastro"
  }
  else {
    sem_classificacao: message text="Vou encaminhar seu atendimento para a equipe responsável."
    fim_sem_classificacao: terminate reason="Sem classificação automática"
  }
}
Resultado: O cliente cadastrado cai na fila certa com a etiqueta e o protocolo e sem a automação repetindo o trabalho; o cliente novo vai para a URA de cadastro; o resto é encerrado com o motivo registrado.

Retorno por ligação: oferta, confirmação e desfecho da chamada

Oferecer um retorno por telefone num fluxo por mensagem e tratar o que acontece depois da chamada (que é disparada pelo elemento de discagem e devolve o desfecho numa automação de fim de ligação).

  1. startCall — é o elemento de voz que disca para o telefone do atendimento; o exemplo usa o pedido por mensagem e, na automação de voz, o startCall aponta no campo endAutomationId a automação de fim de ligação que trata o desfecho (atendeu, não atendeu, ocupado) — aqui ele é citado como o passo que faz a ponte entre a conversa e a chamada.
  2. message — oferece o retorno por telefone antes de pedir qualquer dado.
  3. question — pergunta se o cliente quer receber a ligação e guarda o SIM ou NAO na variável quer_ligacao.
  4. varCondition — compara a resposta em maiúsculas (filtro toUpperCase) procurando o texto SIM no ramo decide_retorno.
  5. info — registra internamente que o cliente aceitou o retorno por telefone.
  6. sleep — espera dois segundos antes de seguir, para o cliente ler a confirmação.
  7. waitMessage — para o fluxo até o cliente escrever de novo, o que acontece quando a ligação termina.
  8. terminate — encerra o atendimento nos dois caminhos, com o motivo da escolha do cliente.
oferece_ligacao: message text="Se preferir, eu peço para te ligarmos e resolvemos por telefone."
confirma_ligacao: question varName="quer_ligacao" text="Responda SIM para receber a ligação ou NAO para continuar por mensagem."
decide_retorno: varCondition value="{{quer_ligacao | toUpperCase}}" {
  case aceita conditionOperator="in" conditionValue="SIM" {
    confirma_retorno: message text="Combinado! Registrei o pedido de ligação para o número {{chat_client_number}}."
    registra_pedido: info text="Cliente aceitou o retorno por telefone. O pedido fica registrado para a discagem pela automação de voz."
    pausa: sleep time=2
    aguarda_cliente: waitMessage
    apos_ligacao: message text="Se a ligação não completou, escreva aqui que eu sigo com você por mensagem."
    fim_retorno: terminate reason="Retorno por telefone solicitado"
  }
  else {
    continua_chat: message text="Sem problema! Seguimos por aqui. Escreva o que você precisa que eu te ajudo."
    fim_chat: terminate reason="Cliente preferiu continuar por mensagem"
  }
}
Resultado: O cliente que aceita recebe a confirmação e tem o pedido de ligação registrado; quem prefere continuar escrevendo segue no chat. Nos dois casos o atendimento encerra com o motivo registrado.
