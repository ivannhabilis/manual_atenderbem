WhatsApp Business API e WAMD

Alteração de Nome de Exibição na API Oficial

P: Como alterar o nome de exibição de um número na API Oficial do WhatsApp?

R: Após alterar o nome no WhatsApp Manager, é necessário emitir um novo registro. Atualmente não há um botão para essa ação na interface, mas será implementado em versões futuras. Enquanto isso, o processo requer suporte técnico para atualização manual.

Instabilidades e Banimentos

P: Quais são as causas comuns de instabilidade em conexões não oficiais (WAMD)?

R: As instabilidades estão frequentemente associadas a:

  • Uso de grupos, canais ou comunidades pelo número conectado.
  • Conexões via dispositivos iPhone.
  • Falta de garantia de estabilidade em filas não oficiais, que operam em "melhor esforço" devido à engenharia reversa.

P: Quais são as diferenças entre banimento de número e desativação de conta?

  • Banimento de número: afeta apenas o número específico, geralmente por violações de políticas (ex.: produtos proibidos ou alta taxa de bloqueios).
  • Desativação de conta: invalida todos os números vinculados, ocorrendo quando a Meta não consegue verificar a legitimidade da empresa ou identifica violações graves.

P: Como reduzir riscos de banimento na API Oficial?

  • Verifique a empresa no Meta Business Manager.
  • Mantenha um site corporativo com CNPJ, endereço, política de privacidade e descrição clara do negócio.
  • Evite operar em setores regulados (saúde, armas etc.) sem registros nos órgãos competentes (Anvisa, conselhos profissionais).

Migração para API Oficial

P: Por que os clientes devem migrar para a API Oficial, apesar do custo?

R: A Meta está descontinuando o suporte para conexões não oficiais. Benefícios da API Oficial:

  • Estabilidade superior e funcionalidades exclusivas (ex.: mensagens passivas gratuitas).
  • Redução de riscos de banimento e alinhamento com as políticas da Meta.

P: Quais são as opções de fila na API Oficial?

  1. WA Cloud API (Dev App): conexão tradicional, com maior compatibilidade.
  2. WA Cloud API (Tech Provider): oferece "Coexistence" (uso simultâneo do app Business no celular), mas com limitações em mensagens de dispositivos antigos.

Mensagens não suportadas na Coexistence

P: Por que algumas mensagens aparecem como "conteúdo não suportado"?

R: É uma limitação da Meta em conexões Coexistence, especialmente para mensagens de:

  • Dispositivos antigos (WhatsApp Windows em versões desatualizadas).
  • Wear OS ou aplicativos não oficiais.

Solução: opte pela API convencional (sem Coexistence) para máxima compatibilidade.

Quem configura a Cloud API do WhatsApp e quais são os pré-requisitos para conectar?

Resumo

A conexão da Cloud API (WhatsApp oficial) é feita pelo próprio sistema, direto na tela da fila — não é preciso nenhuma ferramenta externa. Antes de conectar, você precisa ter um Business Manager ativo na Meta, um número que não esteja em uso em outro WhatsApp Business App ou Cloud API, e uma forma de pagamento cadastrada na conta.

Quando se aplica

  • Você vai ativar um número de WhatsApp como fila oficial (Cloud API) pela primeira vez.
  • Você não sabe se precisa contratar ou configurar algo fora do sistema para isso.
  • A conexão falha ou não conclui e você quer saber o que verificar antes de tentar de novo.

Passo a passo

  1. Garanta os pré-requisitos na Meta. Tenha um Business Manager (Gerenciador de Negócios) ativo, com uma forma de pagamento válida cadastrada nele.
  2. Confirme que o número está livre. O número de telefone não pode estar conectado, no momento, a outro WhatsApp Business App ou a uma Cloud API de outra plataforma. Conectá-lo aqui deriva automaticamente a conexão ativa que ele tinha em outro lugar.
  3. Crie ou abra a fila. Em Configurações > Filas, clique em Adicionar (ou abra uma fila já existente) e defina o tipo como WA Cloud API.
  4. Abra a aba Conexão. Na fila, acesse a aba Conexão e localize a seção Autenticação.
  5. Conecte pelo Facebook. Clique em Entrar com o Facebook e siga o fluxo de login e seleção da conta/página que a Meta apresenta. É esse fluxo que vincula o número à fila — o sistema não pede nenhum dado técnico manual nessa etapa.
  6. Cadastre a forma de pagamento, se ainda não tiver. Se a Meta não tiver um método de pagamento cadastrado, acesse o WhatsApp Manager (Visão geral), clique em Adicionar método de pagamento e conclua o fluxo — sem isso a Cloud API não ativa.

Pontos de atenção

  • Não existe ferramenta externa. Toda a conexão (login, seleção de número, vínculo à fila) acontece dentro do próprio sistema, pelo botão Entrar com o Facebook.
  • Número já em uso em outra plataforma. Conectar um número que já está ativo em outro WhatsApp Business App ou Cloud API não é bloqueado pelo sistema, mas derruba a conexão anterior automaticamente — confirme com o cliente final antes de prosseguir para não interromper um canal que ele já usa em outro lugar.
  • Sem forma de pagamento, a API não ativa. Esse é um requisito da própria Meta, não do sistema; o cadastro é feito no WhatsApp Manager, fora da tela de conexão.
  • A conexão em modo Coexistence (QR Code + API ao mesmo tempo) segue outro fluxo, iniciado pelo mesmo botão mas com leitura de QR Code — se o objetivo é a Cloud API "pura", confira se essa opção não foi selecionada sem querer.

Se não resolver

Se o login pelo Facebook não conclui ou a fila não fica ativa mesmo após o fluxo completo, reúna: se o Business Manager tem forma de pagamento cadastrada, se o número já estava vinculado a outro WhatsApp/plataforma, e a mensagem de erro exata exibida (se houver) antes de acionar o suporte.

Como sincronizar os templates do WhatsApp Cloud API com a Meta e o que significa cada status?

Resumo

Na tela "Templates WA Cloud API", o botão "Atualizar online" sincroniza com a Meta, em paralelo, os templates de todas as filas de WhatsApp Cloud API elegíveis (habilitadas e com API key e WABA configurados), trazendo o status de aprovação atualizado de cada um. Só templates criados pela opção "Cloud API" (importados/publicados na Meta) recebem esse status; os cadastrados manualmente pela opção "Outros" sempre aparecem como "Desconhecido", porque não passam por aprovação da Meta.

Quando se aplica

  • Você aprovou ou editou um template diretamente no gerenciador da Meta e quer trazer o status atualizado para o sistema.
  • Você não entende o que significa cada status de um template na lista (Aprovado, Rejeitado, Pendente, etc.).
  • Você quer entender a diferença entre cadastrar um template pela opção "Cloud API" e pela opção "Outros".
  • Você precisa saber os limites de caracteres ao criar um template pela tela do sistema.

Passo a passo

  1. Abra a tela de templates. Vá em Configurações > Cadastros > Templates WA Cloud API.
  2. Sincronize com a Meta. Clique em "Atualizar online". A sincronização roda para todas as filas WhatsApp Cloud API elegíveis ao mesmo tempo (habilitadas e com API key e WABA configurados) e atualiza o status de cada template importado.
  3. Confira o status de cada template na coluna de status da lista.
  4. Para criar um novo template direto na Meta, use "Adicionar > Cloud API": escolha a fila, a categoria (Marketing, Utilidade ou Autenticação), preencha nome, idioma, corpo do template, rodapé e botões, e publique.
  5. Para cadastrar um template manualmente (sem publicar na Meta), use "Adicionar > Outros"; esse template não recebe status de aprovação e aparece sempre como "Desconhecido".

  • Ao criar um template pela opção "Cloud API": nome do modelo aceita até 512 caracteres, corpo do template aceita até 1.024 caracteres, e o rodapé (opcional) aceita até 60 caracteres — todos com contador de caracteres na própria tela.
  • A categoria do template só pode ser Marketing, Utilidade ou Autenticação.
  • Só entram na sincronização automática ("Atualizar online") as filas de WhatsApp Cloud API habilitadas que já têm API key e WABA configurados; filas sem essa configuração não são sincronizadas.
  • A tela "Templates WA Cloud API" fica disponível para o Administrador, ou para usuários com a permissão de editar galeria habilitada em seu cadastro.

Pontos de atenção

  • Um template cadastrado como "Outros" nunca vai mostrar Aprovado/Rejeitado/Pendente — o status "Desconhecido" é esperado e não indica erro.
  • Editar um template diretamente no gerenciador da Meta não atualiza o sistema sozinho: é preciso clicar em "Atualizar online" para trazer a mudança.
  • Um template com status diferente de "Aprovado" pode não estar disponível para uso em campanhas ou no atendimento, dependendo da fila.
  • Os limites de caracteres da opção "Cloud API" (nome, corpo, rodapé) seguem as regras da própria Meta para templates de WhatsApp — preencher acima do limite não é possível pela tela.

Se não resolver

Se um template aprovado na Meta continuar sem aparecer ou sem atualizar mesmo depois de "Atualizar online", veja o artigo "Por que templates aprovados na Meta não aparecem ou não sincronizam no sistema?". Antes de acionar o suporte, reúna: o nome do template, a fila WhatsApp Cloud API associada, o status atual mostrado na lista e se a fila tem API key e WABA configurados.

Por que templates aprovados na Meta não aparecem ou não sincronizam no sistema?

Resumo

Antes de tudo, use o botão Atualizar online na tela de Templates WA Cloud API: ele busca os dados mais recentes direto na Meta e cadastra automaticamente os templates que ainda não existem no sistema. Se, mesmo assim, o template aprovado continuar sem aparecer ou sem atualizar, o cenário mais comum é uma instabilidade do lado da integração da Habilis com a Meta, sem relação com erro de configuração da sua conta e sem prazo definido de normalização.

Quando se aplica

  • Você criou ou aprovou um template direto no Gerenciador de Negócios da Meta e ele não aparece na lista de templates do sistema.
  • Um template já cadastrado foi editado na Meta e a alteração não é refletida no sistema.
  • Um template que já aparecia na lista sumiu sem você ter excluído nada.

Passo a passo

  1. Force a atualização. Acesse Configurações > Templates WA Cloud API e clique em Atualizar online. Essa ação atualiza os templates existentes com base nos dados cadastrados na Meta e cadastra automaticamente os que ainda não constam no sistema. Está disponível apenas para filas WA Cloud API, Dialog 360 (Cloud API) e WA Smarte.
  2. Aguarde a confirmação. O sistema exibe uma mensagem de sucesso e recarrega a lista de templates.
  3. Se não resolver, reaplique a configuração da instância. Se você tiver acesso ao Painel de Instâncias (parceiro/administrador), use as opções Reaplicar configuração e Reiniciar serviço (ou Reiniciar container) na instância afetada.
  4. Se persistir, é provável instabilidade externa. Esse tipo de falha costuma ser intermitente — às vezes o template sobe, às vezes trava de novo — e depende da própria integração com a Meta normalizar, sem uma data garantida.

Pontos de atenção

  • O botão Atualizar online só aparece e funciona em filas WA Cloud API, Dialog 360 (Cloud API) e WA Smarte — não existe em filas WAMD (não oficiais).
  • Esse tipo de instabilidade, quando confirmada como externa, também já afetou em paralelo outras ações ligadas à integração com a Meta (como ativação de novas filas oficiais e sincronização de filas de Facebook/Instagram), sem impactar o envio e recebimento geral de mensagens.
  • Um template recém-aprovado pode levar algum tempo para ficar plenamente disponível para envio — isso é normal enquanto a Meta conclui a validação, e não deve ser confundido com falha de sincronização.
  • Trocar o navegador usado para acessar o painel (por exemplo, para o Edge) já resolveu sintomas parecidos em casos pontuais ligados a cache do navegador — vale testar, mas não é garantia.

Se não resolver

Acione o suporte informando o nome do template, se ele está pendente/aprovado/ausente na Meta e no sistema, o horário em que tentou o Atualizar online, e se o sintoma afeta um template específico ou vários ao mesmo tempo — isso ajuda a diferenciar um caso pontual de uma instabilidade mais ampla.

Por que um template do WhatsApp já aprovado na Meta falha ao enviar?

Resumo

Um template aprovado na Meta pode falhar no envio por motivos que acontecem do lado da Meta, não no cadastro dentro do sistema. As causas mais observadas em suporte são: a Meta adicionar automaticamente um botão de chamada ao template durante a aprovação (erro do tipo "Calling API not enabled"); o template usar emoji no texto do cabeçalho, que a Meta pode rejeitar; ou a fila estar conectada a uma Conta Comercial do WhatsApp (WABA/portfólio) diferente daquela onde o template foi aprovado, fazendo o sistema não encontrar o template para enviar.

Quando se aplica

  • O template está com status "Aprovado" na Meta, mas o envio individual ou em massa falha ou retorna erro.
  • Você não consegue localizar/selecionar, na tela do sistema, um template que já está aprovado na Meta.
  • Um disparo em massa com um template falha, mesmo quando outro disparo com o mesmo template funcionou antes.

Passo a passo

  1. Confira se a Meta adicionou um botão de chamada. Abra o template no Gerenciador de Negócios da Meta e veja se, na área de botões, existe algo como "Can {nome do negócio} call you?" (botão de chamada/consentimento). Esse botão só funciona quando o número tem a função de chamadas por API ativada; na maioria dos casos não tem, e o envio falha.
  2. Remova o botão de chamada. Edite o template na Meta e remova esse botão nas configurações de botões. Se não for possível editar, crie um novo template idêntico com os botões marcados como "Nenhum" e aguarde a nova aprovação.
  3. Revise o cabeçalho por emojis. Se o template tiver emoji no texto do cabeçalho (título), remova-o e teste o envio novamente — a Meta pode rejeitar templates com emoji em determinados campos, tanto em envio individual quanto em disparo em massa.
  4. Se o template simplesmente não aparece para seleção, primeiro use o botão Atualizar online na tela de Templates WA Cloud API — veja o artigo "Por que templates aprovados na Meta não aparecem ou não sincronizam no sistema?" para esse cenário específico.
  5. Se mesmo assim o template não aparece, confira o portfólio conectado. Verifique em qual Conta Comercial (WABA/portfólio) da Meta o template foi criado e aprovado, e compare com a conta que está conectada na fila do sistema.
  6. Reconecte a fila ao portfólio correto. Em Configurações > Filas, refaça a conexão da fila com o WhatsApp Cloud API e, no fluxo de conexão da Meta, selecione explicitamente a mesma Conta Comercial onde o template está aprovado — o sistema usa a conta escolhida nesse fluxo de conexão, ele não escolhe sozinho qual portfólio vincular.
  7. Depois de reconectar, sincronize os templates. Na tela de templates, use Atualizar online para trazer os templates aprovados daquele portfólio para o sistema.

Pontos de atenção

  • Botão de chamada, emoji e portfólio incorreto são as causas mais observadas no suporte, mas nem toda falha de envio de um template aprovado tem causa óbvia — em alguns casos é preciso investigar caso a caso.
  • Um disparo em massa (campanha) pode falhar mesmo que o mesmo template já tenha funcionado antes: verifique também o volume de disparos e se o número não está sendo sinalizado como possível spam pela Meta.
  • Reconectar a fila ao WhatsApp Cloud API exige acesso de administrador ao Gerenciador de Negócios da Meta para escolher a conta correta durante a conexão.
  • Se a fila conecta normalmente mas o problema parece mais amplo (não só um template), veja também o artigo "Como saber se uma falha de conexão, envio ou template do WhatsApp Cloud API é da Meta?", que traz um diagnóstico mais completo via verificação de saúde do número.

Se não resolver

Se depois de checar botão de chamada, emoji e portfólio o template ainda falhar, reúna o nome exato do template, o print do erro retornado pela Meta e a fila/instância utilizada antes de acionar o suporte.

Por que um template com documento/anexo dá erro 400 ao ser enviado pela API?

Resumo

O endpoint de envio de template pela API não aceita um documento/arquivo diferente a cada chamada: o arquivo enviado no cabeçalho é sempre o mesmo arquivo cadastrado como Mídia padrão do cabeçalho no template. Se o campo data da chamada incluir um objeto de arquivo (ex.: {"file": "...", "filename": "..."}) pensando em substituir esse arquivo, ele acaba sendo interpretado como uma variável de texto comum, o que desalinha a contagem de parâmetros e gera erros como "Format mismatch, expected DOCUMENT, received UNKNOWN" (código Meta 132012) ou a mensagem genérica de parâmetros que não batem com o template.

Quando se aplica

  • Seu template tem cabeçalho do tipo Documento (ou Imagem/Vídeo) e o envio pela API retorna erro 400, enquanto o mesmo template sem cabeçalho de arquivo funciona normalmente.
  • A Meta retorna um erro citando parâmetro/formato do cabeçalho, como "Format mismatch, expected DOCUMENT, received UNKNOWN" (132012) ou "número de parâmetros não corresponde ao template".
  • Você está tentando enviar um documento diferente por chamada da API, e não o arquivo fixo já cadastrado no template.

Passo a passo

  1. Confirme o cabeçalho do template. Em Configurações > Templates WA Cloud API, abra o template usado e confira se o Tipo do cabeçalho está como Documento (ou Imagem/Vídeo) e se há um arquivo salvo em Mídia padrão do cabeçalho. Sem esse arquivo cadastrado, o envio por API sempre falha no cabeçalho.
  2. Monte o array de parâmetros na ordem certa. No campo data da chamada, envie somente as variáveis de texto do corpo (e do cabeçalho de texto, se houver), na mesma ordem e quantidade cadastradas no template. Não inclua um objeto de arquivo no meio dessa lista — o arquivo do cabeçalho de mídia não é passado por esse campo neste endpoint, ele vem do arquivo padrão já cadastrado no template.
  3. Reveja a contagem de variáveis. Se o corpo do template tem, por exemplo, 2 variáveis ({{1}}, {{2}}), o array data precisa ter exatamente 2 itens de texto — nem a mais, nem a menos, e um objeto de arquivo enviado por engano no início do array desloca essa contagem e gera exatamente esse tipo de erro.
  4. Teste com um template de texto simples primeiro. Envie o mesmo payload de variáveis usando um template sem cabeçalho de arquivo para confirmar que a contagem e a ordem dos parâmetros estão corretas antes de reintroduzir o cabeçalho de documento.
  5. Se precisar trocar o documento, edite o template em Configurações > Templates WA Cloud API e substitua o arquivo em Mídia padrão do cabeçalho — esse é o arquivo que será usado em todos os envios seguintes desse template pela API.

Pontos de atenção

  • Esse endpoint de envio por API não suporta um arquivo diferente por envio quando o cabeçalho é de mídia: o documento/imagem/vídeo enviado é sempre o cadastrado no template, não algo definido em cada chamada.
  • O sistema não faz uma checagem prévia do número de parâmetros antes de repassar a chamada para a Meta — o erro de contagem/formato retornado é o erro original da própria Meta.
  • Templates de texto simples, sem cabeçalho de arquivo, não sofrem essa limitação e continuam aceitando envio normalmente pelo mesmo endpoint.
  • A documentação de referência da sua instância, com os campos exatos aceitos pelo endpoint, fica em Configurações > Filas > Documentação da API (botão no canto superior direito da tela).

Se não resolver

Se depois de ajustar a ordem/contagem de parâmetros e confirmar o arquivo cadastrado no cabeçalho o erro persistir, reúna o payload exato enviado (sem dados sensíveis do cliente), a resposta de erro completa da Meta e o nome do template antes de acionar o suporte.

Por que aparece "Erro ao salvar" ao tentar criar um template de WhatsApp?

Resumo

A mensagem "Erro ao salvar" ao criar um template quase sempre indica que falta preencher algum campo obrigatório do formulário — confira principalmente fila, categoria, nome, idioma, corpo com todos os exemplos de variável e, se o cabeçalho for de mídia, o arquivo anexado. A tela de templates do sistema suporta apenas modelos mais simples: formatos elaborados, como carrossel ou templates com múltiplos componentes fora do padrão simples, precisam ser criados diretamente no Gerenciador de Negócios da Meta. A aprovação do template, de qualquer forma, é sempre feita pela Meta, nunca pelo sistema.

Quando se aplica

  • Você recebe "Erro ao salvar" ao tentar cadastrar um novo template.
  • Você preencheu o que parecia necessário e mesmo assim o cadastro falhou.
  • Você quer um formato de template (carrossel, múltiplas imagens etc.) e não encontra a opção na tela de criação do sistema.

Passo a passo

  1. Abra a tela de templates. Acesse Configurações > Templates WA Cloud API.
  2. Inicie a criação. Clique em Adicionar > Cloud API. O assistente abre em duas etapas: "Fila e tipo" e "Editar modelo".
  3. Etapa 1 — Fila e tipo. Selecione a Fila de WhatsApp Cloud API à qual o template pertence e escolha a categoria: Marketing, Utilidade ou Autenticação.
  4. Etapa 2 — Nome, idioma e corpo. Preencha Nome do modelo, Idioma e o Corpo do template. Se o corpo tiver variáveis ({{1}}, {{2}}...), preencha um valor de exemplo para cada uma — sem exemplo o sistema não salva.
  5. Configure o cabeçalho, se for usar. O campo Texto do cabeçalho é opcional de verdade: dá para salvar o template sem preenchê-lo. Mas se você escolher cabeçalho de mídia (imagem, vídeo ou documento), é obrigatório anexar um arquivo em Mídia no cabeçalho — sem ele, o template não salva.
  6. Rodapé e botões (opcionais). O rodapé não pode conter variáveis. Cada botão precisa ter o texto preenchido, e campos como número de telefone, URL ou ID do Flow dependem do tipo de botão escolhido — o sistema aceita no máximo 3 botões.
  7. Salve. O template é enviado para aprovação da Meta com status pendente; a aprovação em si acontece no ambiente da Meta, fora do sistema.

Pontos de atenção

  • "Erro ao salvar" quase sempre é campo obrigatório faltando. Confira fila, categoria, nome, idioma, corpo preenchido com todos os exemplos de variável e — quando o cabeçalho for de mídia — o arquivo anexado.
  • O texto de cabeçalho é mesmo opcional. Templates sem texto no cabeçalho (ou com cabeçalho marcado como "Nenhuma") salvam normalmente; se isso não estiver funcionando na sua instância, é uma exceção pontual, e vale reportar ao suporte com o formato exato do template usado.
  • Formatos elaborados não são suportados na tela do sistema. Carrossel e outros formatos fora do padrão simples precisam ser criados direto no Gerenciador de Negócios da Meta; depois de aprovados lá, eles ficam disponíveis para uso no sistema usando Atualizar online na tela de templates.
  • Uma vez pendente, aguarde a Meta. O tempo de aprovação é definido pela própria Meta, não pelo sistema.

Se não resolver

Se o erro persistir mesmo com todos os campos preenchidos (fila, categoria, nome, idioma, corpo com exemplos e arquivo de cabeçalho quando aplicável), reúna um print da tela com o erro e o passo a passo exato que você seguiu antes de acionar o suporte.

Por que mensagens para números de WhatsApp internacionais não chegam ou dão erro?

Resumo

Falhas ao enviar mensagens para números de WhatsApp internacionais têm duas causas distintas já confirmadas: (1) o número foi sinalizado como spam ou denunciado à Meta — isolado a um contato específico; e (2) o sistema pode recusar como Número inválido alguns formatos de número internacional, especialmente DDIs de três dígitos, mesmo sendo um número real. Identifique qual dos dois cenários é o seu antes de agir.

Quando se aplica

  • O envio para um número internacional específico aparece marcado com um X vermelho, mesmo com o chat aberto e a mensagem aparentemente entregue.
  • Ao tentar abrir um novo atendimento digitando um número internacional (pela tela ou pela API), aparece a mensagem Número inválido e não é possível prosseguir.
  • Outros números internacionais funcionam normalmente — o problema é isolado a um contato ou a um DDI específico.

Passo a passo

  1. Confirme se é um caso isolado. Teste abrir atendimento com outro número internacional. Se os demais funcionam normalmente, o problema está restrito àquele contato ou àquele DDI, e não é uma falha geral do canal.
  2. Se o X vermelho aparece só em um contato. Passe o mouse (ou toque, no celular) sobre o ícone para ver a mensagem exibida. Quando o chat já existe e o histórico mostra a mensagem como enviada, mas o ícone persiste, a causa mais provável é que o número esteja marcado como spam pela Meta ou tenha denunciado o número da fila — isso não é causado por uma configuração do sistema.
  3. Contorne a suspeita de spam. Peça ao contato para salvar o número da fila em sua agenda de celular e, se houver outra fila/número disponível, tente reabrir o atendimento por ela.
  4. Se a mensagem é "Número inválido" ao digitar o número. Confira o DDI e o número completo, sem espaços ou caracteres extras, no padrão código do país + código de área/DDD + número. Números com DDI de três dígitos (por exemplo, 595, do Paraguai) já tiveram relato confirmado de rejeição mesmo digitados corretamente.
  5. Registre o caso se a rejeição persistir. Se o número está correto e mesmo assim é recusado como inválido, acione o suporte informando o DDI, o formato exato digitado e se o teste foi feito pela tela ou pela API.

Pontos de atenção

  • A validação de Número inválido ocorre tanto ao abrir chat pela tela quanto pela API — não é um problema restrito a um único canal de acesso.
  • Números com DDI de três dígitos que começam com o dígito 9 (como o 595 do Paraguai) têm relato confirmado de rejeição indevida; se for o seu caso, é um comportamento já identificado pelo suporte, não um erro de digitação seu.
  • O X vermelho em uma mensagem enviada nem sempre significa falha de entrega — verifique a mensagem exata ao passar o mouse sobre ele antes de concluir que é um problema do sistema.
  • A suspeita de spam ou denúncia à Meta é uma decisão da própria Meta sobre aquele contato específico; nem o suporte nem o sistema conseguem reverter isso diretamente.

Se não resolver

Reúna o protocolo, o número completo com DDI, se o teste foi feito pela tela ou pela API, e uma captura de tela do erro exato (a mensagem do X ou do "Número inválido") antes de acionar o suporte.

WhatsApp não oficial (WAMD e QR Code)

Como conectar e configurar uma fila de WhatsApp não oficial via QR Code e o que cada opção faz?

Resumo

Uma fila de WhatsApp não oficial (conectada por QR Code, nas variantes WAMD, WAMD 2 ou WAMD 3) exibe, na aba "Conexão", indicadores de status e botões para conectar, desconectar, deslogar e ler o QR Code. A tela mostra um aviso pedindo para consultar os termos de uso do serviço de mensageria antes de usar a integração, por se tratar de conexão não oficial.

Quando se aplica

  • Conectar ou reconectar uma fila de WhatsApp não oficial pela leitura do QR Code.
  • Entender o que cada indicador e botão da aba "Conexão" significa.
  • Importar uma sessão do WhatsApp já autenticada, sem ler o QR Code novamente.

Passo a passo

  1. Abra a fila. Vá em Configurações > Filas, clique na fila de WhatsApp não oficial para expandi-la e abra a aba "Conexão".
  2. Habilite o servidor, se ainda não estiver habilitado.
  3. Clique em "Conectar" para iniciar a conexão com o servidor de mensageria.
  4. Clique em "QR Code" para exibir o código e parear com o celular usando o aplicativo de mensageria.
  5. Acompanhe os indicadores de smartphone, conexão (socket) e autenticação até todos indicarem conectado/autenticado.

Limites e regras

  • Indicadores de status na aba "Conexão": ícone de smartphone (conectado/desconectado), ícone de conexão (socket conectado/desconectado) e ícone de cadeado (servidor autenticado/não autenticado).
  • Botão Conectar: fica desabilitado se a fila estiver desabilitada ou já conectada.
  • Botão Desconectar: fica desabilitado se a fila estiver desabilitada ou já desconectada.
  • Botão Deslogar: desconecta e apaga os dados de autenticação salvos, exigindo nova leitura de QR Code na próxima conexão.
  • Botão QR Code: só fica disponível com a fila habilitada, conectada e ainda não autenticada.
  • Botão Importar sessão: só existe na variante WAMD 2. Importa uma sessão do WhatsApp exportada do navegador; só fica disponível com a fila desabilitada. A ação apaga as credenciais atuais e, ao reabilitar a fila, ela reconecta já autenticada com a sessão importada.
  • Campo "Importar histórico": define até quantos dias de mensagens antigas são importados na sincronização inicial da fila, logo após a leitura do QR Code — opções de "Não importar" até 180 dias. Esse campo fica na aba "Configurações", não na aba "Conexão".
  • Em algumas variantes existem ainda dois alternadores próprios de sincronização com o celular: "Importar histórico de mensagens" e "Importar contatos do aparelho". Os dois só funcionam se a conexão foi feita via QR Code em modo Coexistence e o celular está conectado, e precisam estar ativos ANTES da autenticação da fila para valerem — ativá-los depois não importa nada retroativamente. Nenhum dos dois abre atendimentos no sistema para mensagens antigas ainda não lidas.

Pontos de atenção

  • Os botões de conexão (Conectar, Desconectar, Deslogar) variam conforme a variante da fila — nem todas as variantes de WhatsApp não oficial mostram exatamente os mesmos botões.
  • "Importar sessão" derruba a autenticação atual assim que o arquivo é carregado; use apenas quando pretende substituir a sessão em uso.
  • Os campos "Manter conexão online", "Versão do WhatsApp Web" e "User-agent" ficam na aba "Configurações" da fila, não na aba "Conexão" — veja o artigo "Quais opções de comportamento existem na aba Configurações de uma fila e o que cada uma faz?" para o detalhe desses campos.
  • "Enviar eventos de digitação" (indicador de "digitando..." para o cliente) só existe nas variantes de WhatsApp não oficial — não existe na fila de WhatsApp Cloud API oficial.
  • Os botões para converter a fila entre WAMD, WAMD 2, WAMD 3 e Cloud API também ficam na aba "Conexão", ao lado dos controles de autenticação — veja o artigo "Quais botões existem para converter uma fila de WhatsApp entre WAMD, WAMD 2, WAMD 3 e Cloud API?" para os detalhes de cada conversão.
  • Por ser integração não oficial, o funcionamento depende do serviço de mensageria de terceiros e está sujeito aos termos de uso desse serviço.

Se não resolver

Se a fila não sai do estado "desconectado" ou o QR Code não aparece mesmo com o servidor habilitado, confirme se o celular usado no pareamento está com internet ativa e se nenhuma outra sessão está usando o mesmo número. Antes de acionar o suporte, reúna a variante da fila (WAMD, WAMD 2 ou WAMD 3), o estado exato dos três indicadores de status e se a tentativa foi de primeira conexão, reconexão ou importação de sessão.

Por que meu número em fila de WhatsApp não oficial é banido ou tem envios bloqueados pela Meta?

Resumo

Números conectados por QR Code (WAMD, WAMD2 ou WAMD3) correm risco de banimento ou de bloqueio silencioso pela Meta com base no padrão de uso do número — volume, frequência e comportamento de automação —, independentemente das permissões configuradas no sistema. Para reduzir picos de disparo, o sistema aplica por padrão um limite de mensagens por minuto para envios feitos pela API de integração, que não fica visível nem é editável na interface. Não há hoje um indicador na tela avisando quando um número foi restringido pela Meta.

Quando se aplica

  • Você usa uma fila conectada por QR Code (WAMD, WAMD2 ou WAMD3), não a API Oficial (Cloud API).
  • Mensagens deixam de ser entregues sem nenhum aviso de erro visível na tela.
  • Você recebe um erro de limite de requisições ao disparar mensagens pela API de integração.
  • Você quer saber se pode habilitar recursos adicionais, como grupos de WhatsApp, sem aumentar o risco do número.

Passo a passo

  1. Evite picos de envio. Distribua os disparos ao longo do tempo em vez de concentrar um volume grande em poucos minutos — esse é o padrão de comportamento que mais chama atenção das políticas da Meta para números conectados por automação.
  2. Não habilite recursos que fogem do uso esperado de um número comum, como a exibição de grupos de WhatsApp no chat interno, a menos que seja realmente necessário — isso aumenta a chance de banimento.
  3. Se o envio for feito pela API de integração, respeite o retorno de erro de limite de requisições e reduza a frequência das chamadas.
  4. Se você precisa de volume e estabilidade de envio, migre a fila para a API Oficial (Cloud API), que usa templates aprovados pela Meta e não sofre as mesmas restrições comportamentais das conexões não oficiais.

Pontos de atenção

  • O risco de banimento ou bloqueio é inerente ao uso de um número por conexão não oficial — depende do comportamento do número avaliado pela Meta, e não é algo que as permissões do sistema controlem.
  • O bloqueio pode ser silencioso: o número para de enviar sem aviso explícito, e hoje não existe indicador na interface mostrando que um número está restrito pela Meta.
  • Por padrão, o sistema aplica um limite de poucas mensagens por minuto ao envio feito pela API de integração, como proteção contra picos de disparo. Esse limite é definido internamente por instância, não aparece nem pode ser alterado na interface do cliente, e não se aplica ao envio manual feito pelo agente na tela de atendimento.
  • Habilitar grupos de WhatsApp no chat interno aumenta o risco de banimento, mesmo que o número já esteja em uso normal na fila.

Se não resolver

Se um número parar de enviar mensagens sem erro aparente, verifique se não está recebendo erro de limite de requisições da API, se não houve mudança brusca de volume recente e se não está conectado simultaneamente em outro WhatsApp Web ou aplicativo. Reúna o tipo da fila, o horário em que o envio parou e, se houver, a mensagem de erro retornada pela API antes de acionar o suporte — para números efetivamente banidos pela Meta, não há reversão possível dentro do sistema.

Fila de WhatsApp conectada mas não envia mensagens: o que verificar?

Resumo

Quando uma fila de WhatsApp não oficial (WAMD, WAMD2 ou WAMD3) permanece conectada e recebe mensagens normalmente, mas não envia respostas — para todos os contatos ou só para um contato específico — na maioria dos casos é uma instabilidade da própria conexão não oficial, sem uma causa fixa visível na tela. Não existe hoje uma ferramenta de diagnóstico dedicada para esse sintoma nas filas WAMD; siga o checklist abaixo antes de abrir um chamado.

Quando se aplica

  • A fila WAMD, WAMD2 ou WAMD3 mostra status conectado, mas o agente não consegue enviar nem responder mensagens.
  • Mensagens do cliente chegam normalmente, mas as enviadas pelo sistema não saem ou não são confirmadas como entregues.
  • O bloqueio afeta só um contato específico, enquanto outros contatos na mesma fila continuam recebendo mensagens normalmente.

Passo a passo

  1. Confirme o status da fila. Em Configurações > Filas, verifique se a fila realmente aparece conectada e qual variante está em uso (WAMD, WAMD2 ou WAMD3).
  2. Reaplique a configuração e reinicie o serviço. No Painel de Instâncias, use Reaplicar configuração e, em seguida, Reiniciar serviço (ou Reiniciar container) na instância afetada. Esse painel só aparece para usuários com acesso de parceiro/administrador; se você não tiver acesso, peça a quem tiver ou acione o suporte.
  3. Desconecte e reconecte a fila. Na tela de Filas, use Desconectar-se do servidor e, depois, leia o QR Code novamente para reautenticar.
  4. Verifique se o WhatsApp do celular está atualizado. Em conexões via QR Code, uma versão desatualizada do aplicativo no celular pode causar falhas de envio.
  5. Considere trocar de variante. Se o problema persistir, use o botão Converter para WAMD 2 ou Converter para WAMD 3 na tela de Filas — variantes diferentes usam mecanismos de conexão distintos e podem não apresentar a mesma instabilidade. A conversão exige nova leitura do QR Code.

Pontos de atenção

  • Esse tipo de bloqueio de envio silencioso é uma característica conhecida das conexões não oficiais, dependentes de heurísticas da própria Meta — fora do controle direto do sistema.
  • Os passos acima nem sempre resolvem de forma definitiva: em alguns casos o sintoma volta depois de um tempo mesmo após reiniciar e reconectar.
  • Converter o tipo da fila (entre WAMD, WAMD2 e WAMD3) derruba a autenticação atual — combine com a equipe antes de fazer isso em horário de atendimento.
  • Se estabilidade e volume de envio forem essenciais, a alternativa recomendada para eliminar esse tipo de instabilidade é migrar a fila para a API Oficial (Cloud API).

Se não resolver

Se o checklist não resolver, abra um chamado informando: a fila e a instância afetadas, se o bloqueio é geral ou específico a um contato, os passos já testados e, se possível, um print da tentativa de envio mostrando o status da mensagem.

Por que filas desconectam ou param de gerar QR Code após uma atualização do sistema?

Resumo

É comum que, logo após o lançamento de uma nova versão do sistema, filas de WhatsApp fiquem temporariamente desconectadas, não consigam gerar QR Code, ou a instância apareça offline / retorne erro ao tentar reiniciar. Na maioria dos casos isso se resolve reaplicando a configuração e reiniciando a instância pelo Painel de instâncias; às vezes a instância volta sozinha depois de alguns minutos, ainda em função da atualização em andamento no servidor.

Quando se aplica

  • Uma ou mais filas de WhatsApp desconectaram logo após uma atualização do sistema.
  • O botão de Conectar/gerar QR Code na fila não responde.
  • A instância aparece offline no painel ou retorna erro ao tentar reiniciar.
  • Vários clientes relatam o mesmo sintoma ao mesmo tempo, pouco depois de um lançamento.

Passo a passo

  1. Acesse o Painel de instâncias com um usuário que tenha permissão para isso.
  2. Reaplique a configuração da instância afetada.
  3. Reinicie o serviço. Aguarde alguns minutos — durante o rollout de uma atualização, a instância pode demorar um pouco mais que o normal para voltar sozinha.
  4. Se a fila ainda não gerar QR Code, reinicie o container da instância (opção mais forte, usada quando reiniciar o serviço não é suficiente).
  5. Teste a conexão da fila novamente, lendo o QR Code se necessário.

Pontos de atenção

  • Essa ação depende do administrador da instância: o suporte só consegue reaplicar configuração/reiniciar acessando a instância com autorização pontual do cliente. Não existe uma rotina para o suporte aplicar isso remotamente e em massa para todos os clientes afetados por uma mesma atualização — cada instância precisa ser tratada individualmente pelo painel.
  • Se o tempo de instância offline ultrapassar bastante o esperado para uma atualização normal (alguns minutos), é sinal de que o caso já não é o comportamento padrão pós-atualização e vale abrir chamado.
  • Reiniciar o container é mais demorado que reiniciar o serviço e deixa a instância temporariamente indisponível — tente reiniciar o serviço primeiro.
  • Atendimentos abertos há muito tempo sem encerramento também podem gerar inconsistências visuais após atualizações; encerrar chats concluídos ajuda a evitar esse tipo de sintoma.

Se não resolver

Se depois de reaplicar a configuração e reiniciar (serviço e, se preciso, container) a fila continuar sem gerar QR Code ou a instância continuar offline, abra um chamado informando o endereço da instância, o número/tipo da fila afetada, o horário em que o problema começou e se o sintoma coincide com o horário de um lançamento de nova versão.

O que significam os avisos de conexão instável e de fila sem autenticação no cabeçalho?

Resumo

O cabeçalho do sistema mostra ícones fixos e piscantes para avisar sobre problemas de conexão que afetam o uso normal do sistema. O aviso amarelo "Conexão com o servidor instável" indica que a comunicação em tempo real do seu navegador com o servidor está instável. O aviso vermelho de fila sem autenticação indica que uma ou mais filas de mensageria perderam a autenticação e precisam ser reconectadas. Diferente de uma notificação comum, esses avisos ficam fixos no cabeçalho enquanto a condição persistir, e somem sozinhos quando o problema se resolve.

Quando se aplica

  • O usuário vê um ícone piscando no canto superior direito e não sabe o que significa.
  • Mensagens não estão chegando ou saindo em tempo real e há um ícone amarelo aceso no cabeçalho.
  • Uma fila de WhatsApp ou outro canal de mensageria parou de receber mensagens e o cabeçalho mostra um aviso vermelho listando o nome da fila.
  • Este artigo não cobre o aviso azul "conectado em múltiplos dispositivos" — veja o artigo "Por que aparece o aviso de múltiplos dispositivos e como deslogar dos demais?" para esse caso específico.

Passo a passo

  1. Identificar o aviso amarelo "Conexão com o servidor instável". Aparece quando a conexão do navegador com o servidor está instável. Não exige ação: normalmente se resolve sozinho quando a rede normaliza. Se persistir, verifique a conexão de internet do computador ou tente recarregar a página.
  2. Identificar o aviso vermelho de fila sem autenticação. Ao passar o mouse sobre o ícone (ou, no celular, na barra de aviso do topo), o texto lista os nomes das filas afetadas: "Uma ou mais filas perderam a autenticação com o servidor... Filas com problema: (nomes)".
  3. Aguardar a reconexão automática. O próprio texto do aviso orienta aguardar alguns instantes, já que a reautenticação pode ocorrer sozinha.
  4. Reautenticar manualmente se o aviso não sumir. Um Administrador ou Supervisor deve abrir a configuração da fila afetada e reler o QR Code pelo celular (filas de WhatsApp não oficial) ou reintroduzir os dados de autenticação (demais canais), conforme o tipo de conexão da fila.

Limites e regras

  • O aviso de conexão instável e o de fila sem autenticação aparecem para qualquer perfil (Administrador, Supervisor ou Agente) que estiver com a sessão aberta — não dependem de permissão específica para serem exibidos.
  • No layout de celular, o aviso de conexão instável e o de fila sem autenticação aparecem juntos em uma barra própria no topo da tela, com o mesmo texto da versão para computador; só um dos dois é mostrado por vez nessa barra (o de conexão instável tem prioridade sobre o de fila sem autenticação).
  • No computador, os dois avisos podem aparecer lado a lado no cabeçalho ao mesmo tempo, já que cada um tem seu próprio ícone.

Pontos de atenção

  • O aviso de fila sem autenticação é o mais crítico dos dois: enquanto ele estiver ativo, a fila listada não está trocando mensagens com o canal até ser reautenticada.
  • Esses avisos não são notificações que aparecem e somem sozinhas (toast): eles ficam fixos no cabeçalho enquanto a condição persistir, e desaparecem automaticamente assim que o problema é resolvido.
  • Uma instabilidade recorrente e específica de uma fila de Instagram ou Facebook (que volta mesmo depois de reconectar) pode ter causa fora do sistema, do lado da Meta — consulte o artigo de suporte "Por que a fila de Instagram ou Facebook desconecta ou fica instável sozinha?" para esse cenário.

Se não resolver

Se o aviso de conexão instável não sumir depois de recarregar a página e checar a internet local, ou se o aviso de fila sem autenticação continuar mesmo após reler o QR Code ou reconfigurar a autenticação da fila, anote o nome exato da(s) fila(s) listada(s) no aviso, o horário em que o problema começou e se ele afeta um usuário específico ou todos antes de acionar o suporte.

Coexistence e migração de modalidade

O que é o modo Coexistence e por que a fila fica nele ao converter para API Oficial?

Resumo

Uma fila de WhatsApp pode operar em três modos: WAMD (não oficial, conexão por QR Code), API Oficial (Cloud API pura) e Coexistence (API Oficial funcionando ao mesmo tempo com o aplicativo WhatsApp Business no celular, no mesmo número). Ao converter uma fila WAMD para Cloud API, se a janela de autenticação da Meta encontrar o número já ativo no WhatsApp Business App do celular, ela ativa o modo Coexistence automaticamente — mesmo que você não tenha escolhido nada relacionado a isso. Para migrar de fato para API Oficial pura, é preciso apagar a conta do WhatsApp Business App no celular antes de refazer a conexão.

Quando se aplica

  • Você converteu uma fila WAMD para Cloud API e, ao final, a fila ficou marcada como Coexistence (ícone de celular ao lado da fila) em vez de API Oficial pura.
  • Você quer entender a diferença entre WAMD, API Oficial e Coexistence antes de converter uma fila.
  • Você precisa migrar uma fila de Coexistence para API Oficial pura (sem o app no celular).

Passo a passo

  1. Faça backup, se necessário. No celular do cliente, se houver conversas que precisem ser preservadas, oriente a fazer backup pelo próprio WhatsApp Business App antes do próximo passo.
  2. Apague a conta no WhatsApp Business App. No celular do cliente, acesse o aplicativo WhatsApp Business, vá em Configurações > Conta e selecione Apagar conta. Isso remove o vínculo do número com o aplicativo do celular.
  3. Desconecte a fila na plataforma. Na tela de Configurações > Filas, desconecte a fila atual.
  4. Refaça a conexão. Clique novamente na opção de conectar via Facebook/Meta.
  5. Escolha adicionar um número novo. Na janela da Meta, ao chegar na etapa de número, selecione a opção de adicionar um novo número (em vez de selecionar a conta/perfil já existente) e conclua a verificação por SMS ou ligação.

Pontos de atenção

  • O ícone de celular ao lado da fila na lista de filas indica que aquela conexão está em modo Coexistence.
  • Não é possível combinar Coexistence com WAMD e API Oficial ao mesmo tempo no mesmo número — o risco de banimento pelo WhatsApp é alto. É possível, porém, manter várias conexões (WAMD, Oficial ou Coexistence) desde que cada uma use um número diferente.
  • O sistema não bloqueia tecnicamente o cadastro de duas filas diferentes usando o mesmo número na API oficial, mas isso não é recomendado: gera atendimentos duplicados para o mesmo contato e o envio de templates fica vinculado a apenas uma das filas.
  • Um número já em uso em uma fila de API Oficial não pode também ser usado no aplicativo comum do WhatsApp (não Business) ao mesmo tempo, a menos que a conexão seja Coexistence — sem isso, o contato final pode ver o aviso de que o número "não usa mais o WhatsApp".
  • Converter uma fila WAMD para Cloud API é uma ação imediata e encerra automaticamente todos os atendimentos abertos na fila naquele momento — veja o artigo "É possível converter uma fila de WhatsApp entre API oficial e não oficial, inclusive em lote?" para o passo a passo completo do botão de conversão.

Se não resolver

Se, mesmo apagando a conta do celular e escolhendo "adicionar novo número", a fila continuar em modo Coexistence, acione o suporte informando a fila, a instância, e se a conta do WhatsApp Business App foi de fato apagada do celular antes de refazer a conexão.

Por que as mensagens do WhatsApp Coexistence demoram ou param de sincronizar no celular?

Resumo

No modo Coexistence, a sincronização entre o aplicativo WhatsApp Business no celular e o sistema é feita inteiramente pela Meta — o sistema não controla nem força esse processo. Atrasos e inconsistências pontuais (mensagens que demoram a aparecer, ou que param de aparecer no celular) são um comportamento conhecido desse modelo, e não existe um recurso para ressincronizar retroativamente mensagens que já pararam de sincronizar.

Quando se aplica

  • Sua fila está conectada em modo Coexistence (WhatsApp Business App + API Cloud no mesmo número).
  • Mensagens que chegam normalmente no sistema demoram para aparecer no aplicativo do celular, ou pararam de aparecer nele.
  • Você quer saber se dá para recuperar o histórico que parou de sincronizar, ou identificar atendimentos originados de um Status (story) do WhatsApp.

Passo a passo

  1. Confirme a abrangência. Verifique se o problema ocorre em todos os números da fila ou apenas em alguns.
  2. Teste no aplicativo do celular. Confirme que o WhatsApp Business está sendo aberto com regularidade — o aplicativo precisa ser aberto periodicamente para manter a sincronização ativa.
  3. Verifique a atualização e a conexão. Confirme que o aplicativo está na versão mais recente e que a fila está com a conexão estável, sem quedas recentes.
  4. Verifique há quanto tempo a fila está em Coexistence. Conexões muito recentes podem ainda estar concluindo a sincronização inicial.
  5. Se nada disso resolver, desconecte e reconecte a Coexistence. Isso pode ajudar a restabelecer a sincronização, mas não garante a recuperação de mensagens que já pararam de sincronizar antes da reconexão.

Pontos de atenção

  • Não existe hoje um recurso de ressincronização retroativa do histórico entre o sistema e o aplicativo do celular. A importação de histórico e de contatos do celular só é possível durante a configuração inicial da conexão via QR Code, e precisa estar ativada antes da autenticação da fila — não depois, com a fila já em uso.
  • O sistema identifica automaticamente atendimentos originados de um clique em anúncio (Click to WhatsApp), mas não existe hoje uma forma de identificar que um atendimento começou como resposta a um Status/story do WhatsApp — essa origem não é sinalizada pelo WhatsApp para esse tipo de interação.
  • Atrasos e inconsistências de sincronização no Coexistence são inerentes ao modelo, pois dependem da infraestrutura da Meta, e podem se repetir mesmo depois de reconectar.

Se não resolver

Se o problema persistir mesmo após confirmar aplicativo atualizado, conexão estável e reconexão da Coexistence, reúna: os números afetados, há quanto tempo a fila está em Coexistence, se o problema ocorre em todos os números ou só em alguns, e desde quando as mensagens pararam de aparecer no celular — essas informações agilizam a investigação pelo suporte.

Por que o QR Code não aparece ao conectar uma fila em modo Coexistência?

Resumo

O QR Code de conexão em modo Coexistência costuma não aparecer por causa de algo do lado do celular ou da conta Meta do cliente, não do sistema: PIN de confirmação em duas etapas ativo no WhatsApp, permissões incompletas no Gerenciador de Negócios, o botão de confirmação escondido pela rolagem da janela da Meta, ou o número já vinculado a outro cadastro. Revise esses quatro pontos e tente exibir o QR Code novamente.

Quando se aplica

  • Você está conectando (ou reconectando) uma fila de WhatsApp em modo Coexistência (WhatsApp Business App + API no mesmo número) e o QR Code não chega a aparecer na tela.
  • A janela de autenticação da Meta abre, mas fica travada, em branco, ou sem o botão final de confirmação.

Passo a passo

  1. Desative temporariamente o PIN do WhatsApp. No celular onde o WhatsApp Business está instalado, acesse as configurações da conta e desative a confirmação em duas etapas. Com o PIN ativo, a API pode não conseguir assumir o número durante o pareamento inicial. Depois de conectar, o PIN pode ser reativado.
  2. Confira as permissões no Gerenciador de Negócios (Meta Business Manager). O usuário que está fazendo a conexão precisa ter controle total (Admin) sobre o Portfólio Empresarial selecionado, e não pode haver pendência de aceite de termos ou verificação de empresa em aberto.
  3. Verifique se o botão de confirmação não está escondido. Às vezes o botão final de consentimento fica abaixo da área visível da janela da Meta. Role para baixo dentro da janela (com o mouse ou as setas do teclado) antes de concluir que o QR Code não vai aparecer.
  4. Confirme que o número não está vinculado a outro cadastro. Se esse número já foi cadastrado antes em outra API (oficial ou não) ou em outro provedor, ele precisa ser desvinculado dessa outra conta antes de conseguir parear em uma conexão nova.
  5. Tente exibir o QR Code novamente. Na tela da fila, use os botões de conexão para desconectar e, em seguida, solicitar o QR Code de novo. O botão de QR Code só fica disponível quando a fila está conectada ao servidor mas ainda não autenticada.

Pontos de atenção

  • Os quatro primeiros pontos acontecem do lado do celular e da conta Meta do cliente — o suporte não tem como agir diretamente sobre eles, apenas orientar a verificação.
  • Reaplicar configurações e reiniciar o contêiner da instância são ações que o suporte executa pelo painel interno quando os pontos acima já foram checados e o problema persiste — não é algo disponível para o cliente configurar sozinho.
  • O modo Coexistência é diferente da API Oficial "pura": nele o WhatsApp Business App continua ativo no celular ao mesmo tempo que a API. Se a intenção era migrar totalmente para API Oficial sem o aplicativo continuar ativo, esse é um assunto à parte — veja o artigo "O que é o modo Coexistence e por que a fila fica nele ao converter para API Oficial?".

Se não resolver

Se, mesmo após verificar os quatro pontos acima, o QR Code continuar sem aparecer, acione o suporte informando a instância, o número/fila que está tentando conectar, se os pontos de PIN e permissões já foram checados, e um print ou vídeo do momento exato em que a tela trava.

É possível converter uma fila de WhatsApp entre API oficial e não oficial, inclusive em lote?

Resumo

Converter uma fila de WhatsApp não oficial (WAMD, WAMD2 ou WAMD3) para a API Oficial (Cloud API), ou trocar entre as variantes WAMD entre si, é uma ação que você mesmo faz pela tela de Configurações > Filas, sem precisar do suporte. O caminho contrário — converter uma fila já em Cloud API de volta para não oficial — não tem botão próprio e depende de abertura de chamado. Não existe, hoje, uma ferramenta de conversão em lote para várias filas de uma vez.

Quando se aplica

  • Você quer migrar uma fila WAMD, WAMD2 ou WAMD3 para Cloud API, ou trocar entre as variantes não oficiais.
  • Você clicou por engano em um dos botões de conversão e quer entender o que aconteceu e como reverter.
  • Você precisa converter várias filas, possivelmente em instâncias diferentes, de uma só vez.

Passo a passo

  1. Acesse a fila. Vá em Configurações > Filas e localize a fila desejada.
  2. Use o botão de conversão correspondente. Uma fila WAMD, WAMD2 ou WAMD3 mostra o botão Converter para Cloud API e, conforme a variante atual, também Converter para WAMD, Converter para WAMD 2 ou Converter para WAMD 3.
  3. Confirme digitando a palavra pedida. O sistema pede que você digite converter para confirmar — a ação é aplicada imediatamente após a confirmação, não é apenas um pedido para o suporte analisar depois.
  4. Reautentique a fila. Ao converter entre variantes WAMD, a autenticação atual é perdida e é preciso ler o QR Code novamente. Ao converter para Cloud API, é preciso concluir a autenticação via Facebook/Meta na própria tela da fila.
  5. Para reverter uma conversão para Cloud API de volta a não oficial, abra um chamado. Não existe botão para esse caminho contrário; informe a fila, a instância e o tipo desejado ao suporte.

Pontos de atenção

  • A conversão fecha automaticamente todos os atendimentos abertos naquela fila no momento — avise a equipe antes de converter em horário de atendimento.
  • Pode existir um limite de quantidade de filas de um determinado tipo permitidas na instância; ao atingi-lo, a conversão é recusada com a mensagem Limite excedido.
  • Não há botão nem ferramenta de conversão em lote/em massa: cada fila precisa ser convertida individualmente, uma de cada vez. Para um volume grande de filas (dezenas ou centenas, especialmente em instâncias diferentes), é preciso abrir chamado com o suporte, sem garantia de prazo.
  • Converter de Cloud API para não oficial não é recomendado pelo suporte por causa da divergência estrutural entre os dois tipos de conexão; a alternativa geralmente sugerida é criar uma fila nova já no tipo não oficial desejado, em vez de converter a existente.
  • O histórico de mensagens pode deixar de aparecer vinculado ao contato depois da conversão, porque fica ligado ao identificador da integração anterior.

Se não resolver

Se o botão de conversão não aparecer, verifique o tipo atual da fila — o botão só aparece para tipos compatíveis com aquela conversão. Se, após converter, a fila não conectar ou ficar com o tipo anterior, abra chamado informando o ID da fila, a instância e a mensagem de erro exibida.

Como desvincular um número da fila oficial da Habilis para usar outro provedor?

Resumo

A Habilis não realiza a liberação do número/WABA em nome de outro provedor — essa etapa é sempre responsabilidade do novo provedor de destino. Você mesmo consegue remover, pelo seu acesso ao Gerenciador de Negócios da Meta, as permissões concedidas à Habilis, e desconectar a fila no sistema. Se o objetivo é não ter nenhum intermediário, isso exige uma integração própria (BSP ou Direct Developer) direto com a Meta, e o número deixa de poder usar uma fila do tipo WA Cloud API padrão — passando, se quiser continuar no sistema, para uma fila WA Cloud API (Dev App). Importante: o mesmo número não pode ficar ativo em duas plataformas de API oficial ao mesmo tempo — ao ser registrado na plataforma nova, o webhook do número é redirecionado para ela, e a fila que estava conectada na Habilis para de receber mensagens.

Quando se aplica

  • Você está migrando o número da fila oficial da Habilis para outro provedor/parceiro de WhatsApp API.
  • O novo provedor pediu para a Habilis "liberar" o número, a WABA ou desativar a verificação em duas etapas.
  • Você quer usar o número sem nenhum intermediário, com integração própria direto com a Meta.
  • Você quer apenas desvincular as contas de Facebook/Instagram do gerenciamento da Habilis.
  • Você quer saber se pode manter o número funcionando na Habilis e em outra plataforma ao mesmo tempo, durante a transição.

Passo a passo

  1. Entenda quem faz o quê. A liberação de número/WABA para outro provedor é um procedimento do lado do novo provedor junto à Meta — a Habilis não executa essa liberação em nome de terceiros nem atende diretamente o provedor de destino.
  2. Remova as permissões no Gerenciador de Negócios da Meta. É você quem concede e remove o acesso da Habilis aos ativos do seu negócio (páginas, contas do Instagram, WhatsApp Business Platform). Essa remoção é feita pelo próprio Gerenciador de Negócios da Meta, não por uma tela da Habilis.
  3. Desconecte a fila no sistema. Em Configurações > Filas, desabilite ou exclua a fila conectada como oficial se não for mais utilizá-la.
  4. Decida se vai continuar usando o sistema Habilis. Se sim, e a integração com a Meta passará a ser própria (BSP ou Direct Developer), o número deve ser configurado em uma fila do tipo WA Cloud API (Dev App) ao criar a fila — não na fila oficial padrão.

Pontos de atenção

  • Somente Business Solution Providers (BSPs) e Direct Developers têm acesso direto à Cloud API da Meta sem intermediário; é a própria Meta quem define e restringe esse acesso.
  • Remover as permissões da Habilis no Gerenciador de Negócios pode interromper a integração oficial em uso imediatamente — planeje a migração antes de remover o acesso, para não ficar sem o canal funcionando.
  • Se a intenção for apenas trocar de parceiro/BSP mantendo o número na Habilis depois, e não desenvolver integração própria, confirme com o novo parceiro qual etapa cabe a cada lado antes de mexer nas permissões — a Habilis não intermedia esse contato.
  • Uma fila WA Cloud API (Dev App) é destinada a números com integração feita diretamente pelo próprio cliente/desenvolvedor, diferente da fila oficial padrão em que a Habilis é a intermediária junto à Meta.
  • Não existe uma etapa de "coexistência" entre duas plataformas de API oficial: ao concluir a conexão do número na plataforma nova, a conexão anterior para de receber mensagens, mesmo que a fila continue aparecendo como conectada no sistema antigo.

Se não resolver

Se o novo provedor continuar informando que "a Habilis precisa liberar algo" mesmo após você remover as permissões no Gerenciador de Negócios da Meta, peça a ele que detalhe exatamente qual ação técnica falta — na prática, a liberação de número e WABA é um procedimento entre o provedor de destino e a Meta. Ao acionar o suporte, informe se sua intenção é usar uma fila Dev App no próprio sistema ou sair completamente da plataforma.

Instagram e Facebook Messenger

Quais são os requisitos para conectar uma fila de Instagram e evitar erro de permissão?

Resumo

Para conectar uma fila do tipo Instagram, a conta precisa ser profissional e ter uma página do Facebook associada, e o usuário do Facebook usado na autenticação precisa ter, no mínimo, permissão de moderador nessa página. Erros de permissão (inclusive falhas de OAuth) que aparecem depois de a fila já estar funcionando geralmente indicam que esse acesso foi reduzido ou revogado — refazer a conexão da fila costuma resolver.

Quando se aplica

  • Você está criando uma fila do tipo Instagram e a autenticação falha.
  • Uma fila do tipo Instagram que já funcionava parou de enviar ou receber mensagens, com erro de permissão.
  • Você quer saber se dá para atender pelo Instagram e responder pelo WhatsApp na mesma fila.

Passo a passo

  1. Confira os requisitos da conta antes de conectar. A conta do Instagram precisa ser profissional e estar vinculada a uma página do Facebook.
  2. Confira o nível de acesso na página do Facebook. O usuário do Facebook que vai se autenticar precisa ter, no mínimo, permissão de moderador na página vinculada à conta do Instagram. Permissões mais restritas tendem a causar falha na integração ou erro de permissão mais adiante.
  3. Autentique. Em Configurações > Filas, na fila do tipo Instagram, clique em Entrar com o Facebook; uma janela pop-up abre para você fazer login e autorizar o acesso.
  4. Se aparecer erro de permissão depois de já conectada, use o botão Verificar saúde da conexão da fila para confirmar se o token, o webhook ou a conta do Instagram vinculada estão com problema, e refaça a conexão (Desconectar do Facebook e depois Entrar com o Facebook de novo) para revalidar o acesso.

Pontos de atenção

  • Uma conta de Instagram só pode estar conectada a uma fila por vez; conectar a mesma conta em outra fila remove a inscrição de eventos da fila anterior.
  • Não é possível unificar duas filas de canais diferentes — por exemplo, receber pelo Instagram e responder pelo mesmo atendimento no WhatsApp na mesma fila. Cada canal usa sua própria fila.
  • Se outras contas de Instagram na mesma instância continuam funcionando normalmente, o problema costuma ser específico daquela conta ou página (permissão ou sessão expirada), e não uma falha geral do sistema.
  • Ao concluir a conexão, o sistema exige a confirmação de que você leu a política de privacidade e os termos de uso do serviço.

Se não resolver

Rode o Verificar saúde da conexão da fila e anote qual item aparece inválido (Token, Webhook ou Conta Instagram), além do nível de acesso do usuário do Facebook na página vinculada, antes de acionar o suporte.

Que campos e requisitos existem para conectar uma fila de Instagram ou Facebook Messenger?

Resumo

As filas do tipo "FB Messenger" e "IG Messenger" conectam exclusivamente pelo botão "Entrar com o Facebook" (login OAuth em um pop-up) — não existem campos de token para digitar. Depois de autenticado, a fila mostra "Autenticado com a página: {nome da página}" e um botão para verificar a saúde da conexão.

Quando se aplica

  • Você vai criar ou reconectar uma fila de Instagram Direct ou Facebook Messenger e quer saber quais campos preencher.
  • A fila mostra "Entrar com o Facebook" e você não sabe se precisa de token, API key ou outra credencial.
  • Você quer confirmar os pré-requisitos de página/conta antes de iniciar a conexão.

Passo a passo

  1. Abra a fila. Vá em Configurações > Filas, edite (ou crie) uma fila do tipo "FB Messenger" ou "IG Messenger" e abra a aba "Conexão".
  2. Confira os pré-requisitos. Para Facebook Messenger, você precisa ser administrador de uma página da empresa no Facebook. Para Instagram, é preciso ter uma conta profissional associada a uma página do Facebook, com um usuário de permissão de no mínimo moderador.
  3. Clique em "Entrar com o Facebook". Um pop-up abre pedindo login e senha da conta Facebook/Instagram.
  4. Selecione a página. Se o usuário administra mais de uma página, apenas uma pode ser selecionada por fila.
  5. Aceite os termos. Ao continuar, você declara concordar com a Política de Privacidade e os Termos de Uso do fornecedor da integração.
  6. Confirme a autenticação. A tela passa a mostrar "Autenticado com a página: {nome da página}".
  7. Teste a conexão (opcional). Use o botão "Verificar saúde da conexão" para checar se a integração autenticada continua funcionando.

Limites e regras

  • Não há campos de token, chave de API ou credencial digitável nessas filas — a única forma de conectar é pelo login OAuth do botão "Entrar com o Facebook".
  • Uma mesma página do Facebook só pode ser vinculada a uma fila por vez, mesmo que o administrador tenha acesso a várias páginas.
  • Uma mesma conta de Instagram só pode estar sincronizada em uma fila por vez: sincronizá-la em uma segunda fila remove a inscrição de eventos da fila anterior, interrompendo o recebimento de mensagens na fila original.
  • No Instagram, o usuário autenticado precisa ter no mínimo permissão de moderador na página associada.

Pontos de atenção

  • Se o botão "Entrar com o Facebook" não abrir o pop-up ou ele fechar sem concluir o login, verifique se o navegador está bloqueando pop-ups para o domínio do sistema.
  • Trocar a conta sincronizada de uma fila para outra não é automático: é preciso reautenticar na fila nova, o que desconecta a fila antiga desse mesmo canal.
  • Facebook Messenger e Instagram exigem administração/moderação da página no momento da autenticação; perder essa permissão na Meta depois de conectado pode derrubar a integração mesmo sem alteração na fila.
  • Uma fila de Instagram tem, na aba "Configurações" (fora da aba "Conexão"), duas opções independentes para abrir atendimento automaticamente quando alguém comenta em uma publicação ou em uma live da conta conectada.
  • Para os requisitos de permissão da Meta e erros comuns ao conectar, veja também o artigo "Quais são os requisitos para conectar uma fila de Instagram e evitar erro de permissão?".

Se não resolver

Se a autenticação falhar ou a fila aparecer desconectada mesmo depois de autenticada, use o botão "Verificar saúde da conexão" para confirmar o status atual. Antes de acionar o suporte, reúna: o tipo de fila (FB Messenger ou IG Messenger), se a autenticação chegou a ser concluída (a tela mostrou o nome da página), e se a mesma conta está ou já esteve conectada em outra fila.

Por que uma imagem ou áudio enviado pela fila do Instagram não chega ao cliente?

Resumo

Quando uma imagem ou um áudio enviado pela fila do Instagram aparece como "enviado" no sistema mas não chega ao cliente final, a causa mais comum é a perda de conexão da conta do Instagram vinculada à fila — por exemplo, depois de uma troca de senha da conta. Antes de qualquer outra coisa, use o botão Verificar saúde da conexão na configuração da fila para confirmar se o token e a conta ainda estão válidos.

Quando se aplica

  • Você enviou uma imagem ou um áudio pelo Instagram e o sistema mostra como enviado, mas o cliente final diz que não recebeu nada.
  • O problema começou depois de alguma alteração na conta do Instagram (senha, segurança, dispositivos conectados).
  • Apenas uma fila específica apresenta o problema, enquanto outras filas de Instagram continuam funcionando normalmente.

Passo a passo

  1. Verifique a saúde da conexão. Em Configurações > Filas, abra a fila do Instagram e clique no botão Verificar saúde da conexão (disponível quando a fila já está autenticada). Ele confirma se o token de acesso e a conta do Instagram vinculada continuam válidos.
  2. Se a verificação indicar problema, reconecte a fila. Clique em Desconectar do Facebook e depois em Entrar com o Facebook novamente, autenticando com a mesma conta.
  3. Confirme se a conta segue com os requisitos. A conta precisa ser profissional, estar associada a uma página do Facebook, e o usuário que autentica precisa ter no mínimo permissão de moderador nessa página.
  4. Isole o problema com uma fila de teste. Crie ou use uma fila de Instagram de teste com outra conta e tente enviar uma imagem e um áudio. Se o comportamento se repetir em qualquer conta, o problema não está limitado a uma conta específica.
  5. Reinicie a instância, se necessário. No painel de instâncias, reaplique a configuração e reinicie o serviço; em alguns casos isso restabelece a sincronização da fila.

Pontos de atenção

  • Uma troca de senha na conta do Instagram pode invalidar a sessão da integração sem gerar nenhum aviso visível dentro do sistema — o sintoma percebido é justamente mídia "enviada" que não chega ao destinatário. Reconectar a fila resolve esse caso.
  • Uma mesma conta de Instagram só pode estar sincronizada a uma fila por vez; conectá-la em uma segunda fila remove a inscrição de eventos da fila anterior.
  • Se a verificação de saúde da conexão não aponta problema e o envio de mídia continua falhando mesmo em uma fila de teste com conta nova, reúna prints ou vídeo do ocorrido antes de acionar o suporte — esse padrão de falha já foi identificado em outros casos e está em análise.
  • Veja também o artigo "Quais são os requisitos para conectar uma fila de Instagram e por que aparece erro de permissão (OAuth)?" para mais detalhes sobre permissões de página exigidas na conexão.

Se não resolver

Se depois de verificar a saúde da conexão, reconectar a fila e testar com uma conta nova o problema de mídia persistir, abra um chamado com o link da instância, o tipo e número da fila, um print do resultado da verificação de saúde da conexão e, se possível, um vídeo mostrando o envio da imagem ou do áudio sem chegar ao destinatário.

Por que a mensagem do Instagram falha com o aviso "Outro aplicativo controla esta conversa"?

Resumo

Quando mais de um aplicativo está ligado à mesma conta do Instagram, a Meta define qual deles é o dono de cada conversa. Se outro aplicativo é o dono, este sistema continua recebendo as mensagens do cliente, mas a Meta recusa as respostas. A mensagem enviada fica com o X vermelho de falha e, abaixo dela, aparece o aviso "Outro aplicativo controla esta conversa no Instagram." com o botão "Tentar obter controle". A solução definitiva é configurar este sistema como aplicativo padrão no encaminhamento de conversas do Instagram, na Página do Facebook vinculada à conta.

Quando se aplica

  • A fila é do tipo "IG Messenger" e as mensagens do cliente chegam normalmente, mas as respostas falham.
  • Ao passar o mouse sobre o horário da mensagem com falha, o erro mostra código 100, subcódigo 2534037 e um texto como "A ação é inválida porque não é a dona do tópico".
  • A conta do Instagram usa ou já usou outra ferramenta de automação ou de atendimento (chatbots, ferramentas de anúncios e similares).
  • O problema aparece só em algumas conversas, por exemplo nas que começaram por um anúncio.

Passo a passo

  1. Entenda o que o sistema já fez. Na primeira falha desse tipo em um atendimento, o sistema tenta assumir a conversa sozinho e, se conseguir, reenvia a mensagem sem que você precise fazer nada. O aviso só aparece quando essa tentativa não deu certo.
  2. Tente manualmente, se quiser. Clique em "Tentar obter controle", abaixo da mensagem que falhou. Se o sistema conseguir assumir a conversa, aparece a confirmação "Controle obtido". Envie a mensagem de novo, porque a mensagem que falhou não é reenviada automaticamente.
  3. Corrija a configuração da conta para resolver de vez. Peça a quem administra a Página do Facebook vinculada ao Instagram que abra a Página, entre em Configurações, depois Configuração da página e depois Encaminhamento de conversas do Instagram.
  4. Defina este sistema como aplicativo padrão. Na seção do aplicativo padrão, selecione este sistema e salve.
  5. Libere a tomada de controle. Na mesma tela, confira se este sistema tem a permissão para assumir o controle das conversas ativada.
  6. Remova aplicativos que não são mais usados. Se uma ferramenta antiga continua ligada à conta, remova-a dali para que ela não volte a ser a dona das conversas.
  7. Confira as conversas vindas de anúncio. A mesma tela permite escolher um aplicativo diferente para as conversas que começam por anúncios. Se só essas conversas falham, verifique qual aplicativo está escolhido para elas.

Limites e regras

  • A tentativa automática acontece uma vez por atendimento. Cada novo atendimento com o mesmo cliente tem direito a uma nova tentativa automática.
  • Depois de uma tentativa, automática ou manual, o botão fica indisponível por 30 segundos e mostra quanto tempo falta ("Tentar de novo em ...s").
  • Cada atendimento aceita no máximo 5 tentativas por hora. Depois disso, o sistema pede para aguardar.
  • O botão aparece apenas para o agente que está com o atendimento aberto. Ele não aparece no histórico de atendimentos anteriores nem nas telas de supervisão.
  • Tentar obter o controle só funciona se a Meta permitir que este sistema assuma as conversas. Sem essa permissão na Página, as tentativas continuam falhando até a configuração ser corrigida.

Pontos de atenção

  • Obter o controle não é permanente. Se a conversa ficar sem atividade por muito tempo, ela pode voltar para o aplicativo padrão definido na Página, e a falha volta a aparecer. Configurar este sistema como aplicativo padrão evita isso.
  • Assumir a conversa tira o controle do outro aplicativo. Se a empresa usa de propósito outra ferramenta nessa conta, combine com quem cuida dela antes de mudar o aplicativo padrão.
  • Respostas públicas a comentários não dependem do dono da conversa e não mostram este aviso.
  • Para os requisitos de conexão da fila, veja o artigo "Que campos e requisitos existem para conectar uma fila de Instagram ou Facebook Messenger?".

Se não resolver

Se a falha continuar depois de definir este sistema como aplicativo padrão e liberar a permissão para assumir o controle das conversas, reconecte a fila pelo botão "Entrar com o Facebook" e envie uma nova mensagem. Antes de acionar o suporte, reúna: o nome da fila, o horário de uma mensagem que falhou, o texto do erro exibido ao passar o mouse sobre o horário e uma captura da tela de encaminhamento de conversas do Instagram na Página.

E-mail, modelos e publicações

Quais campos existem na aba Conexão de uma fila de E-mail (SMTP/IMAP)?

Resumo

A fila do tipo E-mail (marcada como BETA na criação) usa SMTP para enviar mensagens e IMAP para recebê-las. Na aba Conexão dessa fila, a tela mostra dois blocos lado a lado — "Dados para envio (SMTP)" e "Dados para recebimento (IMAP)" — cada um com Servidor, Porta, um toggle "Conexão segura?", Usuário e Senha; o bloco SMTP ainda pede Nome do remetente e E-mail do remetente. Abaixo dos dois blocos há um campo para informar um endereço de teste e os botões para testar o envio, testar o recebimento e salvar as credenciais.

Quando se aplica

  • Você está configurando ou revisando uma fila de E-mail e precisa saber quais campos preencher na aba Conexão.
  • Você quer testar se o envio (SMTP) ou o recebimento (IMAP) estão funcionando antes de salvar.
  • Você não sabe por que a aba "Mensagens" não aparece nessa fila.

Passo a passo

  1. Abra a fila de E-mail. Em Configurações > Filas, expanda a fila do tipo E-mail e abra a aba Conexão.
  2. Preencha "Dados para envio (SMTP)". Servidor, Porta, o toggle "Conexão segura?", Usuário, Senha, Nome do remetente e E-mail do remetente.
  3. Preencha "Dados para recebimento (IMAP)". Servidor, Porta, o toggle "Conexão segura?", Usuário e Senha.
  4. Informe um e-mail em "Enviar para:" e clique em Enviar teste para disparar uma mensagem de teste a esse endereço usando os dados SMTP preenchidos.
  5. Clique em Testar recebimento para validar a leitura via IMAP com os dados informados.
  6. Clique em Salvar dados para gravar as credenciais SMTP e IMAP da fila.

Limites e regras

  • Porta SMTP e Porta IMAP: aceitam valores numéricos entre 1 e 65.535.
  • O E-mail do remetente precisa estar em formato de e-mail válido, assim como o endereço informado em "Enviar para:".
  • A aba "Mensagens" (mensagens automáticas de fora de horário, fechamento, pesquisa de satisfação etc.) não é exibida para filas do tipo E-mail.

Pontos de atenção

  • O tipo E-mail está marcado como BETA na lista de criação de filas — trate como recurso em estágio experimental.
  • Use os botões de teste de envio e de teste de recebimento antes de salvar: eles validam as credenciais sem depender de um cliente real enviando mensagem.
  • Servidor, porta e o toggle "Conexão segura?" precisam ser compatíveis com o que o provedor de e-mail exige (por exemplo, portas e exigência de conexão segura variam entre provedores) — confirme esses dados com o provedor do e-mail antes de preencher.

Se não resolver

Se o teste de envio ou de recebimento falhar mesmo com os dados corretos, veja o artigo "Como configurar uma fila de e-mail com Gmail (SMTP/IMAP) e o que fazer se o envio falhar?" para os passos de diagnóstico de autenticação com provedores como o Gmail. Antes de acionar o suporte, reúna o servidor e a porta usados em cada bloco (SMTP e IMAP), se o toggle "Conexão segura?" estava ativado, e a mensagem de erro exibida ao clicar em Enviar teste ou Testar recebimento.

Para que servem os Modelos HTML e como criar um para usar no atendimento?

Resumo

Modelos HTML é um cadastro em Configurações > Cadastros > Modelos HTML usado para pré-montar e-mails: cada modelo guarda nome, assunto, anexos e um corpo em HTML editável em editor de texto rico. Ao compor um e-mail no atendimento, o agente escolhe um desses modelos na lista "Modelos" e o assunto, o conteúdo e os anexos são preenchidos automaticamente, podendo ser editados antes do envio.

Quando se aplica

  • Padronizar o texto e a formatação de e-mails enviados a partir do atendimento.
  • Entender a diferença entre Modelos HTML e outros cadastros parecidos: Modelos de documentos (usado em Configurações > Cadastros > Modelos de documentos, para gerar documentos, ex.: no CRM) e Templates WA Cloud API (mensagens pré-aprovadas pela Meta para WhatsApp Cloud API).
  • Descobrir por que um e-mail sai com assunto, conteúdo e anexos já preenchidos ao escolher um modelo.

Passo a passo

  1. Abra o cadastro. Vá em Configurações > Cadastros > Modelos HTML e clique em "Adicionar".
  2. Preencha Nome e Assunto. Ambos são obrigatórios: o Nome identifica o modelo na lista de seleção do e-mail; o Assunto é copiado para o campo assunto do e-mail ao usar o modelo.
  3. Adicione anexos, se precisar. Use o campo "Anexos" para vincular arquivos da Galeria de arquivos que devem acompanhar o modelo.
  4. Monte o conteúdo. Clique em "Editar HTML" e use o editor de texto rico (formatação, cores, tabelas, links, imagens) para montar o corpo do e-mail.
  5. Salve. Clique em "Adicionar" (ou "Atualizar", ao editar um modelo existente).
  6. Use o modelo no atendimento. Ao compor um e-mail, selecione o modelo desejado na lista "Modelos"; ao trocar a seleção, o assunto, o conteúdo e os anexos do e-mail são recarregados a partir do modelo escolhido (a opção "Sem modelo" limpa a seleção).

Limites e regras

CampoRegra
NomeObrigatório, até 255 caracteres
AssuntoObrigatório, até 255 caracteres
ConteúdoCorpo em HTML, montado no editor de texto rico
AnexosOpcional, selecionados a partir da Galeria de arquivos
  • Criar, editar ou excluir Modelos HTML exige perfil Administrador ou a permissão de edição da Galeria liberada no cadastro do usuário.

Pontos de atenção

  • Modelos HTML servem para e-mail, não para WhatsApp: templates de WhatsApp Cloud API têm cadastro próprio ("Templates WA Cloud API") e passam por aprovação da Meta.
  • Não confunda com "Modelos de documentos", usado para gerar documentos (por exemplo, ligados a oportunidades do CRM), que é um cadastro separado.
  • Ao trocar o modelo selecionado na composição do e-mail, o conteúdo já digitado é substituído pelo conteúdo do novo modelo.

Se não resolver

Confirme se o modelo foi salvo com Nome e Assunto preenchidos e se o conteúdo HTML não ficou vazio (o botão de salvar do cadastro fica desabilitado sem esses dados). Se o modelo não aparece na lista de composição de e-mail, verifique se ele foi realmente salvo em Configurações > Cadastros > Modelos HTML. Persistindo o problema, reúna o nome do modelo e a fila/canal de e-mail usada antes de acionar o suporte.

Como cadastrar uma Novidade e onde ela aparece para os usuários do sistema?

Resumo

Novidades são avisos ou comunicados criados pelo administrador em Configurações > Cadastros > Novidades, com título, imagem, período de validade e conteúdo em HTML. Elas aparecem para os usuários no botão "Novidades" do menu do usuário (com contador de não lidas) e, se marcadas, também como popup automático no login. Novidades do tipo público ainda podem ser exibidas nas filas de Web Chat.

Quando se aplica

  • Anunciar uma atualização, aviso ou comunicado interno para administradores, supervisores e/ou agentes.
  • Publicar um comunicado público que apareça também para clientes no Web Chat.
  • Entender por que uma novidade não aparece para um usuário específico ou não some do Web Chat de imediato.

Passo a passo

  1. Abra o cadastro. Vá em Configurações > Cadastros > Novidades e clique em "Adicionar".
  2. Preencha o cabeçalho. Informe o link da imagem principal (opcional, tamanho ideal 1200x400px, proporção 3:1) e o Título (obrigatório).
  3. Escolha o Tipo. Selecione Pública, Interna, Pública restrita ou Interna restrita. Nos tipos restritos, um campo "Filas permitidas" aparece para escolher quais filas liberam a novidade.
  4. Defina o período. Preencha "Válido a partir de" e "Válido até" para controlar quando a novidade fica ativa.
  5. Marque o público. Em "Exibir para", marque Admins, Supervisores e/ou Agentes. Em instâncias com Painel de instâncias habilitado, o administrador também pode marcar "Instâncias" para novidades do tipo Interna.
  6. Ative o popup, se quiser. Marque "Exibir popup no login" para que a novidade abra automaticamente na primeira vez que o usuário elegível fizer login.
  7. Complete o conteúdo. Preencha Subtítulo, Palavras-chave e Etiquetas, e use "Editar HTML" para escrever o conteúdo completo no editor de texto rico (formatação, listas, tabelas, links e imagens).
  8. Salve. Clique em "Adicionar" (ou "Atualizar", ao editar uma novidade existente).

Limites e regras

CampoRegra
TítuloObrigatório, até 500 caracteres
Link da Imagem PrincipalOpcional, até 500 caracteres; tamanho ideal 1200x400px (proporção 3:1)
TipoPública, Interna, Pública restrita ou Interna restrita
Filas permitidasObrigatório definir ao menos uma fila quando o Tipo é Pública restrita ou Interna restrita
Exibição pública no Web ChatFica em cache por até 6 horas: criação, edição ou exclusão de uma novidade pública pode levar até 6 horas para refletir nas filas de Web Chat
  • Criar ou editar novidades exige perfil Administrador ou a permissão específica "Editar novidades" liberada no cadastro do usuário.

Pontos de atenção

  • O botão "Novidades" no menu do usuário mostra um contador com a quantidade de novidades ainda não lidas por ele.
  • Uma novidade só aparece para um usuário se o tipo, o período de validade e a marcação em "Exibir para" (ou a fila, nos tipos restritos) forem compatíveis com o perfil dele.
  • O popup automático no login só dispara para novidades marcadas com "Exibir popup no login" que ainda não foram vistas pelo usuário.
  • Alterações em novidades públicas não aparecem de imediato no Web Chat por causa do cache de até 6 horas — isso não é falha do cadastro.
  • Veja também o artigo "Quais permissões liberam editar catálogo, galeria, base de conhecimento e novidades?" para detalhes sobre como liberar a permissão de edição para supervisores ou agentes.

Se não resolver

Confirme o Tipo da novidade, o período de validade, as marcações em "Exibir para" (ou as filas permitidas, se restrita) e se já se passaram até 6 horas no caso de novidade pública destinada ao Web Chat. Se o problema persistir, reúna o título da novidade, o tipo escolhido e o perfil do usuário que deveria vê-la antes de acionar o suporte.

Filas, permissões e limites

Existe limite de quantidade de filas que podem ser criadas por tipo de canal?

Resumo

Sim, o sistema pode limitar quantas filas ativas de um mesmo canal uma instância pode ter. Esse limite é definido na configuração da instância (não é um campo editável na tela de Filas) e pode valer para um tipo exato de fila ou para um grupo inteiro de canal — por exemplo, todas as variantes de WhatsApp somadas. Um tipo de canal também pode estar completamente bloqueado para a instância, independentemente de qualquer limite de quantidade.

Quando se aplica

  • Um administrador tenta criar uma nova fila de um canal (WhatsApp, Telegram, Instagram etc.) e recebe um erro de limite.
  • Entender se o limite conta as filas de cada tipo separadamente ou o canal inteiro somado.
  • Confirmar se um tipo de fila está bloqueado para a instância, e não apenas limitado por quantidade.

Limites e regras

  • Ao tentar criar uma fila além do limite configurado para aquele tipo ou grupo de canal, a interface mostra o erro "Limite excedido — Limite de filas deste tipo foi atingido."
  • Quando um tipo de canal está totalmente desabilitado para a instância, a criação é bloqueada com o erro "Tipo desabilitado — Este tipo de fila está desabilitado", mesmo que o limite de quantidade não tenha sido atingido.
  • O limite pode ser configurado de duas formas, à escolha da administração da plataforma: por tipo exato de fila, ou por grupo de canal (todas as variantes de WhatsApp juntas, todas as variantes de Telegram juntas, e assim por diante).
  • OLX e Mercado Livre têm, cada um, o seu próprio grupo. As duas filas do TikTok (TikTok Shop e TikTok Business Messaging) formam um grupo só: são liberadas ou bloqueadas juntas e, no limite por grupo, contam juntas.
  • Quando o limite por grupo de canal está ativo mas sem um valor específico definido, o sistema aplica automaticamente um padrão de 150 filas ativas para aquele grupo.
  • Esses limites contam apenas filas ativas (não contam filas excluídas ou inativas).

Pontos de atenção

  • Esses limites e bloqueios são definidos na configuração da instância pela administração da plataforma — não existe um campo na tela de Filas onde o cliente possa ver ou alterar o valor do limite.
  • Um mesmo canal pode ter suas variantes contadas juntas (por grupo) ou separadamente (por tipo exato), dependendo de como o limite foi configurado para aquela instância — por isso o mesmo canal pode se comportar de forma diferente em instâncias diferentes.
  • O erro "Tipo desabilitado" e o erro "Limite excedido" têm causas diferentes: um bloqueia o canal por completo, o outro é apenas uma questão de quantidade — vale conferir qual dos dois apareceu antes de investigar.

Se não resolver

Se um cliente não consegue mais criar filas de um determinado canal, primeiro identifique qual dos dois erros apareceu ("Limite excedido" ou "Tipo desabilitado") e o tipo exato de canal envolvido. Como o valor do limite e o bloqueio de tipo são configurados na instância e não ficam visíveis na tela de Filas, acione o suporte informando o canal, o erro exibido e quantas filas ativas desse canal a instância já possui, para que a configuração da instância seja conferida.

Por que uma fila não pode ser desabilitada ou excluída e o que verificar antes?

Resumo

Uma fila só pode ser desabilitada ou excluída depois que todos os agentes e supervisores vinculados a ela forem removidos. Tentar a operação antes disso mostra o aviso "Usuários vinculados" (se houver agentes) ou "Supervisores vinculados" (se houver supervisores, mesmo sem nenhum agente). Tanto o botão de excluir de cada fila quanto o botão de desabilitar em lote fazem a mesma verificação e aplicam, no fundo, a mesma inativação: a fila deixa de operar, mas o registro não é apagado fisicamente.

Quando se aplica

  • Você clicou para excluir ou desabilitar uma fila e recebeu um aviso de bloqueio.
  • Você quer saber o que precisa remover antes de conseguir desabilitar ou excluir uma fila.
  • Você quer saber quem tem permissão para excluir uma fila.

Passo a passo

  1. Remover os agentes vinculados. Em Configurações > Filas, edite a fila e desvincule todos os agentes associados a ela.
  2. Remover os supervisores vinculados. Do mesmo modo, desvincule todos os supervisores associados à fila.
  3. Excluir a fila. Na grade de Filas, clique no ícone de "x" (Excluir fila) na linha da fila — visível apenas para o perfil Administrador.
  4. Ou desabilitar em lote. Selecione uma ou mais filas na grade e clique no botão "Desabilitar" no topo da tela para aplicar a mesma verificação a todas de uma vez.

Limites e regras

  • Existindo pelo menos um agente vinculado à fila, a operação é bloqueada com o aviso "Usuários vinculados".
  • Sem agentes, mas existindo ao menos um supervisor vinculado, a operação é bloqueada com o aviso "Supervisores vinculados".
  • O ícone de excluir fila na grade só aparece para o perfil Administrador.
  • O botão de desabilitar em lote fica disponível somente com pelo menos uma fila selecionada na grade, e só para Administrador ou perfis internos da operação.

Pontos de atenção

  • Excluir uma fila, no sistema, é uma inativação: o registro da fila continua existindo, só deixa de estar habilitado. Não existe, pela interface, uma ação separada de apagar definitivamente os dados da fila.
  • Ao inativar (excluir) uma fila do tipo Webchat (App Web), a configuração do widget dessa fila publicada para uso externo também é removida automaticamente.
  • Veja também o artigo "Quais erros podem aparecer ao criar, conectar ou importar a sessão de uma fila de atendimento?" para outras mensagens de erro do cadastro de filas.

Se não resolver

Se o aviso de bloqueio continuar aparecendo mesmo depois de remover os agentes e supervisores que você conhece, confira novamente a lista completa de vínculos da fila — pode haver mais agentes ou supervisores associados do que o esperado. Antes de acionar o suporte, reúna o nome da fila e a mensagem exata exibida ("Usuários vinculados" ou "Supervisores vinculados").

Quais permissões liberam o chat interno e o acesso a grupos de WhatsApp?

Resumo

Duas permissões da seção Chat da aba Permissões do usuário controlam o acesso ao chat interno: "Acessar chat interno" libera o módulo em si, e "Acessar grupos de WA" libera especificamente os grupos de WhatsApp dentro dele. A segunda depende da primeira: só aparece na tela, e só faz sentido, se "Acessar chat interno" já estiver marcada. Um agente recém-criado já vem com "Acessar chat interno" marcada; "Acessar grupos de WA" não.

Quando se aplica

  • Um usuário não vê o ícone ou o módulo de chat interno.
  • Um usuário acessa o chat interno mas não consegue entrar em grupos de WhatsApp dentro dele.
  • É preciso liberar o chat interno para um agente sem liberar o acesso aos grupos de WhatsApp.
  • É preciso tirar o chat interno de um agente que já nasceu com ele liberado.

Passo a passo

  1. Abra a ficha do usuário. Vá em Configurações > Usuários, edite o usuário e abra a aba Permissões.
  2. Localize a seção Chat. Ela aparece apenas para um usuário do tipo Agente com o chat habilitado, em uma instância com o recurso de chat habilitado.
  3. Confira "Acessar chat interno". Em um agente recém-criado ela já vem marcada; desmarque se aquele agente não deve usar o recurso. Essa opção só é exibida se o chat interno não estiver desabilitado na instância.
  4. Marque "Acessar grupos de WA", se necessário. Essa opção só aparece depois que "Acessar chat interno" já estiver marcada para o mesmo usuário.

Limites e regras

  • Um usuário do tipo Agente é criado já com "Acessar chat interno" marcada, desde que o chat interno esteja habilitado na instância. "Acessar grupos de WA" nunca vem marcada por padrão.
  • "Acessar grupos de WA" tem uma dependência de ordem: a opção só é exibida na tela quando "Acessar chat interno" está marcada. Se você desmarcar "Acessar chat interno" depois, "Acessar grupos de WA" some da tela.
  • Ambas as permissões só existem para usuários do tipo Agente e só ficam visíveis se o chat interno não estiver desabilitado nesta instância.

Pontos de atenção

  • Marcar apenas "Acessar chat interno" não dá acesso a grupos de WhatsApp — é preciso marcar as duas permissões.
  • Se o chat interno estiver desabilitado para toda a instância, nenhuma das duas opções aparece na aba Permissões, independente do que estiver marcado no cadastro do usuário — e um agente novo também não recebe a liberação.
  • A permissão inicial do agente é só um ponto de partida: desmarcá-la vale imediatamente e não é reposta ao salvar a ficha de novo.

Se não resolver

Confirme se o chat interno está habilitado na instância e se o usuário é do tipo Agente; depois revise se as duas permissões — "Acessar chat interno" e "Acessar grupos de WA" — estão marcadas na seção Chat. Veja também o artigo "O que é o Chat Interno e quais usuários podem acessá-lo?" para o funcionamento geral do recurso, e "Por que grupos de WhatsApp não aparecem para um agente mesmo com a permissão liberada?" para outras causas de grupo não aparecer.

Por que grupos de WhatsApp não aparecem para um agente mesmo com a permissão liberada?

Resumo

Grupos de WhatsApp só existem em filas não oficiais (WAMD, WAMD2 ou WAMD3), pois a API Oficial (Cloud API) da Meta não permite gerenciar grupos. Para um agente ver os grupos é preciso que o número conectado à fila seja membro do grupo e que o usuário tenha as permissões Acessar chat interno e Acessar grupos de WA habilitadas. A sincronização em si é automática — não existe uma opção separada para "ligar" na configuração da fila.

Quando se aplica

  • Você habilitou a permissão "Acessar grupos de WA" para um agente e os grupos continuam sem aparecer.
  • Você quer entender por que grupos de WhatsApp não aparecem em uma fila conectada pela API Oficial.
  • Você suspeita que a permissão "Acessar funções de supervisão" bloqueia o acesso a grupos.

Passo a passo

  1. Confirme o tipo da fila. Grupos de WhatsApp só sincronizam em filas dos tipos WAMD, WAMD2 ou WAMD3 (conexão não oficial por QR Code). Em fila da API Oficial não é possível visualizar nem atender grupos, pois a Meta não oferece esse recurso via API.
  2. Confirme que o número está no grupo. Pelo aplicativo do WhatsApp no celular conectado à fila, verifique se o número está de fato entre os participantes do grupo que deveria aparecer.
  3. Confira as duas permissões do usuário. Em Configurações > Usuários, selecione o agente e verifique se Acessar chat interno e Acessar grupos de WA estão habilitadas. A segunda só é exibida na tela de edição quando a primeira já está marcada, e as duas precisam estar ativas ao mesmo tempo.
  4. Peça para o agente atualizar a sessão. Depois de ajustar uma permissão ou reconectar a fila, oriente o agente a sair e entrar novamente no sistema (ou atualizar a página) para que a lista seja recarregada.
  5. Procure o grupo dentro de "Chat Interno". Os grupos de WhatsApp aparecem junto com as conversas do módulo Chat Interno, não em uma tela separada exclusiva de grupos.

Pontos de atenção

  • Grupos de WhatsApp não existem em filas conectadas pela API Oficial (Cloud API) — a Meta não oferece suporte a gerenciamento de grupos por essa via.
  • A permissão Acessar grupos de WA só fica visível na tela de edição do usuário se Acessar chat interno também estiver marcada. Sem o chat interno habilitado, o agente não visualiza grupos, mesmo que a permissão de grupos já esteja salva como ativa.
  • A permissão Acessar funções de supervisão não tem relação com a exibição de grupos de WhatsApp: um agente que recebe essa função continua sendo do tipo Agente e mantém normalmente a permissão de grupos, sem bloqueio cruzado entre as duas opções.
  • A sincronização é automática assim que a fila é do tipo certo e o número está no grupo — não existe um botão de "importar grupos" a acionar na configuração da fila.
  • Há casos registrados de grupo que continua sem aparecer mesmo com todos os requisitos acima atendidos e mesmo depois de reiniciar a instância, indicando uma falha pontual de sincronização já identificada para investigação interna.

Se não resolver

Se você já confirmou o tipo da fila, a participação do número no grupo e as duas permissões do usuário, e o grupo mesmo assim não aparece, acione o suporte informando: o nome do grupo esperado, se o problema ocorre para todos os agentes daquela fila ou só para alguns, e um print da tela de permissões do usuário afetado.

Por que aparece o alerta de arquivo maior que o permitido no atendimento?

Resumo

O tamanho máximo de arquivo aceito em um atendimento é definido pelo campo "Tamanho máximo para arquivos" em Configurações > Geral, preenchido em KB. O maior valor que vale é 300 MB (307.200 KB): se você informar mais que isso, o sistema usa 300 MB. Ele vale nos dois sentidos — arquivo recebido do cliente e arquivo enviado pelo agente — e para qualquer canal de mensageria com suporte a mídia (WhatsApp oficial e não oficial, Instagram, Facebook, Telegram, Webchat, e-mail, entre outros). Se esse campo nunca foi configurado na instância, o sistema usa um padrão de 3 MB (3.145.728 bytes).

Quando se aplica

  • Um alerta de sistema aparece no atendimento avisando que o cliente enviou um arquivo maior que o permitido.
  • O agente tenta anexar uma foto, vídeo, áudio ou documento e recebe um aviso de arquivo muito grande.
  • Você precisa saber ou alterar o limite de tamanho de arquivo aceito pela instância.

Passo a passo

  1. Localize o campo. Acesse Configurações > Geral, aba "Geral", e encontre o campo "Tamanho máximo para arquivos".
  2. Informe o valor em KB. Digite o novo limite, de até 307.200 KB (300 MB); o campo é obrigatório e numérico, com o valor sempre expresso em quilobytes (KB).
  3. Salve. Use o botão "Salvar" da tela para aplicar a mudança.

Limites e regras

  • Quando o cliente envia um arquivo acima do limite, o sistema registra um alerta de sistema no atendimento com o texto "O cliente enviou um arquivo maior que o permitido!" e a mídia não chega a ser processada nem entregue ao agente.
  • Quando o próprio agente tenta enviar um arquivo acima do limite, o sistema recusa o envio e mostra um aviso de "Arquivo muito grande" ("O arquivo enviado excede o tamanho máximo permitido.").

Pontos de atenção

  • Arquivos acima de 300 MB não são aceitos em nenhuma configuração, mesmo que o campo tenha sido preenchido com um valor maior.
  • Esse limite é diferente do limite de tamanho de anexo processado pelo assistente de IA durante o atendimento e do limite de upload de documentos na base de conhecimento (RAG) — cada um tem seu próprio valor e é checado em um momento diferente do fluxo.
  • Só o perfil Administrador acessa e altera o campo "Tamanho máximo para arquivos".
  • Aumentar bastante esse valor eleva o consumo de espaço da instância, o que pode antecipar a limpeza automática por excesso de cota.
  • O campo é obrigatório: não é possível salvar a tela com ele vazio.

Se não resolver

Se um arquivo dentro do limite configurado ainda assim é recusado, confirme com o administrador o valor atual do campo "Tamanho máximo para arquivos" em Configurações > Geral, pois ele é específico de cada instância e pode ter sido reduzido. Antes de acionar o suporte, reúna o canal/fila do atendimento, o tipo e o tamanho aproximado do arquivo e se o problema ocorre no envio (agente) ou no recebimento (cliente). Como criar uma campanha de disparo por WhatsApp e quais são suas 4 etapas?

Resumo

A campanha de disparo em massa por WhatsApp é criada em Configurações > Campanhas (exibida com selo BETA na listagem) por um assistente de 4 etapas: Início, Audiência, Respostas e Liberação. Na primeira etapa você define o tipo, nome, fila de disparo e o template de WhatsApp que será enviado; as demais etapas montam a lista de destinatários, definem o que fazer com as respostas dos clientes e liberam o envio.

Quando se aplica

  • Você precisa criar uma campanha de disparo em massa por WhatsApp e não sabe por onde começar.
  • Você quer saber o que preencher na primeira etapa (Início) do assistente de criação.
  • Você quer saber por que uma fila não aparece na lista de filas disponíveis para a campanha.
  • Você quer saber quem pode apagar uma campanha já criada.

Passo a passo

  1. Abra o assistente. Acesse Configurações > Campanhas e inicie a criação de uma nova campanha.
  2. Etapa Início — dados básicos. Escolha o Tipo da campanha (Marketing ou Utilidades), informe o Nome da campanha (obrigatório), selecione a Fila de disparo (obrigatória) e o Template de WhatsApp a enviar (obrigatório).
  3. (Opcional) Restrinja a visualização. Ainda na etapa Início, você pode escolher um Grupo de visualização para limitar quais agentes enxergam as mensagens enviadas por essa campanha. Supervisores e Administradores sempre veem, independente do grupo escolhido.
  4. (Opcional) Trate atendimentos em aberto. Ainda na etapa Início, o campo Cliente com atendimento em andamento define o que fazer quando o destinatário já tem uma conversa aberta no momento do disparo.
  5. Etapa Audiência — monte a lista. Importe um CSV ou gere a audiência a partir dos contatos ou do CRM.
  6. Etapa Respostas — defina o destino. Configure o tempo de resposta esperado e para onde encaminhar quando o cliente responder à campanha.
  7. Etapa Liberação — envie. Defina o tamanho do teste (se houver) e libere a campanha, imediatamente ou agendada. Opcionalmente, marque "Limitar envios por hora" para distribuir o disparo ao longo do tempo — veja o artigo "Como limitar os envios por hora de uma campanha de disparo?".

Limites e regras

  • Nome da campanha, Fila e Template são obrigatórios na etapa Início.
  • O combo Fila só lista filas habilitadas cujo tipo permite envio de template do WhatsApp Cloud API — uma fila de outro canal, ou uma fila desabilitada, não aparece na lista.
  • A opção "Limitar envios por hora" é opcional e aparece na etapa Liberação, junto das políticas de envio.
  • Apagar uma campanha exige ser Administrador ou o usuário que criou a campanha.

Pontos de atenção

  • O recurso está identificado como BETA na listagem de campanhas.
  • Se a fila que você esperava usar não aparece no combo Fila, confirme se ela está habilitada e se o tipo dela permite envio de template do WhatsApp Cloud API — outros tipos de fila não são elegíveis para disparo de campanha.
  • Para o detalhe de como montar a audiência por CSV ou CRM, veja o artigo "Como funciona a etapa Audiência ao criar uma campanha e como os contatos são importados?".
  • Para o detalhe das opções da etapa Liberação e do envio de teste, veja o artigo "Quais são as opções de liberação de uma campanha e como funciona o envio de teste?".
  • Para o detalhe do limite de envios por hora, veja o artigo "Como limitar os envios por hora de uma campanha de disparo?".
  • Para o detalhe das opções de "Cliente com atendimento em andamento", veja o artigo "O que faz cada opção de 'Cliente com atendimento em andamento' numa campanha?".
  • Para quem tem permissão de criar e apagar campanhas, veja o artigo "Quem pode criar campanhas de disparo e discadora, e como liberar isso a um supervisor?".

Se não resolver

Se o menu Campanhas não aparecer, confirme o perfil do usuário. Se a fila esperada não aparece no combo, confirme se ela está habilitada e se o canal dela suporta template do WhatsApp Cloud API. Se a campanha for criada mas não avançar da etapa Início, confirme se Nome, Fila e Template foram preenchidos. Antes de acionar o suporte, reúna o nome da campanha, o tipo escolhido, a fila usada e o template selecionado.

O que faz cada opção de "Cliente com atendimento em andamento" numa campanha?

Resumo

No cadastro de campanha, o campo "Cliente com atendimento em andamento" define o que fazer quando o destinatário do disparo já tem um atendimento aberto no momento do envio. Existem 3 opções: "Enviar mesmo assim", "Marcar envio como falha e não enviar" e "Deixar na fila e enviar quando o atendimento for encerrado".

Quando se aplica

  • Você quer entender por que uma mensagem de campanha apareceu no meio de uma conversa de atendimento já aberta.
  • Você quer que a campanha nunca interrompa um atendimento em curso, seja descartando o envio, seja adiando para depois do atendimento terminar.
  • Você está configurando uma nova campanha e precisa decidir qual das 3 opções usar.

Passo a passo

  1. Abrir o campo. No cadastro da campanha, em Configurações > Campanhas, localize o campo "Cliente com atendimento em andamento" na etapa inicial do formulário.
  2. Enviar mesmo assim. Escolha esta opção se quiser que a campanha seja enviada independentemente de haver atendimento aberto. A mensagem aparece no meio da conversa do atendimento e fica visível ao agente, se o grupo de visualização dele permitir.
  3. Marcar envio como falha e não enviar. Escolha esta opção se preferir simplesmente não incomodar quem já está em atendimento. O disparo para esse cliente fica registrado como falha no relatório da campanha e a mensagem nunca é enviada.
  4. Deixar na fila e enviar quando o atendimento for encerrado. Escolha esta opção para adiar o envio. A mensagem aguarda o encerramento do atendimento atual e é enviada assim que ele fechar — podendo sair junto com a pesquisa de satisfação, se ela estiver habilitada para a fila.

Limites e regras

  • O campo aceita exatamente uma das 3 opções: "Enviar mesmo assim", "Marcar envio como falha e não enviar" ou "Deixar na fila e enviar quando o atendimento for encerrado".
  • A regra vale por destinatário: em uma mesma campanha, uns clientes podem ter atendimento aberto e outros não — a opção escolhida se aplica individualmente a cada caso encontrado no momento do envio.

Pontos de atenção

  • Com "Enviar mesmo assim", a visibilidade da mensagem para o agente depende do grupo de visualização configurado — em alguns casos o agente pode não perceber que uma campanha foi enviada durante o atendimento.
  • Com "Marcar envio como falha e não enviar", o cliente não recebe a mensagem nesse ciclo; a campanha não tenta reenviar automaticamente depois.
  • Com "Deixar na fila", o envio pode se atrasar de forma imprevisível caso o atendimento em aberto demore para ser encerrado.
  • Essa configuração só entra em ação quando o destinatário já tem um atendimento aberto no exato momento do disparo; não afeta clientes sem atendimento em andamento.

Se não resolver

Se uma mensagem de campanha não chegou ao cliente e você suspeita da opção configurada, confira o relatório de resultados da campanha: um disparo marcado como falha por esse motivo aparece identificado ali. Antes de acionar o suporte, reúna o nome da campanha, a opção configurada em "Cliente com atendimento em andamento" e o identificador do cliente afetado.

Como aprovar e liberar manualmente uma campanha suspensa para envio?

Resumo

Na lista de Configurações > Campanhas, o botão com ícone de play e tooltip "Liberar para envio" aprova uma campanha que está com status "Aguardando liberação" ou "Teste enviado" e libera o disparo das mensagens pendentes. Ao clicar, o status da campanha passa para "Enviado" e todas as mensagens que estavam aguardando autorização entram na fila de envio.

Quando se aplica

  • Você criou a campanha com liberação manual (opção "Envio manual") e ela ficou suspensa aguardando aprovação.
  • Você criou a campanha com "Enviar teste agora e aguardar liberação": o lote de teste já saiu e o restante está parado aguardando você revisar o resultado antes de liberar o envio completo.
  • Você quer saber por que uma campanha não está enviando as mensagens restantes sozinha.

Passo a passo

  1. Localizar a campanha. Acesse Configurações > Campanhas e encontre a campanha com status "Aguardando liberação" ou "Teste enviado" na lista.
  2. Liberar. Clique no botão de ícone de play com tooltip "Liberar para envio" na linha da campanha.
  3. Confirmar a mudança de status. O status da campanha muda para "Enviado" e o botão fica desabilitado (a campanha já não pode ser liberada de novo).
  4. Acompanhar o disparo. As mensagens que estavam aguardando autorização entram na fila de envio e passam a ser processadas normalmente pelo motor de disparo da fila.

Limites e regras

  • O botão "Liberar para envio" fica desabilitado quando a campanha já está com status "Enviado".
  • Liberar a campanha afeta todas as mensagens dela que estavam com status "aguardando autorização" — não é possível liberar mensagens individualmente.
  • A ação é registrada no log de auditoria como aprovação e liberação do disparo da campanha, com o horário e o usuário responsável.
  • Somente Administrador, ou Supervisor com a permissão individual de criar campanhas habilitada, tem acesso à tela de Campanhas e a esse botão.

Pontos de atenção

  • Uma campanha agendada (status "Agendado para" uma data/hora) não precisa de liberação manual: ela dispara sozinha na data configurada, salvo se a política de envio escolhida na criação também exigir aprovação.
  • Depois de liberar, a campanha não pode ser pausada de volta ao estado "aguardando liberação" — a ação não tem desfazer pela interface.
  • Se a campanha foi criada com "Enviar teste agora e aguardar liberação", revise o resultado do lote de teste antes de liberar o restante, pois a liberação envia para todos os destinatários pendentes de uma vez.

Se não resolver

Se o botão "Liberar para envio" estiver desabilitado mesmo com a campanha parecendo pendente, confirme o status exato exibido na coluna de status da lista. Se o status mudar para "Enviado" mas as mensagens não saírem, veja o artigo "Por que uma campanha de disparo falha, aparece bloqueada ou envia para número errado?". Antes de acionar o suporte, reúna o nome da campanha, o status atual e o horário em que você clicou em liberar.

Quais são as opções de liberação de uma campanha e como funciona o envio de teste?

Resumo

Na etapa "Liberação" do cadastro de uma campanha existem quatro políticas de envio: enviar manualmente só depois de uma liberação, enviar um teste antes e aguardar liberação, enviar imediatamente, ou agendar para uma data e horário futuros. A campanha criada mostra na lista um status que reflete a política escolhida, e uma campanha suspensa pode ser liberada manualmente a qualquer momento pelo botão de liberação da lista. A mesma etapa traz ainda a opção opcional "Limitar envios por hora", que controla o ritmo do disparo — veja o artigo "Como limitar os envios por hora de uma campanha de disparo?".

Quando se aplica

  • Você está criando uma campanha e não sabe qual opção escolher na etapa de liberação.
  • Você quer testar o disparo com poucos contatos antes de liberar para toda a base.
  • Você quer programar o início do disparo para uma data e horário futuros.
  • Você não entende o que significa o status da campanha na lista (Aguardando liberação, Teste enviado, Enviado, Agendado).

Passo a passo

  1. Abra o cadastro da campanha. Vá em Configurações > Campanhas e crie ou edite uma campanha até chegar na etapa "Liberação".
  2. Escolha a política de envio.
    OpçãoO que faz
    Envio manualA campanha fica suspensa aguardando liberação manual, sem enviar nada até você liberar.
    Enviar teste agora e aguardar liberaçãoEnvia o número de mensagens definido em "Tamanho do teste" e, em seguida, suspende a campanha aguardando liberação manual do restante.
    Enviar agoraLibera e envia a campanha imediatamente para todos os destinatários.
    Agendar envioAgenda o disparo para a data e horário escolhidos no campo "Selecione uma data".
  3. Preencha "Tamanho do teste". Só fica habilitado quando a política é "Enviar teste agora e aguardar liberação"; define quantas mensagens de teste serão enviadas antes de suspender o envio da campanha.
  4. Preencha a data de agendamento. Só fica habilitado quando a política é "Agendar envio"; a data mínima selecionável é a data atual (não é possível agendar no passado).
  5. (Opcional) Marque "Limitar envios por hora" e informe o máximo de mensagens que a campanha pode enviar em 1 hora, para distribuir o disparo ao longo do tempo. Veja o artigo "Como limitar os envios por hora de uma campanha de disparo?".
  6. Libere manualmente quando necessário. Na lista de campanhas (Configurações > Campanhas), use o botão "Liberar para envio" em uma campanha suspensa (política "Envio manual" ou depois de um teste) para iniciar o disparo do restante da base.

Limites e regras

  • Existem exatamente quatro políticas de envio: Envio manual, Enviar teste agora e aguardar liberação, Enviar agora, Agendar envio.
  • O status da campanha na lista reflete a política escolhida: "Aguardando liberação" (envio manual ou aguardando após teste), "Teste enviado", "Enviado" ou "Agendado para [data e hora]".
  • O botão "Liberar para envio" fica desabilitado quando a campanha já está com status "Enviado".
  • Para agendamento, a data e horário precisam ser futuros — o seletor não permite escolher uma data anterior à atual.
  • A opção "Limitar envios por hora" é independente da política de envio escolhida e vale para todas elas.
  • O item de menu "Campanhas" só aparece para o perfil Administrador, ou para o Supervisor quando o usuário tem a permissão de criar campanhas habilitada em seu cadastro.

Pontos de atenção

  • Escolher "Enviar teste agora e aguardar liberação" sem preencher (ou preenchendo com zero) "Tamanho do teste" pode resultar em nenhuma mensagem de teste sendo enviada antes da suspensão — confirme o valor antes de avançar.
  • Uma campanha agendada só passa a status "Enviado" quando a data programada chega; até lá permanece com o rótulo "Agendado para [data]".
  • Depois de liberada uma campanha (política "Enviar agora" ou liberação manual), o processo de disparo é irreversível — não é possível suspender novamente.
  • Quem apenas visualiza a lista de campanhas sem ser Administrador precisa ter a permissão de criação de campanhas para enxergar o menu e liberar disparos.

Se não resolver

Se a campanha não mudar de status mesmo depois de liberada, ou parte da base não receber as mensagens, veja o artigo "Por que uma campanha de disparo falha, aparece bloqueada ou envia para número errado?". Antes de acionar o suporte, reúna: o nome da campanha, a política de envio escolhida, o horário em que ela foi liberada (ou a data agendada) e o status atual mostrado na lista.

Como limitar os envios por hora de uma campanha de disparo?

Resumo

A opção "Limitar envios por hora", na etapa "Liberação" do cadastro de uma campanha, distribui o disparo ao longo do tempo: em qualquer janela de 1 hora, no máximo o número de mensagens informado será enviado. As mensagens restantes ficam na fila e o envio retoma sozinho quando a janela abre, até o fim da audiência. Por exemplo, uma campanha de 1000 destinatários com limite de 100 por hora leva cerca de 10 horas para ser concluída, enviando aproximadamente 100 mensagens por hora.

Quando se aplica

  • Você quer disparar uma campanha grande sem sobrecarregar a entrada de atendimentos da sua operação.
  • Você quer que as respostas da campanha cheguem de forma espaçada, em um volume que sua equipe consiga atender.
  • Você quer entender por que uma campanha limitada envia poucas mensagens por hora ou demora dias para terminar.

Passo a passo

  1. Abra o cadastro da campanha. Vá em Configurações > Campanhas, clique em "Adicionar" e siga o assistente.
  2. Avance até a etapa "Liberação" (depois de Início, Audiência e Respostas).
  3. Marque a opção "Limitar envios por hora". Ela é opcional e vem desmarcada: sem ela, a campanha envia no ritmo padrão do sistema, sem limite por hora.
  4. Informe o "Máximo de envios por hora". Digite um número inteiro a partir de 1. Ex.: 100.
  5. Conclua a campanha. O limite passa a valer a partir da liberação do disparo, em qualquer política de envio (manual, teste, agora ou agendada).

Limites e regras

  • A contagem é por janela deslizante de 1 hora: em QUALQUER período de 60 minutos, a campanha envia no máximo o número informado de mensagens — não é por hora fechada do relógio.
  • Ao atingir o limite, o envio pausa sozinho e retoma sozinho à medida que a janela abre; não é preciso liberar nada manualmente.
  • O limite é por campanha: duas campanhas limitadas em 100 na mesma fila podem enviar até 200 mensagens por hora na fila.
  • As mensagens do envio de teste também contam para o limite da campanha.
  • Se o sistema for reiniciado no meio de uma janela, a contagem da hora corrente é preservada — o limite não é esquecido.
  • Mensagens com falha que serão reenviadas automaticamente também esperam a janela do limite abrir, como qualquer outra.

Pontos de atenção

  • A campanha não pode ser editada depois de criada: se precisar de outro limite, crie a campanha novamente.
  • Com o limite ativo, a campanha leva mais tempo para concluir. Uma estimativa simples: número de destinatários dividido pelo limite informado.
  • Enquanto aguardam a janela abrir, os disparos continuam aparecendo com o status "Na fila" no detalhe da campanha — isso é o comportamento esperado, não uma falha.
  • O limite controla o ritmo da campanha; ele não interfere nos limites de taxa do WhatsApp da própria Meta.

Se não resolver

Se a campanha com limite não enviar nada mesmo com a janela aberta, ou se quiser entender o ritmo padrão sem limite, veja os artigos "Quais são as opções de liberação de uma campanha e como funciona o envio de teste?" e "Como funciona o processamento da fila de disparo AutoSend de campanhas com template?". Antes de acionar o suporte, reúna: o nome da campanha, o limite informado, o tamanho da audiência e o horário em que ela foi liberada.

O sistema fica lento durante atendimento ou disparo de campanha — o que verificar?

Resumo

Lentidão percebida durante atendimento ou disparos costuma ter causa local (navegador, cache, internet) ou é o efeito de um agente com um número excessivo de atendimentos abertos ao mesmo tempo — e não necessariamente um problema no servidor. O sistema permite limitar quantos atendimentos simultâneos um agente pode receber, por agente e por fila, o que ajuda a prevenir esse cenário.

Quando se aplica

  • O sistema, os painéis, os relatórios ou o envio de mensagens estão respondendo devagar.
  • Uma campanha de disparo em massa está demorando muito mais que o normal para processar os contatos.
  • Você quer descartar causas locais antes de abrir um chamado de lentidão.
  • Você suspeita que agentes com muitos atendimentos abertos ao mesmo tempo estejam pesando no desempenho.

Passo a passo

  1. Verifique se a lentidão é geral ou pontual. Confirme se ela afeta só um computador/agente ou toda a equipe, e se afeta só uma tela (ex.: campanhas) ou o sistema inteiro (atendimento, relatórios, painéis).
  2. Teste em outro navegador/máquina. Abra a instância anonimamente em outro navegador (janela anônima) ou em outro computador. Se a lentidão não se repetir, o problema é local.
  3. Limpe o cache do navegador do computador afetado e recarregue a página. Cache acumulado é uma causa conhecida de lentidão percebida na interface.
  4. Verifique a conexão de internet local de quem relata lentidão — instabilidade ou baixa velocidade local afeta diretamente o carregamento de conversas e relatórios.
  5. Ajuste as configurações locais de desempenho. No menu do usuário (canto superior), abra Configurações locais e ative Desabilitar animações (reduz animações visuais, útil em máquinas com desempenho limitado — exige recarregar a página) e/ou Desabilitar waveform (remove a visualização de ondas sonoras nos players de áudio, o que ajuda em conversas com muitas mensagens de áudio).
  6. Revise quantos atendimentos cada agente está com aberto. Um agente acumulando um número muito alto de atendimentos não encerrados pode ter o desempenho da própria tela impactado. Oriente a equipe a encerrar atendimentos já resolvidos.
  7. Configure um limite de atendimentos simultâneos por agente, se ainda não existir. Em Configurações > Usuários, edite o agente e ajuste o campo Número máximo de atendimentos (0 = sem limite). Também é possível limitar por fila em Configurações > Filas, no campo Atendimentos / agente.

Pontos de atenção

  • O limite por agente é opcional e vem desligado por padrão. O campo Número máximo de atendimentos (Configurações > Usuários) aceita de 0 a 500; com 0, não há limite algum — se você nunca configurou isso, é esperado que um agente possa acumular centenas de atendimentos abertos.
  • O limite por fila é independente por fila. O campo Atendimentos / agente (Configurações > Filas) limita quantos atendimentos daquela fila específica um agente recebe; atendimentos vindos de outras filas não entram nessa conta. Um agente em 5 filas com limite 10 em cada pode acumular até 50 atendimentos no total.
  • Atendimentos travados, com agente preferencial disponível ou recebidos por transferência não respeitam nenhum desses limites — por isso um agente pode ultrapassar o número configurado em situações específicas.
  • Se a lentidão for isolada a um fluxo de automação específico (por exemplo, uma automação de funil/CRM que trava ao processar listas grandes, ou uma automação em loop), a causa é diferente da lentidão geral de interface tratada aqui — veja os artigos "Por que uma automação de funil trava ao processar muitas oportunidades de uma vez?" e "O que fazer quando uma automação em loop derruba ou trava a instância?".
  • Ao reportar lentidão ao suporte, um teste feito a partir de outra máquina/rede frequentemente não reproduz o problema relatado — por isso reunir evidência do lado do cliente (gravação de tela, horário exato, navegador, se afeta todos os agentes ou só um) é o que mais ajuda a investigar.

Se não resolver

Se, após testar em outro navegador/máquina, limpar o cache, verificar a internet local e revisar a quantidade de atendimentos abertos por agente a lentidão persistir de forma consistente e reproduzível, acione o suporte com: instância, horário exato em que ocorreu, se afeta todos os agentes ou só alguns, navegador usado, e uma gravação de tela mostrando o travamento.

Como funciona o limite de atendimentos por agente e quando ele pode ser ultrapassado?

Resumo

O limite de atendimentos por agente é configurado em Configurações > Usuários, na aba Filas e Atendimento, e cada fila também tem seu próprio limite em Configurações > Filas. Mesmo com o limite ativado, ele só vale para atendimentos que o agente puxa ativamente pela distribuição automática: transferências diretas, atendimentos travados com o agente e atendimentos de agente preferencial continuam chegando normalmente e não contam para esse limite.

Quando se aplica

  • Você configurou um número máximo de atendimentos simultâneos para um agente (ou para uma fila) e ele está recebendo mais do que esse número.
  • Você quer entender a diferença entre o limite do agente e o limite da fila, e por que ajustar só um deles pode não resolver.

Passo a passo

  1. Configure o limite do agente. Acesse Configurações > Usuários, selecione o agente e vá até a aba Filas e Atendimento. Informe o número máximo de atendimentos simultâneos atribuídos a ele; com o valor 0, não há limite.
  2. Ative a aplicação do limite ao puxar. Nessa mesma aba existe uma opção para que esse número máximo seja considerado quando o agente tenta puxar atendimentos da fila. Se essa opção estiver desmarcada, o limite não é aplicado e o agente pode puxar quantos atendimentos quiser.
  3. Configure também o limite por fila, se necessário. Em Configurações > Filas, cada fila tem um campo para o número máximo de atendimentos simultâneos, vindos daquela fila, atribuídos a um agente.
  4. Lembre-se de que os dois limites são independentes. O limite da fila vale só para os atendimentos daquela fila; o limite do agente é o total somado de todas as filas em que ele atua. Um agente em 5 filas com limite de 10 por fila pode acumular até 50 atendimentos no total, então os dois valores precisam ser ajustados de forma compatível com o resultado que você espera.

Pontos de atenção

  • Transferência direta ignora o limite. Se outro agente transferir manualmente um atendimento para alguém que já está no limite, a transferência é concluída mesmo assim.
  • Atendimento travado ignora o limite. Um atendimento travado com o agente (trava de atendimento) pode ser entregue a ele mesmo que ultrapasse o limite da fila e do agente.
  • Agente preferencial ignora o limite. Se o contato tem um agente preferencial disponível, o atendimento vai para ele mesmo que esteja no limite.
  • Confirme se a opção que aplica o limite ao puxar está realmente marcada — é comum o número estar preenchido, mas a aplicação dele estar desativada.
  • Ajustar apenas o limite do agente pode não resolver se o limite configurado na fila continuar permissivo, e vice-versa: os dois valores agem em conjunto.

Se não resolver

Se mesmo com o limite corretamente configurado, a opção de aplicação ativada e nenhuma das exceções acima envolvida (sem transferência direta, sem trava, sem agente preferencial) o agente continuar recebendo atendimentos genuinamente novos acima do limite, reúna o protocolo dos atendimentos excedentes, o horário exato e os valores configurados de limite do agente e da fila antes de acionar o suporte.

Como configurar e resolver falhas de conectividade na integração com o Fórmula Certa?

Resumo

A integração com o Fórmula Certa é habilitada pelo suporte para a sua instância e depende de conectividade direta entre o servidor do sistema e o banco de dados do Fórmula Certa no ambiente do seu cliente. Quando a integração para de funcionar do nada, a causa quase sempre é de rede do lado de quem hospeda o Fórmula Certa: IP alterado, porta bloqueada no firewall ou falha no DDNS.

Quando se aplica

  • Você quer confirmar se o recurso Fórmula Certa está habilitado na sua instância.
  • A busca de orçamento pelo Fórmula Certa parou de funcionar, mesmo já tendo funcionado antes.
  • Você precisa liberar acesso de rede pela primeira vez para configurar a integração.

Passo a passo

  1. Confirme se o recurso está habilitado. Na tela de atendimento, digite / na caixa de mensagem: se a opção Busca orçamento aparecer, o recurso está habilitado para a sua instância. Se não aparecer, acione o suporte para habilitar.
  2. Reúna os dados de conexão com o suporte. Peça o IP (ou endereço DDNS) e a porta configurados para acessar o banco de dados do Fórmula Certa a partir do sistema. Essa porta costuma ser a 3050, padrão do banco usado pelo Fórmula Certa, mas confirme sempre o valor exato com o suporte, pois pode variar.
  3. Libere o acesso no firewall do ambiente do Fórmula Certa. Peça ao time de T.I. responsável pelo servidor do Fórmula Certa que libere, na porta informada, o IP do servidor do sistema.
  4. Confirme o DDNS, se for o caso. Se o acesso usa um endereço de DNS dinâmico em vez de um IP fixo, confirme que esse endereço está resolvendo para o IP atual do ambiente do Fórmula Certa.
  5. Teste a conectividade antes de acionar o suporte novamente. Peça ao seu T.I. um teste de conexão na porta liberada (por exemplo, um teste de porta/telnet) a partir do IP do sistema. Se o teste falhar, o bloqueio está do lado da rede do Fórmula Certa, não do sistema.

Pontos de atenção

  • Apenas um IP por vez. A configuração da integração aceita um único endereço de conexão. Não é possível cadastrar dois IPs simultaneamente; se a rede do cliente usa IP dinâmico, a solução é usar DDNS em vez de tentar liberar múltiplos IPs.
  • Não há tela de configuração para o cliente. A habilitação e os dados técnicos da integração (host, porta, caminho do banco) são configurados pelo suporte, não por uma tela que o administrador da conta acessa sozinho.
  • Coexiste com outras integrações. Habilitar o Fórmula Certa não interfere em outras integrações já configuradas na mesma instância, como uma integração com intranet — elas funcionam de forma independente.
  • Causa mais comum de parada repentina. Quando uma integração que já funcionava passa a falhar, o motivo mais frequente é alguma mudança na rede do cliente (troca de roteador, novo IP, regra de firewall alterada) ou o DDNS parando de resolver corretamente.
  • Cache local. Em alguns casos pontuais, limpar o cache do navegador e recarregar a página resolve problemas de exibição da busca de orçamento sem envolver a rede.

Se não resolver

O suporte não tem acesso a logs internos dessa integração para acelerar o diagnóstico — o teste de porta feito pelo seu T.I. é o que confirma se o bloqueio é de rede. Antes de acionar o suporte novamente, reúna: o resultado do teste de porta, o IP/endereço atual do ambiente onde o Fórmula Certa está hospedado, e se houve alguma mudança recente de rede, roteador ou provedor de internet no ambiente do cliente.

É possível liberar acesso direto ao banco de dados da instância para terceiros?

Resumo

Não. O sistema não fornece credenciais de conexão (usuário, senha, host, banco) nem libera acesso direto ao banco de dados de nenhuma instância para sistemas ou desenvolvedores externos — é uma política de segurança de dados, sem exceção. Para consumir os dados da instância de forma estruturada fora do sistema, a alternativa oferecida é a integração com o BigQuery.

Quando se aplica

  • Um parceiro, desenvolvedor ou fornecedor pediu usuário, senha, host e nome do banco de dados da sua instância.
  • Pediram para liberar o IP de um servidor externo para conectar direto ao banco.
  • Você precisa consumir dados da instância (atendimentos, contatos, tickets etc.) em outro sistema, de forma estruturada e recorrente.

Passo a passo

  1. Peça a habilitação da integração com o BigQuery. Abra um chamado com o suporte solicitando a integração, e tenha em mãos um Project ID de um projeto seu no Google Cloud onde os dados serão replicados.
  2. Configure o Project ID. Um administrador acessa Configurações > Geral, localiza a seção Integração BigQuery e preenche o campo ProjectID do BigQuery.
  3. Consulte os dados pelo BigQuery. A partir da sincronização, seu parceiro ou desenvolvedor consulta os dados diretamente no seu projeto BigQuery, com as ferramentas de sua preferência — sem qualquer acesso ao banco de dados original da instância.

Pontos de atenção

  • Credenciais de banco de dados não são fornecidas em nenhuma hipótese, mesmo para desenvolvedores de confiança do cliente ou parceiros já homologados.
  • Em casos pontuais, o suporte pode informar apenas o IP da própria instância para que um fornecedor externo o libere do lado dele — isso não abre acesso ao banco, apenas permite que a instância se conecte a um serviço de terceiros (por exemplo, uma API do parceiro).
  • Registros atualizados são reinseridos no BigQuery; registros excluídos localmente na instância não são removidos automaticamente do BigQuery pela integração — considere isso ao construir consultas ou relatórios sobre esses dados.
  • A configuração do Project ID exige perfil de administrador e um projeto próprio do cliente no Google Cloud.

Se não resolver

Se a sincronização do BigQuery não atender sua necessidade (por exemplo, você precisa de dados em tempo real ou de alguma informação que não é replicada), abra um chamado descrevendo exatamente quais dados e com que frequência o sistema externo precisa consumir, para o suporte avaliar alternativas.

Como formatar os campos clientId e number nas chamadas de API de mensagem?

Resumo

Nas chamadas de API que enviam mensagem ou consultam atendimentos de um contato, o campo number é o telefone do cliente (DDD + número) e o campo clientId é o identificador do atendimento/conversa daquele contato no canal — não é o mesmo ID usado no cadastro de contatos. Sempre que o endpoint aceitar os dois, prefira informar apenas o number: o sistema completa e valida automaticamente o formato do número brasileiro.

Quando se aplica

  • Você está integrando via API (envio de mensagem, consulta de atendimentos abertos, consulta de histórico de um contato) e não sabe o que colocar em clientId ou number.
  • Sua chamada retorna lista vazia ou erro mesmo enviando um clientId que parece correto.
  • Você quer saber se clientId é o mesmo campo usado para identificar um contato no CRM.

Passo a passo

  1. Prefira sempre o campo number quando o endpoint aceitar. Informe apenas os dígitos do telefone do cliente (DDD + número). Você pode enviar com ou sem o código do país (55) e com ou sem o nono dígito — para números brasileiros o sistema tenta as variações automaticamente e valida o formato.
  2. Use clientId apenas quando já tiver esse valor em mãos (por exemplo, recebido em um webhook anterior ou em uma resposta de outro endpoint da API), não tente montá-lo manualmente a partir do número do cliente.
  3. Não confunda clientId com o ID do cadastro de contato. Se sua integração precisa buscar, criar ou editar um contato no CRM, use o campo de identificação do contato dos endpoints de contato — ele é um valor numérico próprio, diferente do clientId usado nos endpoints de mensagem/atendimento.
  4. Se for consultar por clientId e a fila for oficial (WhatsApp Cloud API), o valor esperado é apenas o número, sem qualquer sufixo.
  5. Se for consultar por clientId e a fila for WhatsApp não oficial, o valor esperado inclui o sufixo @s.whatsapp.net depois do número.
  6. Confira a chave de autenticação da fila (apikey) usada na chamada em Configurações > Filas, selecionando a fila e abrindo a aba API e Webhooks.

Pontos de atenção

  • clientId não é o ID do contato do CRM. É o identificador da conversa/canal daquele contato, derivado do número de telefone (e não o valor numérico interno usado para buscar, criar ou editar um cadastro de contato).
  • O formato do clientId muda conforme o tipo de canal. Fila oficial (Cloud API): só o número, sem sufixo. Fila de WhatsApp não oficial: número seguido de @s.whatsapp.net. Enviar o formato errado para o tipo de fila resulta em lista vazia ou "não encontrado", mesmo com o número correto.
  • Quando o endpoint aceita number e clientId ao mesmo tempo, normalmente só um dos dois é efetivamente usado para localizar o contato — evite enviar os dois com valores diferentes, pois isso pode gerar resultado inesperado. Se possível, envie apenas o campo que você tem certeza do valor.
  • number não exige o 55 na frente. Para números brasileiros, DDD + número (com ou sem o nono dígito) já é aceito; o sistema completa o formato automaticamente ao processar.
  • Se você monta o clientId manualmente a partir do número do cliente (por exemplo, tirando o nono dígito ou acrescentando o sufixo por conta própria), o risco de errar o formato é maior — sempre que possível, prefira number ou reaproveite um clientId já recebido do próprio sistema em uma resposta anterior.

Se não resolver

Se a chamada continuar retornando lista vazia ou "não encontrado", reúna: o endpoint chamado, o payload enviado (sem a chave de autenticação), a resposta recebida, o tipo do canal (WhatsApp oficial ou não oficial) e o ID da fila usada, e acione o suporte com essas informações.

Como remover ou editar o R$ (símbolo de moeda) da mensagem de orçamento antes de enviar?

Resumo

Quando o sistema gera automaticamente o texto de uma mensagem a partir de uma integração (como uma busca de orçamento), o texto é aberto em uma caixa de edição antes de ser enviado ao cliente. Você pode editar livremente esse texto — inclusive remover o símbolo de moeda ou qualquer outro trecho — antes de clicar em enviar. Não existe uma configuração permanente do sistema para mudar o formato desse texto de uma vez por todas: a edição precisa ser feita mensagem por mensagem.

Quando se aplica

  • Você usa, na caixa de mensagem do atendimento, um atalho/comando que busca dados (como um orçamento) e monta automaticamente um texto para enviar ao cliente.
  • O texto gerado vem com um formato (por exemplo, o símbolo "R$" antes do valor) que você gostaria de mudar ou remover.
  • Você quer saber se dá para personalizar permanentemente esse texto para todas as próximas mensagens.

Passo a passo

  1. Gere a mensagem. No atendimento, use o atalho de busca correspondente na caixa de mensagem, informe os dados pedidos (por exemplo, os identificadores do orçamento) e confirme a busca.
  2. Abra a edição do texto. Com os dados retornados na tela, clique na opção que gera a mensagem. O sistema abre uma janela Editar mensagem com um campo de texto contendo a mensagem completa que seria enviada.
  3. Edite o texto livremente. Nesse campo você pode apagar, reescrever ou remover qualquer parte do texto, incluindo símbolos de moeda, antes de enviar.
  4. Envie. Clique em Enviar para que o texto editado (e não o texto original gerado) seja a mensagem efetivamente entregue ao cliente.

Pontos de atenção

  • A edição vale apenas para aquela mensagem. Da próxima vez que a mensagem for gerada a partir dos dados da integração, o texto volta a vir no formato original — não há campo de configuração do sistema para alterar permanentemente o modelo desse texto.
  • Esse recurso de geração automática de mensagem a partir de uma busca de orçamento é uma integração específica, habilitada apenas para as contas que a contrataram. Se o atalho não aparecer na sua caixa de mensagem, esse recurso não está habilitado na sua conta.
  • Se o campo de texto ficar vazio, o botão Enviar permanece desabilitado — é preciso manter algum conteúdo na mensagem.
  • Para textos que o sistema envia automaticamente sem intervenção do agente (como mensagens de automações/URA), a personalização é feita na configuração do próprio fluxo de automação, não nesta janela de edição.

Se não resolver

Se o atalho de busca de orçamento não aparece para você, confirme com o administrador se essa integração está habilitada na sua conta. Se o texto gerado vier com dados incorretos (não apenas de formatação), reúna o identificador do orçamento consultado e a filial informada antes de acionar o suporte.

Quais erros aparecem ao usar a assistência remota em um atendimento?

Resumo

Durante um atendimento, o ícone "Assistência remota" no cabeçalho do chat abre um menu para iniciar uma sessão de suporte/assistência remota com o cliente. Se a opção não aparecer ou uma tentativa falhar, o sistema mostra uma mensagem específica: falta de licença ou de habilitação na fila, sessão já em andamento, ou o cliente não está no ambiente esperado (aplicativo desktop ou página com o chat incorporado). Este artigo lista o que cada mensagem significa.

Quando se aplica

  • O ícone de assistência remota não aparece no cabeçalho do atendimento.
  • Ao clicar em "Iniciar suporte remoto" ou "Iniciar assistência remota", aparece uma mensagem de erro em vez de a sessão começar.
  • Um agente convidado (que não é o titular do atendimento) tenta iniciar a sessão.
  • A sessão de suporte remoto cai ou não pode mais ser retomada.

Limites e regras

  • Somente usuários com perfil Agente têm acesso à funcionalidade de assistência/suporte remoto.
  • O usuário precisa ter uma licença de suporte remoto atribuída à sua conta; sem ela, o ícone de assistência remota não aparece no cabeçalho do chat.
  • A fila do atendimento precisa ter a assistência/suporte remoto habilitado. Em Configurações > Filas, na aba "Assistência / Suporte remotos" da fila, o campo "Assistência / Suporte remoto" define isso, com as opções: Desabilitar, Habilitar todos os tipos, Habilitar somente suporte remoto e (para os tipos de fila que suportam, como Web Chat) Habilitar somente assistência remota.
  • Somente o agente titular do atendimento pode iniciar uma sessão de suporte ou assistência remota — um agente convidado no chat não consegue.
  • Um agente só pode ter uma sessão de suporte/assistência remota ativa por vez; não é possível abrir uma segunda sessão em outro atendimento enquanto a primeira está em andamento.
  • A assistência remota tem dois modos, cada um com um pré-requisito do lado do cliente: controle do aplicativo desktop (o cliente precisa estar usando o app) ou assistência em página (o cliente precisa estar com o chat incorporado na própria página, modo de compartilhamento de tela do navegador).
  • A tela de configuração da fila também permite habilitar a gravação das sessões remotas e disparar uma automação ao iniciar ou ao encerrar a sessão.

Pontos de atenção

  • O botão de assistência remota só aparece para atendimentos de canais compatíveis com a funcionalidade (por exemplo, Webchat); em outros canais o ícone simplesmente não é exibido.
  • Perder a licença de suporte remoto (por exemplo, se ela for removida do usuário) faz o ícone desaparecer do cabeçalho sem gerar mensagem de erro — é preciso verificar o cadastro do usuário.

Se não resolver

Confirme, nesta ordem: se o usuário tem perfil Agente e licença de suporte remoto atribuída; se a fila do atendimento tem a assistência/suporte remoto habilitado e, se aplicável, se o tipo certo de assistência está liberado para aquele tipo de fila; se o agente já não tem outra sessão remota ativa em outro atendimento; e, no lado do cliente, se ele está no ambiente esperado (app desktop ou chat incorporado na página). Se tudo isso estiver correto e o erro persistir, acione o suporte informando a mensagem exata exibida e o horário da tentativa.

O que é a Assistência Remota e como o agente inicia o controle da tela do cliente?

Resumo

A Assistência Remota deixa o agente ver a tela do computador do cliente durante um atendimento e, se escolher esse modo, também controlar o mouse e o teclado dele. O agente inicia pelo ícone de assistência remota no cabeçalho do atendimento, escolhe entre "Somente visualizar" ou "Visualizar e controlar", e o cliente precisa aceitar o pedido antes da sessão começar. O recurso só existe em atendimentos de filas WebChat V2 e exige uma licença de suporte remoto atribuída ao agente.

Quando se aplica

  • O agente precisa orientar o cliente visualizando a tela dele em tempo real.
  • O agente precisa executar uma ação diretamente no computador do cliente (preencher um campo, clicar em um botão, navegar até uma tela).
  • O ícone de assistência remota não aparece no cabeçalho do atendimento.
  • Entender a diferença entre "Somente visualizar" e "Visualizar e controlar".

Passo a passo

  1. Abra o atendimento. Dentro de um atendimento ativo de uma fila WebChat V2, localize o ícone de assistência remota no cabeçalho do chat (dica "Assistência remota").
  2. Abra o menu. Clique no ícone e escolha a opção "Iniciar assistência remota".
  3. Escolha o modo. No diálogo "Assistência remota", selecione "Somente visualizar" (você vê a tela, mas não controla mouse/teclado) ou "Visualizar e controlar" (você vê e controla mouse e teclado do cliente).
  4. Inicie a sessão. Clique em "Iniciar". O sistema lembra sua última escolha de modo para a próxima vez.
  5. Aguarde o aceite do cliente. O cliente recebe o pedido de acesso e precisa aceitar antes da tela aparecer para o agente; ele pode interromper a sessão a qualquer momento pelo lado dele.
  6. Durante a sessão. É possível minimizar a janela da sessão (ela e a gravação, se habilitada, continuam em segundo plano), silenciar o áudio do computador remoto, trocar de monitor quando o cliente tem mais de um, e trocar arquivos e área de transferência com o cliente.

Limites e regras

  • Só está disponível em atendimentos de filas do tipo WebChat V2 — não existe em outros canais (WhatsApp, e-mail, Instagram, telefonia, etc.).
  • A fila precisa ter a assistência remota habilitada na aba "Assistência / Suporte remotos" do cadastro da fila (opção "Habilitar todos os tipos" ou "Habilitar somente assistência remota").
  • O agente precisa ter uma licença de suporte remoto atribuída. O administrador atribui a licença em Configurações > Licenças, pelo botão "Atribuir licença"; uma licença atribuída fica vinculada ao agente por no mínimo 5 dias antes de poder ser removida.
  • Só o titular do atendimento pode iniciar a assistência remota — um agente que só está acompanhando o atendimento (convidado) não vê a opção habilitada.
  • Enquanto o agente já tem uma sessão de assistência (ou suporte) remota ativa, a opção "Iniciar assistência remota" fica indisponível no menu até essa sessão ser encerrada.
  • A gravação das sessões de assistência remota é uma opção configurável por fila (Habilitar/Desabilitar) na mesma aba "Assistência / Suporte remotos"; quando habilitada, a gravação continua mesmo se o agente minimizar a janela da sessão.
  • É possível vincular automações que disparam automaticamente ao iniciar e ao encerrar uma sessão de assistência remota, configuradas na mesma aba da fila.
  • A fila pode ter um texto de "Termos de Uso" configurado, exibido ao cliente no início da sessão remota.

Pontos de atenção

  • Existem dois modos técnicos por trás da mesma ação "Iniciar assistência remota": acesso ao aplicativo desktop do cliente, ou uma sessão embutida na própria página do cliente (co-navegação). O sistema escolhe automaticamente qual modo usar de acordo com como o cliente está conectado — o agente não escolhe isso, só escolhe entre visualizar e controlar.
  • No modo embutido na página do cliente, o botão de iniciar só fica disponível depois que o navegador do cliente sinaliza que está pronto para a sessão; pode haver um pequeno atraso até o ícone habilitar.
  • Se o ícone de assistência remota não aparecer, confirme a licença do agente, a configuração da fila e se a janela do chat está larga o suficiente para exibir os ícones do cabeçalho.
  • Este recurso é diferente do "Suporte remoto" tradicional (acesso por vídeo/tela), que aparece como uma opção separada no mesmo menu quando habilitado para a fila.

Se não resolver

Confirme, nesta ordem: se a fila do atendimento é WebChat V2, se a aba "Assistência / Suporte remotos" da fila está habilitada, se o agente tem licença de suporte remoto atribuída em Configurações > Licenças, e se o agente é o titular do atendimento (não um convidado). Se tudo isso estiver correto e o ícone ainda não aparecer, ou o cliente não conseguir aceitar o pedido, reúna o horário aproximado da tentativa, o nome da fila e o navegador/aplicativo usado pelo cliente antes de acionar o suporte.

Como instalar e configurar uma extensão nesta instância?

Resumo

A instalação de extensões fica em Configurações > Extensões instaladas e é restrita às contas internas da operação (os perfis 98 e 99). Instalar tem duas etapas: informar o endereço do manifest publicado pelo fornecedor e, depois que o sistema lê esse manifest, preencher o nome da instalação, os campos de configuração que a própria extensão declara e o filtro de quem recebe. Valores marcados como segredo são gravados cifrados e nunca mais podem ser lidos — só substituídos. Se a extensão mostra páginas de outros sites, a lista desses sites aparece antes de instalar.

Quando se aplica

  • O fornecedor entregou o endereço de uma extensão e você precisa colocá-la em uso na instância.
  • Precisa alterar a configuração, o público ou a chave de uma extensão já instalada.
  • Quer instalar a mesma extensão duas vezes — uma para produção e outra para teste.
  • Precisa desligar uma extensão temporariamente sem perder a configuração.
  • Um Administrador comum reclama que não encontra a tela de extensões.
  • O fornecedor avisou que a extensão não consegue mais guardar dados e você precisa saber qual é o espaço disponível.
  • Quer saber de quais sites uma extensão mostra conteúdo dentro do sistema.

Passo a passo

  1. Abra a tela. Vá em Configurações > Extensões instaladas. O item só aparece para os perfis 98 e 99.
  2. Inicie a instalação. Clique em Instalar extensão.
  3. Informe o endereço. Preencha URL do manifest com o endereço que o fornecedor passou. Ele precisa apontar direto para o arquivo do manifest, sem redirecionamentos. Clique em Buscar manifest.
  4. Confira a identificação. O sistema mostra nome, versão, descrição, fornecedor e quantos pontos de montagem a extensão declara. Se o endereço estiver errado, use Trocar URL. Se a extensão mostra páginas de outros sites (um painel do Looker Studio ou do Power BI, por exemplo), aparece também o quadro Páginas de outros sites, com a lista desses sites: confira se são os esperados antes de continuar.
  5. Dê um nome à instalação. Preencha Nome da instalação. É o que distingue duas instalações da mesma extensão — por exemplo "Financeiro (produção)" e "Financeiro (teste)". Esse nome aparece só para a administração.
  6. Preencha a configuração. Em Configuração da extensão aparecem os campos que a própria extensão pediu: texto, número, endereço, lista de opções, chave/liga-desliga e segredos. Os obrigatórios são marcados com asterisco. Se a extensão não pedir nada, a seção informa isso. Quando a extensão mostra um relatório externo, é comum ela pedir aqui o identificador ou o endereço do relatório do seu cliente.
  7. Defina quem recebe. Em Quem recebe esta extensão, monte as listas de inclusão e exclusão. Veja o artigo "Como definir quais usuários recebem uma extensão (inclusão e exclusão)".
  8. Decida o compartilhamento. Em Compartilhamento entre instalações, deixe Compartilhar armazenamento e Compartilhar canal de mensagens desligados, que é o padrão e a opção segura.
  9. Conclua. Clique em Instalar. Para alterar depois, use o botão Configurar na linha da instalação e finalize em Salvar.

Limites e regras

  • A tela é restrita aos perfis 98 e 99, e o servidor recusa qualquer operação de extensão vinda de outro perfil, inclusive as de leitura. Um Administrador comum não vê a tela, não instala, não remove e não consegue ler nem alterar a configuração local.
  • Campos de segredo nunca voltam em leitura, nem nesta tela nem por consulta externa. Com um valor já guardado, deixar o campo como está mantém o valor; digitar um novo substitui. Segredos não obrigatórios podem ser apagados pelo botão da borracha, e a exclusão só é efetivada ao salvar.
  • Quando um segredo é gravado, ele não é mais exibido. Guarde uma cópia em local seguro antes de salvar.
  • O endereço informado precisa ser um endereço direto do manifest. O servidor que hospeda a extensão precisa devolver o cabeçalho Access-Control-Allow-Origin; sem isso a instalação é recusada com essa explicação na própria tela.
  • O nome da instalação é obrigatório e aceita até 255 caracteres.
  • Campos de endereço precisam começar por http:// ou https://.
  • Espaço para os dados que a extensão guarda: cerca de 262 mil caracteres, somando o nome e o conteúdo de todas as entradas guardadas. Esse espaço é de cada usuário em cada instalação — não é um bolo único dividido entre a equipe, e um agente que enche o próprio espaço não tira lugar de ninguém. Ao atingir o teto, aquela extensão deixa de conseguir gravar para aquele usuário até que algo seja apagado.
  • A mesma extensão pode ser instalada mais de uma vez. Por padrão, cada instalação tem armazenamento e canal isolados — a etiqueta Isolada na lista indica isso.
  • Avisos do manifest não impedem a instalação: o ponto de montagem afetado simplesmente não aparece para os usuários.
  • Uma extensão só consegue mostrar páginas dos sites listados no quadro Páginas de outros sites, no máximo 10, sempre com endereço seguro (https). O endereço do próprio sistema nunca aparece nessa lista.

Pontos de atenção

  • Quando uma operação é recusada, a mensagem do servidor aparece inteira numa faixa vermelha no topo da tela ou do formulário. Ela diz exatamente o que falta — leia antes de repetir a tentativa.
  • Ligar Compartilhar armazenamento faz todas as instalações da mesma extensão lerem e gravarem os mesmos dados. É o que impede uma instalação de teste de mexer nos dados da instalação de produção; mantenha desligado a menos que o fornecedor exija.
  • Com o armazenamento compartilhado ligado, as instalações da mesma extensão passam a dividir também o mesmo teto de espaço, sempre dentro do espaço daquele usuário.
  • Os dados guardados pela extensão ficam no navegador de cada usuário: quem entra de outro computador ou de outro navegador começa com o espaço vazio, e uma limpeza de dados do navegador apaga o que estava guardado. O que precisa sobreviver a isso é responsabilidade do sistema do fornecedor.
  • Na lista, o botão de sincronizar reconsulta o manifest no fornecedor e atualiza a versão em uso; a coluna Verificado em mostra quando isso foi feito pela última vez. Uma versão nova do fornecedor pode trazer uma lista diferente de sites externos; a lista em vigor aparece ao abrir Configurar.
  • Para desligar sem perder a configuração, use o botão de habilitar/desabilitar em vez de remover.
  • Remover é definitivo: apaga a configuração local, os segredos guardados e o token do canal, e os usuários deixam de receber a extensão imediatamente. A confirmação mostra o nome da instalação antes de executar.

Se não resolver

Se a busca do manifest falhar, confirme com o fornecedor se o endereço aponta direto para o arquivo e se o servidor dele devolve o cabeçalho exigido — a faixa de erro traz o diagnóstico. Se a instalação concluir mas a extensão ficar como Desabilitada, veja o artigo "Por que uma extensão instalada aparece como Desabilitada e o que fazer". Se ela ficar Habilitada mas ninguém a enxergar, o problema é o filtro de entrega: veja "Como definir quais usuários recebem uma extensão (inclusão e exclusão)". Se um item que mostra um relatório externo não aparece, confira se o campo de configuração que o fornecedor pediu para esse relatório está preenchido; para página em branco, veja "O que uma extensão consegue fazer no sistema e quais são os limites?". Se o fornecedor relatar falha ao guardar dados, confira o teto de espaço acima antes de abrir chamado — e confirme se o problema atinge todos os usuários ou apenas um, já que o espaço é individual. Ao acionar o suporte, informe o nome da instalação e o texto exato da mensagem de erro exibida na tela.
