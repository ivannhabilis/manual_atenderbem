CRM e Funil de Vendas

Gerencie oportunidades de negócio, visualize o funil de vendas e acompanhe os valores envolvidos.

1. Visão geral

O módulo CRM (Customer Relationship Management) concentra o acompanhamento de oportunidades comerciais. Ele é indicado para equipes de vendas que usam a plataforma também para fechar negócios, além do atendimento.

2. Seletor de funil (Sales funnel)

No topo, o seletor Sales funnel permite escolher o funil exibido. Ao lado foram observados um ícone de engrenagem e um botão circular +. A captura não permitiu confirmar os fluxos acionados por esses controles.

3. Cartões de métricas

Cinco indicadores resumem a saúde do funil selecionado:

MétricaSignificado
OpportunitiesQuantidade de oportunidades no funil.
Total valueValor total das oportunidades.
Expected valueValor esperado (ponderado pela probabilidade).
Total recurringTotal de receita recorrente.
Expected recurringReceita recorrente esperada.

4. Área de oportunidades

A área principal mostra as oportunidades do funil. Quando não há dados, a tela aparece vazia (como no ambiente de exemplo capturado). À direita, ícones permitem alternar a visualização e há uma barra de Search para localizar rapidamente uma oportunidade.

Dica: se a tela estiver vazia, verifique se o Sales funnel correto está selecionado — funis diferentes mostram conjuntos diferentes de oportunidades.
Relacionado: o Carrinho Sincronizado transforma o carrinho de produtos de um atendimento em uma oportunidade de CRM sincronizada ao vivo. Quando uma fila está configurada para isso, cada carrinho ativo vira uma oportunidade no funil escolhido, na etapa "carrinho aberto".

5. Integração do CRM com sistemas externos (ERP)

O CRM pode ser integrado a sistemas externos — tipicamente um ERP — para que as duas plataformas trabalhem com o mesmo dado. A base tecnológica da integração é formada por automações, Requisição HTTP, Código JS, Capturas de Webhook e a API nativa. O objetivo é manter consistência das informações, rastreabilidade das oportunidades e autonomia para construir integrações sob medida.

5.1. Automações: por evento e periódicas

  • Baseadas em eventos: fluxos de automação acionados instantaneamente por eventos da oportunidade — Ganho, Perda, Atraso, Entrada ou Saída de Etapa e Estagnação.
  • Periódicas: execuções recorrentes sobre as oportunidades de um funil específico. Ficam em Configurações › Automação › Automação com Contatos e Oportunidades, onde se agenda o fluxo para rodar em intervalos predefinidos.

5.2. Ferramentas de transferência de dados

Dentro dos fluxos de automação, quatro recursos se combinam para mover dados entre o CRM e o sistema externo:

FerramentaO que fazOnde fica
Requisição HTTP Envia ou busca informações de forma dinâmica em sistemas externos, dentro do fluxo. Elemento do fluxo de automação.
Código JS (JavaScript) Cria, manipula e reestrutura variáveis do sistema ou dados recebidos nas requisições. Elemento do fluxo de automação.
Captura de Webhook Gera uma URL exclusiva que o sistema externo chama para enviar dados em tempo real; o CRM processa e executa o fluxo vinculado à captura. Configurações › Automação › Captura de Webhook.
API nativa Endpoints dedicados às operações do CRM (criar, editar, atualizar status, anexos, entre outras). Filas › Documentação da API.

5.3. Exemplo prático: sincronização CRM ⇄ ERP

Arquitetura sugerida para manter o CRM e o ERP do cliente atualizados simultaneamente.

Chave de associação única (o passo fundamental): antes de tudo, os dois sistemas precisam saber que tratam da mesma informação. É indispensável ter um dado único registrado nas duas plataformas para o cruzamento. A prática mais comum é criar um campo no ERP para guardar o ID da Oportunidade gerado no CRM — e vice-versa.

Fluxo 1 — Do CRM para o ERP

  • Atualizações por evento (tempo real): nos fluxos de Ganho ou Perda, configurar uma Requisição HTTP para o endpoint correspondente na API do ERP. Ao ganhar uma oportunidade no CRM, o sistema envia o ID e o novo status, atualizando ou fechando o negócio no ERP automaticamente.
  • Sincronização periódica (varredura inteligente): um fluxo diário garante a consistência. Para não atualizar dados desnecessariamente, a automação usa uma Requisição HTTP para buscar o registro no ERP e, em seguida, Código JS para comparar as informações entre os sistemas. Se o script identificar divergências, monta o payload no formato que o ERP exige e dispara a atualização apenas para os dados que realmente mudaram.

Fluxo 2 — Do ERP para o CRM

O caminho inverso depende das tecnologias de saída (API ou webhook) disponíveis no ERP. Se o ERP tiver automações acionadas por eventos, ele pode enviar os dados de duas formas:

  1. Via API: realizando operações (criar, editar ou atualizar status) diretamente nos endpoints da API do CRM.
  2. Via Webhook: disparando a atualização para a URL da Captura de Webhook. Ao receber a notificação, o CRM processa as informações e executa as ações definidas no fluxo de automação vinculado àquela captura.

5.4. Atribuição de responsáveis

Para oportunidades que já têm um responsável definido no ERP, é possível espelhar essa associação no momento em que a oportunidade é criada ou atualizada no CRM: basta preencher o campo de responsável com o ID do usuário correspondente na plataforma — seja via endpoint da API ou por inserção manual.

5.5. Envio de arquivos (anexos)

Quando o ERP precisa enviar documentos que serão associados a uma oportunidade, a sequência de integração via API recomendada é:

  1. Usar o endpoint uploadFile para subir o documento e gerar o ID único do arquivo no CRM.
  2. Chamar o endpoint getOpportunity para recuperar a lista atual de arquivos já associados àquela oportunidade.
  3. Acrescentar o novo ID de arquivo à lista recuperada.
  4. Enviar a lista de IDs atualizada pelo endpoint updateOpportunity, consolidando o novo anexo na oportunidade.
Em resumo: Requisições HTTP, Código JS, Capturas de Webhook e a API nativa formam a base que permite integrar o CRM a qualquer sistema externo compatível com APIs — com o parceiro no controle da lógica de sincronização.

6. Cartões de Informação no painel do agente

Os Cartões de Informação são estruturas visuais que enriquecem o painel de atendimento do agente. Com eles é possível trazer dados detalhados e dinâmicos — informações financeiras, dados de contato, status de oportunidades do CRM — diretamente para a tela do agente, vinculados a um atendimento inteiro ou a uma mensagem específica.

6.1. Acesso e criação

  1. Acesse Configurações › Cadastros › Cartões de Informação.
  2. Clique em + Adicionar, no canto superior direito.
  3. O sistema cria um cartão padrão chamado "Novo cartão de informação".
  4. Boa prática: edite e renomeie o cartão imediatamente com um título claro e descritivo (ex.: "Cartão — Resumo Financeiro") — isso evita confusão na listagem quando houver dezenas de cartões.

6.2. Segurança e grupos de visualização

É possível restringir quem vê as informações de um cartão, protegendo dados sensíveis (faturas, cobranças) de agentes não autorizados:

  • Na tela de configuração do cartão, localize o campo Grupo de visualização e selecione um grupo específico (ex.: "Equipe Financeira").
  • Somente os agentes que tiverem esse mesmo grupo atrelado ao próprio perfil (Configurações › Usuários) enxergarão o cartão durante o atendimento.

6.3. Gerenciamento na listagem principal

Na listagem dos cartões, a coluna de funções traz atalhos práticos:

AçãoO que faz
EditarAbre o construtor visual do cartão.
Copiar EstruturaCopia o código JSON do cartão para a área de transferência.
Clonar CartãoCria uma cópia exata do cartão dentro do próprio painel.
ExportarExporta a estrutura do cartão para importá-la em outros clientes/instâncias, economizando tempo e evitando recadastros manuais.
ExcluirRemove o cartão permanentemente.

6.4. Construindo o layout (o editor visual)

No modo de edição, os componentes ficam disponíveis como elementos arrastáveis no painel lateral esquerdo. Ao clicar em um elemento inserido, o painel de configurações abre à direita, dividido entre propriedades comuns e parâmetros específicos.

Propriedades comuns (globais)

Praticamente todos os elementos de conteúdo e blocos de estrutura compartilham as mesmas configurações, para garantir harmonia visual:

  • Alinhamento: posicionamento horizontal no grid (Esquerda, Centro ou Direita).
  • Margens (espaçamento interno/externo): recuos em pixels (px) para que as informações não fiquem coladas umas nas outras nem nas bordas do cartão.
  • Visibilidade condicional / variáveis de renderização: campo que aceita condicionais — o elemento só é exibido se a variável mapeada possuir dados ou corresponder ao critério definido.

Elementos de conteúdo

Os elementos disponíveis no construtor e o tipo de propriedades de cada um:

ElementoPara que servePropriedades principais
Texto Títulos, parágrafos ou rótulos, com dados fixos ou dinâmicos. Conteúdo/Valor (aceita chaves duplas, ex. {{cards_nome}}); ajustes da fonte (escala em px, peso, cor); cor de fundo (ex.: vermelho para alertas).
Etiqueta (Label) Exibir status ou categorias com destaque (ex.: "Inadimplente"). Texto da etiqueta (rótulo ou variável); ícone (ex.: icon-far-star).
Botão Interatividade na tela do atendimento, disparando ações externas ou internas. Título/Label; Tipo de ação; estilo do botão. Ver tipos de ação abaixo.
Link Aplicar hiperlink em uma linha de texto, para redirecionamentos discretos (ex.: "Acesse os termos de uso"). Texto (fixo ou variável, ex. Visualizar Fatura #{{cards_id_fatura}}); URL (fixa ou dinâmica, ex. {{cards_link_boleto}}); ajustes da fonte.
Ícone Sinalizações visuais rápidas ao lado de textos ou em seções isoladas. Ícone (biblioteca Font Awesome, ex. icon-far-home, ou emoji); ajustes do ícone (escala em px, cor aplicada às linhas do vetor).
Rótulo: Valor (KeyValue) Par título fixo à esquerda e valor à direita — ideal para fichas cadastrais (ex.: "CPF: 123.456..."). Título (rótulo, ex. "RG:"); Valor (recomendado usar variável dinâmica, ex. MG {{cards_documento}}); ajustes do rótulo (tamanho, espaçamento, cores).
Avatar Renderizar fotos de perfil, logotipos ou ícones informativos. URL da imagem (ou variável, ex. {{cards_foto_cliente}}); tamanho (largura e altura); formato de exibição (ex.: Quadrada); fallback (iniciais, cor da fonte e fundo sem imagem).
Lista Dados sequenciais (ex.: histórico de últimas faturas). Itens (ex.: "Instalação da Internet" ou {{cards_item}}); ajustes da fonte.
Progresso (Progress Bar) Barra horizontal para metas, limites de crédito consumidos ou andamento de etapas de um projeto/ticket. Valor (preenchimento atual, ex. {{cards_porcentagem}}); ajustes da barra (cor de preenchimento ativo, cor da trilha restante).
Avaliação (Estrelas) Transformar uma nota em sequência de estrelas — satisfação ou classificação do cliente. Valor (fixo ou variável, ex. {{cards_nota_nps}}); quantidade de estrelas (escala máxima, geralmente 5 ou 10); ajustes da avaliação (cor das ativas, contorno das restantes, meia estrela).
Imagem Qualquer elemento visual estático ou dinâmico (banners, logotipos detalhados, comprovantes, gráficos informativos). Diferente do Avatar, não aplica máscara de foto de perfil. URL da imagem (link hospedado ou variável do sistema/ERP, ex. {{cards_link_comprovante}}); ajustes da imagem (altura, largura, borda, comportamento de ajuste).
Tipos de ação do elemento Botão:
  • Abrir URL: redireciona para link externo (aceita variáveis, ex. {{cards_link}}).
  • Copiar conteúdo: copia uma informação para a área de transferência do agente, útil para colar no chat.
  • Fazer ligação: se a instância tiver integração com PABX, inicia uma chamada passando a variável do número ({{cards_telefone}}).
  • Atalhos: abrir contato, abrir oportunidade, abrir tarefa, abrir empresa.
  • Executar automação: aciona um fluxo de automação específico.
Atenção ao botão "Executar automação": para que essa ação funcione, é preciso ir até o Fluxo de Automação correspondente e marcar a opção "Permitir uso pelos agentes ativa". Sem essa marcação, o botão não fará nada ao ser clicado.

Elementos de organização

  • Divisor: uma linha horizontal simples para separar seções.
  • Espaçador: adiciona um espaço em branco (respiro) entre elementos.
  • Nova linha: essencial para criar colunas — coloque uma Imagem/Avatar de um lado e um Texto do outro arrastando os componentes para dentro dela.
Dica de design: combine o elemento Nova linha com Avatar e Texto lado a lado para criar cabeçalhos estruturados, simulando a ficha cadastral do cliente.

6.5. Variáveis dinâmicas

Para que o cartão exiba dados reais do cliente em atendimento (nome, telefone, notas), utilize variáveis:

  • A regra é usar chaves duplas e o prefixo cards_ — ex.: {{cards_nome}}, {{cards_telefone}}, {{cards_nota}}.
  • Dados Demo: no canto inferior direito do editor há a seção "Variáveis de demonstração". Insira valores fictícios (ex.: digitar "João" na variável cards_nome) para visualizar como o cartão ficará renderizado.

6.6. Chamando o cartão na URA / fluxo de automação

Depois de pronto, o cartão precisa ser chamado dentro do fluxo de automação ou da URA para aparecer no painel. Há duas formas de aplicação:

A. Cartão no atendimento (múltiplos cartões)

É possível empilhar vários cartões em um mesmo atendimento, organizando-os por Sessões (ex.: uma aba "Financeiro", outra "Suporte").

  1. No fluxo, insira a caixinha Adicionar cartão de informação.
  2. Em Tipo, selecione "Pré-cadastrado" (o recomendado).
  3. Informe o ID do Cartão (o número que aparece na listagem principal).
  4. Informe o ID da Sessão e um Nome da Sessão — use nomes fixos nas sessões e evite variáveis no nome, para não desconfigurar a exibição.
  5. Se o cartão usar variáveis dinâmicas (ex.: {{cards_nome}}), utilize um elemento de Código JavaScript ou Salvar Variável imediatamente antes da caixa do cartão para declarar as variáveis e atribuir valores a elas.
Dica de ouro (boas práticas de implantação): em fluxos complexos, evite poluir a tela com dezenas de caixinhas de "Nova Variável". Use um elemento de Código JavaScript para montar e organizar todas as variáveis antes de chamar os elementos de exibição do cartão — isso mantém o fluxo enxuto, padronizado e fácil de dar manutenção. 
vars['cards_nome'] = "Maria";
vars['cards_nota'] = 5;

B. Cartão na mensagem (cartão único)

Usado para atrelar um cartão a uma mensagem de chat específica (ex.: um comprovante de fatura junto ao balão de texto).

  1. No fluxo, insira a caixinha Adicionar cartão de informação a mensagem.
  2. Esse modo funciona de forma estritamente dinâmica.
  3. É preciso passar o ID da Mensagem e a variável que contém toda a estrutura JSON do cartão.
Limite: diferente do atendimento, no modo mensagem só é permitido exibir 1 (um) cartão por mensagem.
